# v0.7：从目标到真实作品

本版完成 v0.7—v1.0 路线的第一个发布阶段：在已有数字仿真和 CPU16 系统上，接通应用、制作、验证、保存和对照修改的完整流程。原有元件、手册、任务、芯片封装与共享继续使用；注册模型仍为 64 个。

## 一台可以拆开修改的数据记录器

点击工程栏「数据记录器」，选择空白接口、程序骨架或完整参考。空白接口保留公开输入和 RAM，供玩家自行接 CPU 与总线；骨架已接线，但程序只做初始化；参考有寄存器轮询、RAM 游标与子程序两种实现。

「应用」面板提供实际样本输入、记录开关、清空请求、状态及历史。「制作」回到同一个电路画布，编辑 CPU 程序和接线。「验证」按单样本、连续记录、控制和容量四个需求逐步验证当前候选设计，可以直接进入任意阶段，也可继续修改已有作品。

输入经真实的输入寄存器、CPU 与总线写入外部 RAM，面板只显示已提交记录。程序先写数据，再提交计数，未完成写入不显示为有效记录。参考程序需要 400 μs 初始化；每份输入保持至少 400 μs。缓存保存 8 条，满后停止追加；恢复采集只记录最新输入，清空需要 CPU 确认。暖复位保留物理 RAM，但固件重新初始化逻辑会话；运行快照可精确接着执行。详见 [接口与程序手册](RECORDER-V7.md)。

## 验证和自由修改

验证冷启动候选设计的独立副本，不消耗工作台的输入队列或改变现场。未编译源码草稿继续保留，并明确提示尚未进入候选程序。失败时展示实际时刻、期望、观察值和目标，并可定位真实实例；接口缺失另报不兼容，不猜测根因。

任务固定的 RAM 角色 `ram` 是公开观察合同的一部分，不要求内部 CPU 或译码结构完全相同；重命名公开角色要相应编辑测试合同。两个程序都通过同一组 52 条检查。任务是有限时间下的行为验收，不是对所有输入的证明。

「图形时间线」可编辑输入事件、检查时刻和保持采样，保留高级 JSON、原种子和区间规则。修改仅保存到本地测试草稿，不替换固定任务的完成条件。关闭窗口可以放弃编辑，数据校验失败不会半应用。详见 [时间线说明](TIMELINE-V7.md)。

## 保存有意义的版本并比较

「里程碑」保存完整候选设计、源码、已应用设计、运行现场、依赖、父层和分页。命名记录不参与自动历史轮转。恢复前先保存当前现场，备份失败就不替换；可导出、导入和明确迁入旧作品库。

记录器的比较入口携带固定合同。保存两份方案后，在同一合同、种子、冷启动条件和成本规则下重新执行，展示行为结果、结构、程序、游戏面积与存储位。双方实际通过时才比较面积；附带的旧报告不会代替本次验证。

IndexedDB 是首选后端，仅在明确不可用时显示回退状态。存储有限额，失败会保留旧数据；本机数据仍应导出备份。详见 [存储、恢复及比较](MILESTONES-V7.md)。

## 版本边界与后续

本阶段没有增加自定义 CPU 中断、事务协议适配器、后台 Worker 或跨设备个人存档同步。v0.8 的完整 MCU 通信终端、v0.9 的长时间调试和后台计算、v1.0 候选的创作生态仍是后续阶段。这里的输入是数字样本接口，不是物理传感器或新 UART/SPI/I²C 链路。

v0.6 工程、快照和固定挑战继续兼容，不原地改写旧模型或历史内容 hash。网站沿用原所有者访问范围；第二个真实账号验收按用户决定延后。本地测试身份与实际本地 D1 只能验证本地服务行为。
