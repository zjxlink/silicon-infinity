# 系统总线、DMA 与中断 v0.5

本模块实现文件为 `game/systems-v5.js`、`game/systems-ui-v5.js` 与 `game/systems-ui-v5.css`。它为实际 Runtime 注册六个数字功能模型，提供完整系统示例、参数编辑、状态观察和同源芯片手册。CPU16 来自独立的 `architecture-v5.js`，总线没有替 CPU 执行程序，也没有从界面直接向目标 RAM 填入搬运结果。

## 直接使用

顶部「系统总线」提供三个可运行实验：

1. **DMA · 内存搬运**：RAM 地址 16—19 初值为 17、34、51、68。点击「触发 DMA」，再「推进100拍」，实际逐字读源、写入64—67。手动 CPU 端口可以用输入控件发起另一组总线请求。
2. **CPU + DMA · 共享系统总线**：CPU16 持续更新 RAM[0] 并写寄存器外设，DMA 是另一个独立总线主端。DMA 完成后向四路中断控制器发出请求，CPU 的实际 IRQ/ACK 线完成进入与确认。
3. **双CPU · 共享RAM**：两颗 CPU 分别更新同一 RAM 的地址0和1，通过同一仲裁器竞争；主端获准次数与事务记录可直接观察。读改写不是原子指令，示例使用不同字避免将丢失更新误认为算术错误。

选择画布中的系统元件后，观察区提供「配置参数」和「观察总线与事务」。参数可以保存为候选，或明确应用后冷启动。地址窗口重叠、越界、内容超过 RAM 容量等错误会在替换工程之前拒绝。实际总线输出、等待拍数、获准次数、DMA剩余与已完成数量、IRQ pending、RAM内容、寄存器状态和最近事务均可查看。长推进经过现有可中止推进桥；推进期间按钮禁用，避免叠加两个本地推进请求。

## 共同握手合同

地址为 **16位字地址**，每个字16位；不使用字节地址或字节写掩码。

| 信号 | 主端方向 | 宽度 | 合同 |
|---|---|---|---|
| req | 输出 | 1 | 请求期间保持1；上电/复位后先低一拍，每次完成后至少低一拍。 |
| we | 输出 | 1 | 0读、1写，请求期间不变。 |
| address | 输出 | 16 | 0—65535，请求期间不变。 |
| wdata | 输出 | 16 | 写数据，请求期间不变；读操作不要求其有已知值。 |
| rdata | 输入 | 16 | READY=1且ERROR=0时有效。 |
| ready | 输入 | 1 | 本次响应已完成，主端必须采样后释放REQ。 |
| error | 输入 | 1 | 与READY同时为1才表示本次失败。 |

每个整数微秒同时采样，采样后统一提交。某模块本拍新产生的响应由其他模块下一拍采样。RAM/寄存器捕获请求后再等待 `latency` 拍才完成；额外的仲裁、译码与主端采样会增加端到端时间。默认DMA示例在先空闲一拍、随后触发的情况下，四字搬运于57 μs完成，仲裁器记录八笔完成的事务。

未知控制、未知读响应、未映射地址、请求中途变化和等待超时都是显式错误，不将X/Z当作0。错误响应丢失与实际写入是否已发生是不同问题：例如写入已被从设备接受后，响应线再断开，主端会失败，但不会自动回滚已经发生的写入。中止不是事务性撤销。

## 六个模型

| 模型 | 主要参数 | 行为 |
|---|---|---|
| `std.bus-arbiter16/1` | timeout 4—4096，默认64 | 两主端轮询，锁定一次完整事务；当前主端完成后优先另一主端。 |
| `std.bus-decoder16/1` | base0/size0/base1/size1 | 两个互不重叠的窗口，给从端的地址减去对应base；size=0禁用。 |
| `std.bus-ram16/1` | depth 1—4096、contents、latency 1—64 | 真实握手读写，响应保持期间只写一次；暖复位保留内存。 |
| `std.bus-register16/1` | initial、latency 1—64 | 四个总线寄存器，含写入计数和可确认中断。 |
| `std.dma16/1` | maxWords 1—4096、timeout 4—4096 | 上升沿触发，逐字先读后写，成功写入才增加completed。 |
| `std.irq4/1` | priority0—3，各0—3 | 四路上升沿锁存、使能屏蔽、优先级选择和确认空拍。 |

这些系统RAM/寄存器模型与ArchitectureV5的基础 `std.busram16/1`、可编程寄存器设备是不同的已注册模型；不复用同一个模型ID覆盖旧语义。

### 仲裁与译码

仲裁器有 `m0_`、`m1_` 两套从主端接入的握手口和 `s_` 一套下游主端口。`grant=0`表示没有授予；1为主0；2为主1。`waiting` 的bit0/bit1表示未获准的待请求主端。`owner`是内部编号-1/0/1，面板同时显示真正的GRANT输出，不能将两者混淆。

正常主端必须遵守释放REQ规则。未知/断线主端得到错误后不再永久占用总线，仲裁器释放它，直到再次看到明确REQ=0才重新武装；另一主端仍可继续。公平性不代表一个始终不释放REQ的违规主端可以无限占用后自动恢复全部业务。

译码器下游使用 `s0_` / `s1_` 前缀。参数校验拒绝窗口重叠与超出65536字空间，不进行静默截断。译码窗口与实际从端容量分别检查：示例RAM窗口为0—255，但真实RAM容量128字，128—255会由RAM给出越界错误。寄存器窗口为0x1000—0x1003。

### 寄存器外设

| 窗口内字偏移 | 名称 | 读写 | 语义 |
|---|---|---|---|
| 0 | VALUE | RW | 写入改变真实value，写次数加1并置STATUS。 |
| 1 | WRITES | RO | 成功写VALUE的次数，16位回绕；写此地址报错。 |
| 2 | IRQ_ENABLE | RW | 仅bit0有意义。 |
| 3 | STATUS | RW1C | 写1清bit0；有状态且使能时IRQ=1。 |

复位清计数、使能和状态，VALUE恢复initial。没有未声明的UI写入路径。

### DMA

`trigger` 上升沿锁定 `source`、`destination`、`count`。进行中的配置改动不影响本次传输。COUNT=0立即完成且没有总线流量；超出maxWords或源/目标范围在开始前拒绝。busy期间再次触发不重启。完成或失败后，需先让trigger低，再产生新的上升沿。

每个字经历读请求、读响应、空拍、写请求、写响应、空拍。`completed`只统计实际成功写入，错误保留已完成字数且不置DONE。`irq`在完成或错误时锁存为1，下一次触发或复位清除。它是单通道前向搬运器，不提供突发、链表描述符、memmove重叠保护或内存一致性机制。

### IRQ

`irq0..irq3` 只在0→1时设置pending，持续高不重复触发。`enable[4]`屏蔽不丢弃pending；数值较小的priority优先，同优先级按编号小者优先。`ack/ack_id`确认对应事件，并使irq低至少一拍；同拍确认和新的上升沿以保留新事件为准。

CPU16负责保存现场、EI/DI/IRET和中断嵌套，本控制器不代存CPU寄存器。控制器排序参数与CPU的嵌套优先级参数是分别配置的；希望采用同一策略时应保持一致。与系统示例连接的CPU16最多四层，并只允许更高优先级嵌套。该CPU自身合同与测试见ArchitectureV5文档。

## 复位、快照、封装与历史

同步reset输入为冷复位，需接确定0/1；全局暖复位调用模型warm-reset合同。RAM暖复位保留已提交内存；冷启动恢复contents。其他控制状态、响应、DMA完成标记与IRQ pending复位。复位取消在途请求，主从端重新看到REQ低才武装，避免旧请求自动重放。全局暂停冻结时间与所有计数。

reset输入为X/Z（包括复位线断开）时，即刻屏蔽REQ/READY及旧响应，并在下一次采样取消在途状态，显示E_UNKNOWN_RESET；不会继续发送旧请求或把上一笔数据当作新应答。已提交RAM和外设值保留。恢复确定0后主从端必须重新见REQ=0；DMA必须重新经历TRIGGER低→高才能启动。IRQ清除pending并要求输入重新产生上升沿。

状态为严格可序列化对象。快照校验字段集合、阶段、锁定请求、内存长度与16位范围、DMA数量一致性、IRQ位掩码以及历史结构。每个状态保留最多128条事务历史，另存精确十进制截断计数；获准次数也使用十进制字符串。历史记录实际完成/取消时刻，不是界面预测。

完整系统可通过现有模块包封装、保存、导入和重复放置；两个实例拥有独立RAM、DMA、域和状态，不能共享可变数组。相同运行现场恢复后，后续响应与历史与连续执行一致。

## 集成接口与边界

`SystemsV5` 是浏览器全局和CommonJS导出，提供：

- `models/list/supported/defaultParameters/validateParameters/fresh/reset/output/sample/validateState`，符合现有Hardware provider调用；`sample`第六参数为精确时间。
- `boards`、异步 `build(id)` 返回完整workspace；`inspect(runtime)`返回系统实例状态和真实输出信号。
- `manuals={entries,portHints}`供统一手册合并，不修改原手册数据。
- `SystemsUIV5.open()`、`openParameters(instanceId)`和只读`busy`状态。

Systems provider在circuit之前加载，UI在LabAPI之后。所有端口都是明确位宽的数字信号，没有额外协议路由后门。UI在协作房间存在时拒绝本地例子替换、参数写入和本地推进；真实共享运行权限、房间资源预算与服务器验证由根集成负责，本模块不声称已独立完成多账号生产验收。
