# 创造任务与验证中心

v0.6 把完整作品、公开目标和优化反馈接成同一条流程：打开作品 → 修改接线或程序 → 验证实际行为 → 比较成本与故障表现 → 导出或分享自己的版本。所有任务都可以自由开始，工具和元件不需要购买或解锁。

## 四个完整作品

在工程操作区打开“创造任务”。每个任务有可直接运行、可以修改的参考实现和三个递进阶段。

| 作品 | 三个目标 | 可修改实现 |
| --- | --- | --- |
| 避障机器人控制器 | 使能与停止；障碍与急停；全部 16 种输入组合 | 直接逻辑门、NAND/NOT 两种结构 |
| 8 位加法计算器 | 普通加法；溢出与进位；固定种子的 80 组操作数 | 通用 ALU、八级逐位进位两种结构 |
| 双键游戏计分器 | 两次按下加两分；长按与暂停；复位及 256 次加分回绕 | DFF 边沿记忆、实际加法器和分数寄存器 |
| 可编程数据采集站 | 采集一个样本；跟随环境变化；暂停保留与恢复 | 可编辑 Core8/2 程序，真实 I²C → SPI → UART 路径 |

机器人电机是数字驱动输出，不模拟机械位置、动力和碰撞。计算器的合同明确限定加法：`operation=1`，完整结果为 `result + 256 × carry`；并非两种参考结构都支持 ALU 的所有其他操作。计分器按 0→1 边沿计分，长按不连加。采集站的传感器、SPI 缓冲与终端是公开的观察接口，修改程序会改变真实输出。

两个多实现任务共享完全相同的行为测试。检查不依赖内部元件数量、布局或门的名称；测试需要保留说明中的公开端口。任务面板同时说明初学者可以逐步使用的提示。

## 从改作品到完成目标

1. 打开任一参考实现。任务面板列出输入、输出和目标。
2. 回到画布，修改元件或接线。采集站的“程序 / 电路编辑”会打开真实 MCU 程序；其他任务直接在画布编辑。
3. 回到“创造任务”，验证单个阶段或全部目标。验证读当前候选设计，无需先应用草稿。
4. 查看首个不符合目标的结果、游戏面积权重和分档。基础功能通过后仍可以继续换结构、封装和优化。
5. “在验证中心继续”会带入同一组目标，运行批量测试、故障对照及波形采样。

验证从独立冷启动副本开始，不应用当前草稿，不推进当前运行现场，也不消费原输入队列。“返回原作品”恢复进入任务前的候选工程、源码、已应用设计及仿真快照。外部切换作品后会清除旧返回点，避免恢复到过时工程。

通过记录保存在当前浏览器。记录包含完成时的设计哈希与面积分档；“曾通过”不表示随后修改的设计也通过，应重新验证。关闭面板后，后台完成或取消的验证不会抢回焦点或覆盖另一个程序编辑窗口。

## 成本与优化的含义

所有数值都有明确计算依据，但它们是游戏指标，不是晶圆面积、晶体管计数、实际功耗或物理时序。

- **展开面积权重**：展开所有嵌套封装，逐个实际实例计权重，封装不会把成本藏起来。例如普通逻辑门权重 1、XOR/XNOR 为 4、DFF 为 4、每寄存器位为 4、通用 ALU 每位为 12。其他模型使用文档化的固定或位宽规则。报告逐行列出计算规则。
- **已识别存储容量**：计算 DFF、寄存器、RAM、ROM、FIFO 的配置容量。Core8 计 4,096 字节 ROM、1,024 字节 RAM 与八个寄存器；CPU16 当前对应行仅计八个寄存器。其他控制状态、协议设备的软件日志和未单独建模的控制存储不在该数值中，不可把它理解成完整芯片全部存储。
- **固件镜像位数**：单独列出工程中的实际固件数据长度，不再加到已计入的 ROM 容量里。
- **采样延迟**：在选定探针上观察实际请求边沿和响应边沿，按顺序配对后计算 P50、P95 和最大值。零微秒表示同一个采样时刻已经观察到响应；精度受采样间隔限制。
- **窗口吞吐**：已观察且配对的响应次数除以本次实际观察的虚拟时间。它只描述此输入负载，不代表系统的最大处理能力。待回应请求和未知采样单列，不伪装成完成。

当前优化分档只使用展开面积权重：

| 任务 | 精简档上限 | 均衡档上限 |
| --- | ---: | ---: |
| 机器人控制器 | 6 | 12 |
| 加法计算器 | 100 | 180 |
| 游戏计分器 | 145 | 210 |
| 数据采集站 | 1,400 | 2,400 |

超过分档上限但行为正确，仍获得“功能通过 · 自由实现”。存储容量、采样延迟与吞吐另列，不参与隐藏扣分。两种机器人实现实测面积权重为 6、9；两种计算器为 96、93，分别来自真实展开后的结构。

## 验证中心

可以从任务进入，也可以单独打开“验证中心”。当前测试台中的目标可加入集合；集合最多包含 12 组 v5 声明式测试，每组仍使用原测试台的输入、检查、不变量和随机种子合同，不运行任意脚本。

“完整验证集合 JSON”可以修改全部测试。修改后必须点“应用集合 JSON”；格式无效时完整拒绝，原集合与工作台不变。

### 覆盖情况

报告分别统计：声明/实际执行的检查数量、输入事件数量、声明/实际观察的数字端口。遇到早期失败时，后续未执行的目标不会算作覆盖。统计不是代码覆盖、门内部路径覆盖、所有输入覆盖或形式证明。

### 故障对照

先跑未变异的基线，再在独立副本里施加以下一种变化：

- **断线**：从指定时刻起关闭一条真实连接，并移除该线之后重新接通的测试事件。
- **输入卡住**：从指定时刻起固定一个顶层输入。之后对应的显式输入和已展开的随机输入都会被替换，其他输入不变。
- **复位**：在指定时刻向实际实例或 `all` 注入一次暖/冷复位。

结果区分“目标检出了变化”“当前目标未发现变化”“基线失败，不能比较”“故障在测试时间之外”和“未完成，不能下结论”。无效的导线或实例引用不算检出了故障。未发现变化可能意味着测试不足、故障与本目标无关，或系统能够容忍；不能直接等同于容错能力。

“全部基础目标通过”指基线功能目标通过，故障对照的结论仍需看对应行。总预算耗尽或取消则不判定整批通过。

### 波形与开销

在探针设置中选择测试组、数字端口、采样间隔与保留帧数。波形来自重新执行真实输入时间线的独立引擎，保留 0/1/X/Z 和多位总线。图中最多显示最近 120 帧；多位总线抽取文字标签，导出的 JSON/CSV 包含实际缓冲中的全部帧。

长记录采用有界缓冲，明确显示采样总数、保留数和丢弃的最早帧数。每组基线另保留最近 256 帧检查记录，并记录 `traceDropped`，首个反例不被丢弃。

“游戏成本与开销”列出最大的实例和每组测试在当前设备上的实际墙钟耗时、虚拟时长、保守工作量。硬件控制器已有的事务日志只统计其实际保留部分，并保留丢弃计数；不把日志截断后的最大等待当成整个历史的最大值。

## 预算与取消

| 项目 | 上限 |
| --- | --- |
| 集合大小 | 4 MiB UTF-8，12 组测试，8 种故障 |
| 单组测试 | 沿用 v5：8 秒墙钟、5,000,000 元件×微秒等既有预算 |
| 整批验证 | 30 秒墙钟、40,000,000 元件×微秒的保守预算 |
| 波形采样 | 最多 32 个探针、20,000 个采样时刻、8—2,048 个保留帧 |
| 单次波形阶段 | 8 秒及 5,000,000 元件×微秒，并受整批剩余预算限制 |

每个子运行只能使用整批剩余预算，最后一个测试、故障和波形阶段完成后也会再次检查总预算及取消信号。推进分批让出界面；点击“取消”后不会把未运行部分算成功。即使零时刻的观察也遵守预先取消信号。

验证使用主线程上的有界同步引擎批次，不是可强行终止任意同步代码的工作线程。每次推进和编译期间，取消在下一检查边界生效。较长测试应减小电路、拆分时间线或增加采样间隔。

## 分享作品和挑战

任务的“导出此阶段挑战”和验证中心的“导出此组挑战”都生成现有 `chip-game.challenge/1` v5 格式。文件包含锁定工作台、全部芯片/固件依赖、公开目标及测试，可以离线导入。

验证中心导入挑战后默认验证文件里的锁定作品，**不会把它加载到当前画布**。取消“验证导入文件的锁定作品”则用相同目标检查当前候选设计。文件导入失败不会改变任何现场。

“发布此阶段挑战”或“发布此组挑战”由明确的用户点击触发，向在线作品库交付同一份标准包，打开可审阅发布表单；不会因为验证通过而自动上传。在线发布需要在网站打开并登录，离线使用可导出文件分享。在线权限、不可变修订和存储由作品库模块处理。

共享房间中允许查看、隔离验证和导出；载入/恢复本地任务、编辑验证集合、导入本地挑战或打开本地发布流程需先离开房间，入口和实际动作都检查房间状态。

## 开发接口

所有核心模块支持 CommonJS；浏览器分别导出 `CampaignV6` 与 `VerificationV6`。

```js
const built = await CampaignV6.build('robot', 'reference');
const result = await CampaignV6.verify('robot', built.workspace, {
  stageId: 'drive',
  signal: abortController.signal
});
const pkg = await CampaignV6.challenge('robot', 'drive', built.workspace);

const collection = CampaignV6.suite('robot');
const batch = await VerificationV6.runBatch(built.workspace, collection, {
  signal: abortController.signal,
  onProgress: progress => { /* 仅界面进度回调，不属于分享的合同 */ }
});
const csv = VerificationV6.exportWaveforms(batch, 'csv');
```

`CampaignV6.list/stages/suite` 提供任务目录、阶段和验证集合。`VerificationV6.validate/cost/mutate/observe/coverage` 提供声明校验、游戏成本、故障变异、有界观察及声明覆盖统计。集合格式为 `chip-game.verification/1`，测试项为 `{id,name,spec}`，`spec` 使用未修改的 v5 合同；故障和采样设置为纯数据。

UI 导出 `CampaignUIV6.open/load/restore/verify/challenge` 和 `VerificationUIV6.open/run/update/importPackage/challenge`。共享流程调用返回 v5 包的 `challenge()` 即可；随后由玩家点击调用 `EcosystemUIV6.publishPackage(pkg)` 打开审阅表单。

新增源码：`verification-v6.js`、`campaign-v6.js`、`campaign-ui-v6.js`、`verification-ui-v6.js`，样式共用 `campaign-ui-v6.css`。没有修改 v5 测试合同、公共仿真引擎或服务器。
