# 共享芯片库与联机设计规格

版本 0.2.0 · 设计冻结日期 2026-10-10。

本次交付已实现芯片包文件分享。本文完成云端共享和联机的产品、数据、接口、冲突及验收设计，云端服务与多人房间尚未实现。下文的接口和额度是本项目的设计选择，不是当前网站已有接口或平台承诺。

## 1. 体验与实施顺序

**阶段 A：交换作品。** 目前可把个人芯片或完整 MCU 模块导出为 `.chip.json`，另一个浏览器导入后，加入个人芯片库。包携带固定版本依赖、固件、可编辑设计和布局。导入失败保留当前工程和芯片库；同一版本内容不一致时拒绝覆盖。

**阶段 B：云端芯片库。** 玩家选择作品，填写名称、用途、标签、许可证与可见范围，预览输入输出和行为测试，再发布一个不可变修订。浏览器搜索、预览、收藏、派生修改和显式升级。默认仅本人可见；公开或邀请可见由发布者选择。下载与放置分开，下载新版本不会更改运行中的工程。

**阶段 C：共同设计。** 工程拥有者创建邀请制房间，邀请者可查看、编辑或控制仿真。每个房间只有一个共享设计版本和一条运行时间轴。先提供 2—8 人的协作编辑、运行控制和旁观，再考虑公开大厅与挑战赛。

**阶段 D：大规模内容。** 在实际使用和性能基线达到要求后，再加入搜索推荐、作品评价、依赖升级助手、关卡投稿及团队空间。首个联网版本不把公开大厅、排名和商城作为依赖。

## 2. 芯片身份与资产

芯片身份保持 `stableId + revision + contentHash`。工程锁指向确定的修订；删除云端目录项不会使已完整下载的合法工程丢失依赖。发布记录只能追加新修订，不能修改旧字节。名称、缩略图、说明可以单独修订，但不得暗换执行定义。

| 记录 | 主要字段 | 不变量 |
| --- | --- | --- |
| Chip | 服务端 ID、ownerId、稳定名、目录状态 | ownerId 取自认证会话 |
| Release | chipId、revision、packageHash、modelVersions、createdAt、license | 同一修订不可变；内容哈希由服务端重算 |
| Blob | packageHash、byteLength、依赖集合、存储键 | 私有对象通过授权读取，无永久公开下载链接 |
| Verification | releaseId、验证器版本、用例、结果、资源预算 | 用户上传的“测试通过”文字不能替代服务端结果 |
| Grant | 资源 ID、用户/团队 ID、角色、撤销时间 | 每次读写与 WebSocket 恢复都检查授权 |
| Derivation | 源 releaseId、目标 releaseId、许可证继承信息 | 派生不冒充原作者发布 |

核心执行包与展示描述分离。依赖闭包随发布解析，禁止浮动的 `latest` 执行引用。固件只能作为相应 MCU 型号的字节数据执行；不支持任意 JavaScript、网络插件或自定义宿主代码。

发布失败保留本地设计；上传使用请求幂等键，同一键重试返回同一结果。服务端验证通过并写入发布记录后才出现在搜索索引中。索引延迟不改变下载授权或发布结果。

## 3. 云端库 API 合同

所有接口需要身份校验；下表是相对路径，服务地址待部署时配置。

| 接口 | 输入 | 输出/失败 |
| --- | --- | --- |
| `POST /api/chips` | 名称、说明、幂等键 | 新 Chip；请求体不能指定他人的 ownerId |
| `POST /api/chips/{id}/releases` | 芯片包、许可证、可见范围、baseRevision、幂等键 | 验证任务 ID；冲突 409、越权 403、超限 413 |
| `GET /api/verification/{id}` | 任务 ID | pending / passed / rejected 与可定位诊断 |
| `GET /api/releases/{id}` | 修订 ID | 经授权的元数据及下载入口 |
| `GET /api/library?q=&cursor=` | 搜索条件、分页游标 | 当前用户有权看到的条目，不泄露私有标题或统计 |
| `POST /api/releases/{id}/fork` | 派生名称、幂等键 | 新 Chip 草稿，保留来源与许可证 |
| `POST /api/chips/{id}/grants` | 被邀请对象、角色 | 显式邀请；只有拥有者可授予权限 |
| `DELETE /api/chips/{id}/grants/{grant}` | 授权 ID | 撤销后下一次访问与连接恢复被拒绝 |

v1 云端上传预算：单包 8 MiB；沿用工程的节点、导线、层级和定义上限；对验证任务另外限制执行事件数和墙钟时间。预算不能依靠前端检查。大于预算的作品可以继续在本地保存，但发布时明确说明拒绝原因。

## 4. 房间中的设计一致性

房间状态包括 `roomId, projectRevision, executionEpoch, simTime, controllerId, permissions, pinnedDependencies`。项目修订表示设计变化；执行代次在冷启动、替换工程或恢复快照后递增。来自旧代次的运行指令和观察包一律丢弃。

首个联机版本使用服务端排序的操作日志，不采用“最后一个整文件覆盖”。每个操作包含 `opId, clientId, clientSequence, baseRevision, preconditions, kind, payload`。客户端的 ID 仅用于去重，权限来自连接会话。

支持的设计操作：新增/删除实例、增删导线、移动、改名、修改参数、编辑源码草稿、切换定义修订、应用已验证设计。服务器对操作去重、检查前提、应用到候选、验证，再分配新修订并广播。未确认的操作在界面显示等待状态。

- 两人移动不同实例可独立接收；移动同一实例时，后到的旧前提操作得到冲突响应，显示当前位置并可重新提交。
- 删除实例同时引用的导线由同一个原子操作删除；另一人的后续接线若引用已删除端点则拒绝。
- 更改端口合同须经过版本差异预览，所有受影响导线一起处理；不能产生短暂非法工程。
- 源码编辑第一阶段采用“每个 MCU 一个编辑租约”；租约到期前另一人可以阅读或复制分支，避免未经设计的文本合并破坏程序。
- 撤销提交反向操作且带当前值前提。若别人已经改过同一对象，提示冲突，不回滚别人的后续操作。

布局和显示偏好不改变模拟结果。源码草稿也不等于已装入固件；只有控制者明确编译、验证并应用后才递增执行代次、冷启动。

## 5. 共享运行

运行控制者持有单一可转移租约。拥有者可收回控制权，普通编辑者提出接管请求。旁观者无运行写权限。外部输入、温度变化、断线开关、复位和暂停都作为服务端事件入队，并带执行代次和单调序号。

客户端不提交绝对未来时间来抢先执行。服务器把接受的控制事件安排在当前虚拟时间之后的合法边界，所有 CPU 共用现有采样/提交顺序。帧率和网络延迟不进入逻辑求值。服务器广播状态增量、最近信号和有界诊断；频率初始目标为 10—20 次/秒，不广播每条指令。

拓扑编辑先暂停共享运行并形成候选。应用后所有成员切换到同一个新工程哈希和执行代次。恢复快照也需要控制权，且所有成员都看见时间回退通知。模拟不会因为一名旁观者关闭浏览器而重置。

控制者断线后立即冻结新的控制输入，5 秒宽限后暂停运行并开放接管。无人在线时保存快照并暂停，不承诺长期后台仿真。重新连接携带最后确认序号；仍保留日志时补发，否则发送完整工程与快照。每个快照都校验依赖哈希和引擎版本。

## 6. 服务分工与部署可行性

静态前端继续负责绘图、编辑和本地离线执行。联网新增身份入口、芯片目录数据库、私有资产存储、异步验证任务和房间执行服务。房间服务是唯一共享状态写入者，按房间划分负载；目录搜索与房间执行不共享内存可变状态。

一种可行的部署选择是 Worker API + 对象存储 + 数据库 + 每房间一个 Durable Object。官方提供 WebSocket 与休眠机制，可在保留连接的情况下处理房间空闲状态；具体的模拟暂停与保存仍需本项目实现。[WebSocket 官方说明](https://developers.cloudflare.com/durable-objects/best-practices/websockets/)

房间日志与检查点可采用该对象的持久化存储，新项目可选择 SQLite 后端。其存储能力支持这一架构选择，并不自动提供本项目的协作协议、权限或可重放语义。[存储官方说明](https://developers.cloudflare.com/durable-objects/best-practices/access-durable-objects-storage/)

当前 Sites 发布物是静态站点，尚未配置上述房间运行环境。联网落地前需验证实际部署平台支持的身份、WebSocket、持久化绑定和任务预算，再固定基础设施方案；不能仅给界面添加“房间号”就宣称联机完成。

首个房间限制建议：8 人、200 个展开节点、800 条连线；本地工程仍使用原有较大上限。房间规模限制是初始产品预算，性能测试通过后再扩大。大工程采用 Worker 或服务端分批推进，暂停与错误必须有响应，不能无限阻塞界面。

## 7. 验收与完成定义

| 编号 | 场景 | 必须观察到的结果 |
| --- | --- | --- |
| SHARE-01 | 发布、重试相同幂等键 | 一个修订、一个内容哈希，无重复作品 |
| SHARE-02 | 修改包字节但沿用哈希、缺失依赖或超预算 | 拒绝且不进入目录，原作品可继续用 |
| SHARE-03 | 新修订出现后打开旧工程 | 仍运行锁定旧修订；升级前显示差异 |
| SHARE-04 | 私有作品被未授权用户搜索/读取 | 不泄露条目、包内容、计数和缩略图 |
| ROOM-01 | 两客户端接同一输入事件、不同帧率 | GPIO、UART、协议事务和最终快照一致 |
| ROOM-02 | 并发删除实例与接线 | 一致的已接受操作日志，非法端点操作明确拒绝 |
| ROOM-03 | 同一操作重复发送、短断线恢复 | 只执行一次，恢复后修订与时间一致 |
| ROOM-04 | 控制者断线和接管 | 按合同暂停，旧控制者的延迟命令不能污染新代次 |
| ROOM-05 | 冷启动或恢复快照时有旧事务 | 所有客户端同步代次；旧字节不交付到新运行 |
| ROOM-06 | 撤销别人已修改的对象 | 返回冲突，不覆盖对方成果 |
| ROOM-07 | 权限撤销和连接恢复 | 未授权读写被拒绝，无残留控制权 |
| ROOM-08 | 8 人、目标上限工程持续运行 30 分钟 | 无状态分叉或无界内存增长；报告延迟与事件预算 |

上述联网用例状态均为**待实现、待执行**。完成定义是这些行为通过两个及以上独立客户端的实际连接测试，且备份恢复、错误提示和邀请权限可用。芯片文件分享是已实现的过渡功能，不能替代这些网络验收。
