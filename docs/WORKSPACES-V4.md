# 作品管理与触控工作台 v0.4

实现版本 0.4.0，2026-10-10。源码为 `game/workspaces-v4.js`，编辑器集成位于 `game/app.js`、`game/style.css` 和 `game/index.html`。本文只记录本地作品、依赖升级与触控，不将联机测试或最终发布状态计入本模块结果。

## 使用路径

顶部「我的作品」可以新建、打开、另存、重命名、查看历史、导出和删除。删除必须在第二个确认窗口明确确认；删除的是该作品全部本地历史，当前画布仍保留。删除当前作品后暂停其自动备份，直到下一次编辑或手动保存。另存创建独立记录，原记录与运行状态不共享可变对象。

「保存」或 Ctrl / ⌘ S 是手动保存。页面状态栏明确区分手动保存与自动备份，写入失败显示「未保存」。自动备份在编辑后约 600 毫秒合并执行，运行过程中每约 10 秒备份；相同内容不增加记录。连续浏览未手动保存的示例复用一个自动草稿，避免将每次打开都变成新作品。

每个作品最多 5 条历史，保留最近一次手动保存，其余位置滚动保留近期自动记录。作品库最多 20 个作品，序列化文本按 UTF-16 估算最多 4 MiB；浏览器自己的配额可能更低。自动历史不是永久归档。清除网站数据、浏览器清理策略或设备损坏可能删除本地内容，作品列表提供「导出」和「导出当前现场」，文件可通过主工具栏「导入」恢复。普通「导出设计」仍按原合同导出冷启动的设计。

## 一条历史保存什么

`silicon-lab.session/1` 包含四个必需字段与一个可选导航字段：

- `format`：版本标识。
- `workspace`：当前候选设计、位置、源码、当前实验与全部锁定依赖。
- `applied`：对应当前 Runtime 的已应用设计及工作台资料。
- `snapshot`：该 Runtime 的精确运行快照，包括 MCU RAM、寄存器、外设、供电、在途事件、连线开关与版本、虚拟时间。
- `parents`（可选）：最多 16 个父层导航现场，每层保存候选工作台 `workspace`、已应用 canonical 工程 `applied` 及其 `snapshot`。导入逐层验证；旧会话不含此字段时视为空路径。

候选设计和已应用电路可以不同。例如一块板正在 1050 μs，用户改了源码但还没有编译，恢复时仍保留旧程序在 1050 μs 的现场和待编辑源码，不会把草稿冒充已经运行的程序。恢复后统一暂停，用户自行继续。旧 `silicon-lab.workspace/1`、芯片包、快照和 canonical 工程导入继续支持。

本地 Store 的所有读取返回深拷贝；保存先做完整工程和快照兼容校验，再计算内容 hash，并用单次存储写入提交。配额失败、非法候选、损坏 hash、缺少依赖或不兼容快照都保留当前画布和旧存储。损坏作品库不自动重建覆盖，提供导出原始数据入口。打开其他作品前先备份当前现场；目标记录先读取校验，避免历史轮转删掉刚选中的记录。新增作品先完成有效存储，才替换画布。

## 实际差异与依赖升级

「历史与比较」可以比较两条历史，或历史与当前工作台。比较依据实际对象，不只比较名称与时间：节点、连线、边界端口、定义、锁、固件、供电域、初始输入、源码、位置、模块来源和运行事件均会列出变化。源码显示共同前后文之外的实际新增／删除行。长对象界面最多显示前 4000 字符，完整对象可导出；这不是语义等价证明。

选中存在新版的个人芯片，观察面板提供「比较并升级」。先比较接口方向、类型、位宽和协议，再生成并校验完整候选工程。确认仅替换选中的实例，其他实例继续锁定旧定义；「应用」才冷启动新设计。撤销可恢复候选定义、固件、供电、源码和来源元数据。接口不兼容、依赖冲突、资源超限、校验失败或比较期间工程发生变化，都拒绝提交。

完整 MCU 模块升级会重绑定新的独立固件和电源域。`view.moduleOrigins[instanceId]` 保存 `{stableId,revision,contentHash,placedHash}`；前三个字段是来源包定义身份，最后一个必须与已放置实例当前定义 hash 一致。仅有效映射用于发现新版，映射不参与仿真与芯片签名。复制模块时重绑定已放置 hash。旧工程缺少这一来源信息时不按名称猜测来源，用户可重新放入新版。旧纯数字芯片的稳定身份升级路径保持兼容。

行为自动比较仅对输入总位数不超过 6、输出数不超过 8 的纯二值组合电路穷举。含记忆、MCU、协议、双向端口或更大接口时明确只提供结构和接口比较，用户仍应运行原工程验收。升级后旧资源可作为其他实例或历史依赖继续保留，不自动做破坏性清理。

## 手机与耗时控制

触屏操作经过 Chrome 移动视口与真实浏览器触摸事件验证：拖元件标题移动；依次点两个端口连接；双指缩放并保持中心点；单指在空白处平移；先打开「框选」再拖矩形选择多个节点。双指缩放不会修改元件位置，平移不会改电路拓扑。鼠标、Shift 多选和原快捷键继续保留。

自动运行在换 Runtime 后从 1 μs 开始，以实际推进量和实际耗时调整每批大小，目标约 12 毫秒，增长最多翻倍且不超过用户选择的速度上限。调试驱动仍经过统一入口，实际推进量以 Runtime 时间差计算，不跳过虚拟时刻。

含 DFF 或硬件状态的显式长推进采用异步小批，批间让出浏览器事件循环。运行按钮变成「取消推进」；取消、编辑、切换 Runtime 或断点会停止剩余推进，已经发生的时间保留。原 Core8 快路径与短同步 API 保持兼容。此策略改善交互响应，不承诺任意规模电路实时执行，也不能中断正在执行的单个仿真时刻。

## 与联机及扩展模块的边界

`OnlineLab.room` 存在时，即便网络重连中，本地保存、恢复、新建、改名、删除和依赖升级都拒绝执行；可查看列表或导出备份。此模块不替换服务端权威仿真，也不绕过在线 guard。本模块浏览器测试覆盖房间状态防护，真实账号、网络中断与多人操作由独立云端测试负责。

新增 LabAPI：`captureSession()`、异步 `restoreSession(session)`、`setPersistenceHandler(fn)`、`setBeforeWorkspaceLoadHandler(fn)`、异步 `advanceResponsive(delta,options)`。后者返回实际推进量、剩余量与停止状态。原 API 与 `lab:ready`、`lab:workspace`、`lab:render`、`lab:tick` 保持。

资源顺序包含 `hardware-v3 → mcu-v4 → circuit → builder-mcu → app`；`room-client-v4` 在 `online-v3` 前；作品管理和教学／应用脚本在 LabAPI 建立后加载。`moduleOrigins` 为显示层元数据，云端需要显式接受并校验后才可以保存含该字段的作品。

## 集成边缘复核

隔离身份在本地实际云端服务 4174 创建包含新放置完整 MCU 模块的房间成功，服务端读回的 moduleOrigins 与本地完全一致。503 μs 运行状态、700 μs 待执行输入、未应用节点与未编译源码，经作品历史和正常教学返回都保持完整相等；携带草稿进入房间后返回也保留现场。另修复旧标题入口改名后自动备份仍沿用列表旧名的问题，并增加真实界面回归。中途打开外部工程后再次启动教程的返回点问题由教学模块独立修复，其结果由教学验收记录提供。

### 层级导航补充验收

打开独立工程、课程或其他作品时清除旧父路径；只有「打开芯片内部」显式保存并传入父层现场。会话恢复会同时恢复路径，因此从芯片内部进入课程后，返回原作品仍能继续返回正确父层。父层返回按候选设计和已应用设计分别还原，避免草稿对应错误快照。坏父层快照、递归未知字段或超过 16 层路径在任何画布替换之前拒绝。此处保留导航所需设计、源码与运行现场，导出的父层记录不保留撤销栈。

新增 2 项核心与 2 项真实浏览器回归覆盖正常课程往返、独立工程清路径、旧会话兼容、保存的内部现场恢复，以及父层 503 μs / 700 μs 排队输入和未编译源码全等。既有 refinements 6/6、v2-expansion 14/14 和 learning-v4 19/19 也在此修复后重新通过。
