# v0.9 后台计算与独立运行现场

日期：2026-10-11。此模块在网页中使用原生 Web Worker 执行真实 CircuitLab 引擎；从 `file://` 打开的离线游戏明确使用本地隔离分批计算。两种后端都保留主工作台，不以演示数据代替电路。

## 玩家使用路径

在工程标题旁打开「后台计算」，点击「载入当前现场副本」。副本来自当前**已应用设计及实际快照**，包含排队输入、在途协议、内存和依赖；未应用设计、源码及父层现场仍留在工作台。

点击「持续运行」或「推进 100 μs」。观察区展示真实输入、实例 PC/状态/计数、协议收发和内存前八项；暂停后读取根输出。运行时可以随时暂停，手机面板的标题与运行控制固定在面板顶部。输入、导线开关和暖复位在后台的下一虚拟微秒排队；输入未推进时不会伪装成已经生效。

「将暂停结果带回工作台」只在后台已确认暂停、工作台没有未应用设计、完整原始 `captureSession` 指纹仍相同、当前不在协作房间时可用。切换作品会废弃旧计算。编辑源码、推进主现场或改变原设计后，旧结果不能覆盖工作台，可以导出为独立现场文件。

导出文件是单层 JSON 的 `silicon-lab.session/1` 对象，包含候选设计、已应用设计、实际后台快照、源码和父层导航；可通过原有导入入口恢复。房间内不能启动或回填本地后台副本；进入房间会终止已有本地副本，服务端权威运行不变。

「后台验证测试合同」接受现有 `chip-game.testbench/1` 合同，至少一条检查，执行隔离冷启动。通过、失败、取消、预算未完成分别显示；原工作台不被测试载入替换。多方案比较直接复用同一后台 `verify` / `observe` 接口。

## 模块和接口

`compute-v9.js` 导出 `ComputeV9`；`compute-worker-v9.js` 为 Worker 入口；`compute-ui-v9.js/css` 导出独立面板 `ComputeUIV9`。入口在 `testbench-v5.js`、`verification-v6.js` 与 `app.js` 之后加载。Worker 以固定次序 `importScripts` 导入所有实际模型、引擎和验证模块，无动态脚本执行。旧 Core8 的 `window` 发布方式仅在 Worker 内通过 `self.window=self` 别名兼容，不提供 DOM。

| API | 合同 |
| --- | --- |
| `ComputeV9.create({mode})` | `auto` 默认；网页优先 Worker，启动失败明确本地回退；`worker` 要求原生 Worker；`local` 显式本地隔离 |
| `await client.load({project,snapshot?,projectRevision?})` | 严格导入工程和快照，开启新的运行代次；非法导入不替换旧运行 |
| `await client.command({kind:'advance',delta:'100'})` | 无符号十进制微秒；返回真实 `advanced`、`remaining`、`cancelled`、`incomplete` |
| `command({kind:'input',id,value,at?})` | 四态 1—32 位向量或合法整数；不缩减为布尔 |
| `connection / power / reset / uart / temperature` | 沿用引擎真实导线、供电、暖/冷复位、终端字节、温度事件；可给十进制 `at` |
| `pause()` | 取消在途推进，在完整微秒边界确认暂停并返回检查点 |
| `cancel()` | 取消当前任务并返回最后完整状态，不把取消算成功 |
| `checkpoint(probes=[])` | 完整快照、最多 64 个实际数字端口和资源统计 |
| `run({delta,onUpdate,maxVirtualUs?})` | 串行持续推进；默认每次最多 128 μs，默认更新间隔 250 ms |
| `verify(workspace,spec,{signal,onProgress,workBudget,maxWallMs})` | 原 Testbench 报告形状，加 `compute` 身份信息；隔离冷启动 |
| `observe(workspace,spec,observation,control)` | 原 Verification 真实采样报告形状及采样精度，加 `compute` 身份信息 |
| `dispose()` | 终止 Worker/取消本地任务、拒绝未完成请求、丢弃随后旧回复 |

`ComputeUIV9.open/load/run/pause/apply/verify/dispose` 是面板入口；`client`、`checkpoint`、`report` 是只读观察 getter。它不替换原工作台的同步仿真驱动。

## 时序、隔离和边界

每个请求和回复都携带 `silicon.compute/1`、引擎版本、工程 hash、工程修订指纹、运行 generation 和递增 seq。回复必须匹配尚未结束的请求及当前代次。旧载入即使校验更慢，也不能覆盖后发载入；关闭过程中完成的校验同样被拒绝。单一客户端同一时刻只执行一个计算任务，暂停/取消可以在分批让出后被处理。

后台保持原整数微秒、四态网络、同刻输入顺序和协议完成规则；没有时间跳帧。分批 `advance` 使用轻量返回选项，仅省去调用方未使用的完整观察对象，默认引擎接口、最终快照及事件顺序保持原样。推进因预算、取消或执行前停止而未达目标时保留 `remaining`，不会报告已经完成。

一次消息最多 12 MiB；最多 32 条在途 RPC；最多 4096 个排队外部事件；单次推进目标最多 1,000,000 μs、墙钟最多 8 秒。每批从 1 μs 起步，按耗时调整到 1—128 μs，目标约 10 ms 后让出。主引擎节点/导线限制没有提高，实际规模必须看样板实测，不能把 1000 个简单门外推为任意 1000 个 MCU。

客户端性能样本最多 120 条；引擎运行历史最多 1024 条、issue 最多 256 条；模型自身日志沿用各模型的上限和丢弃计数。通用运行历史达到容量后保留末尾记录，不能据此宣称完整因果记录。测试报告和波形仍受 Testbench / Verification 的工作量、墙钟、采样和帧数上限约束。

Worker 运行中崩溃会明确拒绝当前及后续请求，不静默冷启动并冒充连续现场。网页启动 Worker 失败才允许带说明回退。离线回退也是独立 Runtime，但在主线程运行；其流畅程度取决于实际单拍耗时，不宣称拥有后台线程。

主工作台的断点、Trace 捕获与界面执行保护不自动迁移到后台副本。需要原断点语义时使用原调试台；后台功能提供独立持续运行、暂停、检查点和合同验证。关闭浏览器不保证后台任务继续；长期保留结果需导出或保存作品。

## 验收证据

核心 `tests/compute-v9.test.cjs`：23 项通过。覆盖参考求解器精确快照、SPI/I²C/UART、CPU+DMA、在途快照恢复、暂停/取消、乱序命令、旧回复隔离、延迟载入/关闭竞态、32 位部分未知向量、4096 事件边界、真实报告和波形、启动回退与运行崩溃。

浏览器 `tests/browser/compute-v9.cjs`：Chrome 154、Firefox 153、WebKit 26.5 各 13 项通过。覆盖真实原生 Worker、UI 输入和暂停、明确回填、未应用源码隔离、工程切换、单层 JSON 下载与精确恢复、执行中取消、390 px 窄屏、离线本地协议传输，九类样板与参考快照一致，零页面错误。证据分别在 `qa/v0.9/compute-browser`、`compute-firefox`、`compute-webkit` 的 `results.json`。WebKit 在 Windows 的自动化 offline context 连最小本地 HTML 都无法导航；保留原失败及独立诊断，改用 `file://` 加拦截全部 HTTP(S) 请求验证离线，原业务断言完全相同，结果明确记录此测试条件。

`tests/browser/compute-room-v9.cjs`：3 项通过。实际生产构建 Worker、本地持久 D1、隔离测试身份验证进入房间停止后台、拒绝回填且服务端快照不变、退出恢复原现场。证据 `qa/v0.9/compute-room/results.json`。这不是第二个真实生产账号的正式验收。

长时间验收 `tests/browser/compute-soak-v9.cjs` 使用 21 个展开节点的完整自定义 MCU 终端，持续改变传感输入、周期暖复位，运行真实 CPU/协议/DMA。每约 10 秒在计算中暂停、验证已取消、从检查点恢复后与继续运行保持精确相等；记录虚拟推进、RPC、日志、快照尺寸、主页面心跳和 CDP Worker V8 堆。开始/结束 hash 覆盖全部 Worker 导入依赖与终端样板。

最终长测**通过**：UTC 2026-10-11 07:42:39.206 至 08:12:39.842，实际持续 **1,800,528 ms**，完成 1,655 轮输入和计算、171 次计算中暂停与恢复核对，全部精确相等，零页面错误。末次采样虚拟时间为 1,697,794 μs；墙钟 30 分钟不代表电路以物理实时速度推进 30 分钟。
