# 测试台、开放设计与玩家挑战

测试台把“我觉得电路能用”变成可以重复检查的行为目标。打开顶部“测试台”，安排输入发生的时间，声明输出应满足的条件，再点击“验证当前设计”。测试使用当前候选电路的独立副本，从冷启动开始；不会应用草稿、推进当前现场或消耗其输入队列。

## 两分钟开始

1. 展开“开放设计任务”，选择“两个条件才点灯”的“从公开接口开始”。画布只有输入 `a`、`b` 和输出 `y`。
2. 关闭测试台，在画布加入逻辑门并接线。目标是只有 `a=1`、`b=1` 时 `y=1`。
3. 再打开测试台，点击“验证当前设计”。无需先把候选设计应用到运行现场。
4. 如果失败，点击“重演第一处失败”，查看发生时间、此前输入、期望值和实际值。可前后查看实际采样记录，再关闭测试台修改接线。
5. 成功后展开“保存与分享玩家挑战”，导出文件，或保存到本机。选择“返回原作品”可恢复进入任务前的设计草稿、程序和运行现场。

“三种可运行参考结构”会载入完整解法，适合比较不同做法。它不是判题模板；玩家可以使用其他结构、不同实例名称或嵌套封装。

## 三个开放任务

| 任务 | 外部目标 | 三种已验证参考结构 |
| --- | --- | --- |
| 两个条件才点灯 | `y = a AND b` | AND；NAND 后接 NOT；按德摩根定律组合 NOT/OR |
| 两个条件不同时点灯 | `y = a XOR b` | XOR；四个 NAND；两路 AND 与 NOT/OR 组合 |
| 自己造一位加法器 | `sum` 为和的低位，`carry` 为进位 | XOR+AND；NAND 组合；NOT/AND/OR 组合 |

每个任务检查全部四种二进制输入，再追加固定种子的 40 组输入。前两个任务各 44 项检查，半加器 88 项。缺线或恒定输出不能冒充正确电路。题目只规定外部接口与行为，没有限制门的摆放、数量或内部命名。

## 编辑自己的题目

“目标与输入时间线”提供标题、公开目标、结束时间、随机种子与最多五条逐级提示。修改后点击“保存目标设置”。输入事件和端口目标有独立的添加、删除按钮。高级 JSON 支持状态检查、随机输入、端口间关系与按间隔采样的不变量。

时间单位是虚拟微秒，使用十进制字符串。事件必须发生在 `1 μs` 或更晚，检查可以从 `0 μs` 开始。同一时刻先执行实际仿真引擎的外部输入、到期事务、时序采样与提交，再观察稳定后的结果。同刻同一组外部输入保留声明顺序；随机生成的事件排在显式事件之后。

| 输入种类 | 目标写法 | 值 |
| --- | --- | --- |
| 数字输入 `input` | 顶层输入名，如 `a` | 无符号整数、`"X"`、`"Z"` 或四态信号对象 |
| 复位 `reset` | `all` 或实例路径 | `mode: "warm"` / `"cold"`，遵守引擎既有复位语义 |
| 连接开关 `connection` | 导线 ID；嵌套导线可用 `module/wireId` | 布尔值；只开关既有连接，不改工程拓扑 |
| 温度 `temperature` | 实际温度传感器实例路径 | `0—125` 的整数 |
| 串口字节 `uart` | 实际终端实例路径 | `0—255`；仍经过真实串口队列与传输时延 |

数字端口检查使用 `$.端口名` 或 `实例路径.端口名`。状态检查使用实际实例路径和字段数组。例如组装 MCU 的 RAM 字节可写为 `target: "data_ram"`、`path: ["hardware", "memory", 2]`。缺失字段判失败，不会当作零或 `false`。

检查支持“等于”“数值已知”“范围内”。四态对象完整保存 `width/value/knownMask/driveMask`；`X`、`Z` 不会被自动当作零。`"X"` 或 `"Z"` 的相等检查要求整个端口每一位都匹配。

不变量可选 `known`、`equal`、`at-most-one`、`exactly-one`，其中后两种要求一位端口且所有采样值已知。不变量只覆盖声明的采样时刻，不证明采样间隔内永远成立。

## 一个可直接编辑的测试

下面的合同适用于输入 `a`、`b`，输出 `y` 的与门电路。可贴入“高级 JSON”，再点“应用测试 JSON”。

```json
{
  "schema": "chip-game.testbench/1",
  "seed": 12345,
  "duration": "10",
  "events": [
    { "at": "1", "kind": "input", "target": "a", "value": 1 },
    { "at": "1", "kind": "input", "target": "b", "value": 0 },
    { "at": "4", "kind": "input", "target": "b", "value": 1 }
  ],
  "random": [],
  "checks": [
    { "id": "off", "label": "只有一个条件时不亮", "at": "2", "kind": "port", "target": "$.y", "op": "eq", "value": 0 },
    { "id": "on", "label": "两个条件成立时亮", "at": "5", "kind": "port", "target": "$.y", "op": "eq", "value": 1 }
  ],
  "invariants": [
    { "id": "known", "label": "输出不能浮空", "from": "1", "until": "10", "every": "1", "rule": "known", "targets": ["$.y"] }
  ]
}
```

随机输入项形如 `{ "target":"a", "from":"1", "every":"2", "count":20, "min":0, "max":1 }`，使用 `seed` 决定固定序列。目标表达式可用 `{ "port":"$.a" }`、`{ "literal":1 }`，或 `{ "op":"xor", "args":[{"port":"$.a"},{"port":"$.b"}] }`。仅允许 `add/sub/and/or/xor/mod/eq/lt/not`；`not` 表示零变一、非零变零。表达式最多八层、64 项，未知输入不会伪装成数值；不执行任何 JavaScript。

## 失败重演与运行范围

测试按时间执行，在首个失败时刻停止，并保留同刻全部检查、此前输入以及实际观察的数字端口。重演重新创建独立电路，使用原测试、种子和锁定设计再次执行，并比较失败的时间、检查 ID、期望和实际值。它不是动画，也不把旧记录直接当成新一次验证。

重演仍使用失败时捕获的设计。当前作品随后修改，并不会被旧记录覆盖；要验证新设计，应重新点击“验证当前设计”。设计或测试哈希不同的外部重演请求会被拒绝。结果仅证明声明的检查，不能代替完整功能规格。

为避免分享的题目无限占用资源，当前上限为：

| 项目 | 上限 |
| --- | --- |
| JSON 数据 | 4 MiB UTF-8；格式、字段、深度也需通过校验 |
| 输入事件 | 展开随机输入后最多 1,024 项 |
| 检查采样 | 普通检查和不变量展开合计 2,048 项 |
| 数字观察端口 | 64 个 |
| 单次虚拟时长 | 1,000,000 μs |
| 封装展开后元件数 | 2,000；仍需满足工程自身限制 |
| 运行工作量 | 5,000,000 元件×微秒的保守预算 |
| 墙钟时间 | 8 秒，执行中分批让出界面并支持取消 |

预算耗尽或取消显示“未完成”，绝不会算通过。较大的电路或较长等待应拆成多个测试。编译与单次引擎调用是同步操作，取消在批次边界生效；它不是可强制终止任意操作的独立工作线程。

## 分享文件与本机保存

挑战文件 `chip-game.challenge/1` 包含：公开目标、提示、完整工作台工程、视图、程序源码、锁定芯片与固件依赖、声明式测试、引擎版本及内容哈希。不含当前仿真快照；接收者从冷启动检查。

导入先检查结构、工程合法性、端口绑定、版本和哈希，再显示题目。只有点击“载入锁定题目电路”才改变工作台。篡改的内容、未知字段、重复键、危险属性和访问器会被拒绝。哈希用于内容一致性，不代表作者身份认证或测试目标足够严密。当前要求引擎版本完全一致，不自动迁移旧挑战。

本机最多保存最近八个挑战，浏览器存储不足时会明确失败并提示导出文件。导出当前候选电路允许保存未通过的起始题；分享者应另行运行参考解与故障负例。接收者可以改电路，也可以继续编辑目标制作新题。当前没有在线排行榜或防作弊认证。

共享房间中允许查看、验证独立副本和导出；载入本地题、导入、修改目标和恢复本地作品需先离开房间。入口和实际动作都检查房间状态，不以测试台绕过协作权限。外部切换作品后，旧题目的“返回原作品”位置会清除，防止恢复到过时现场。

## 集成接口

`game/testbench-v5.js` 导出浏览器全局 `LabTestbench`，同时支持 CommonJS：

- `validate(spec)`：纯声明式测试校验与补齐空数组。
- `run(workspaceOrProject, spec, { signal, onProgress })`：返回通过状态、检查、首反例、实际采样、哈希与统计；不修改调用方工程。
- `replay(workspace, spec, firstFailure, options)`：重新执行并返回 `reproduced`。
- `createPackage({ title, description, hints, workspace, testbench })`、`importPackage(raw)`、`exportPackage(pkg)`：挑战包创建、严格导入与 JSON 序列化。
- `listOpenTasks`、`buildTask(id, variant)`：三个公开任务及 `starter/direct/nand/demorgan` 版本。

`game/testbench-ui-v5.js` 导出 `TestbenchUIV5`，通过 `attach(LabAPI)` 自动注册顶部入口；依赖脚本顺序为 `circuit.js`、`app.js`、`testbench-v5.js`、`testbench-ui-v5.js`，样式为 `testbench-ui-v5.css`。与其他功能共用真实引擎，不修改公共引擎、服务器或运行控制逻辑。
