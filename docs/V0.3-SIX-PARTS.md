# v0.3 六部分完成定义与使用路径

版本 0.3.0，2026-10-10。本文件定义本轮已实现的功能范围，以及发布前必须核对的证据。六部分实现与本地验收已完成。离线包附逐文件校验清单；最终网站发布结果见交付包 qa/v0.3/deployment.json。

## 1. 编辑器升级

**完成定义**：可以选择一组实际元件并移动、复制、粘贴或删除；复制包含内部连线、实际依赖、参数、固件、电源域和源码，重复实例运行独立。历史记录能区分结构和视图，整理画布不重置运行状态。

使用路径：画布空白处框选，Shift 点击增减选择，拖标题移动整组；工具栏提供复制粘贴、全选、自动布局和理线；选择元件后可查端口说明。触屏通过「框选」按钮进入对应手势模式。

验收重点是复制完整 MCU 板两次后，两份 UART 实际收到各自启动消息；复制层级模块后其固件和状态隔离；批量删除可以完整撤销。单纯看到新图形不算通过。

边界：60 条编辑历史，页面内剪贴板不跨刷新；外部未选中的导线不复制；设计复制不携带运行中的 RAM。自动布局与直角理线不保证无交叉，不是物理布线。

实现与详细证据：[EDITOR-V3.md](EDITOR-V3.md)、[editor-v3.cjs](../tests/browser/editor-v3.cjs)。

## 2. 调试台与逻辑观察

**完成定义**：探针从真实数字端口读值，能区分每位 0/1/X/Z；波形与事务带真实虚拟时间。PC 断点在所选 CPU 指令产生副作用前停止；运行、时间推进、逐拍和指令单步必须共用同一驱动。

使用路径：「调试台」选择端口并开始采集；选择完整 MCU 实例路径、输入 PC 地址添加断点；查看 RAM 页和 UART/SPI/I²C 事务。嵌套实例可分别选择。先在智能灯 PC=0 停住，再逐条执行，能看清上电初始化的顺序。

验收重点包括断点前寄存器未改变、WAIT 未结束时不提前命中下一条、多 CPU 共同时钟、X/Z 波形、实际通信成功及失败。不用预设动画、标签或模拟字幕代替事件。

边界：16 个探针，每探针 2048 次变化，事务 2048 条；记录截断明确显示。采集在整数微秒稳定后进行，不包含微秒内部的组合求值过程。有采集或断点时单次推进最多 1000 μs，可继续推进。

实现与合同：[DEBUG-AND-CHALLENGES-V3.md](DEBUG-AND-CHALLENGES-V3.md)。

## 3. 硬件模型库

**完成定义**：24 个新增模型可独立放置、接线、改参数、保存和封装，并在四态、复位、共同采样和快照规则下运行。总注册模型 40 个，另有 18 枚结构芯片，不混合计数。

使用路径：「硬件与组装」进入计算器、键盘显示、存储、FIFO 四个实验；或从元件库拖建自己的设计。选中元件点击参数入口，修改常量、初值、容量和 ROM/RAM 内容，校验并应用。

验收重点包括实际写使能才改变 RAM、FIFO 先入先出和满空错误、所有 ALU 运算、未知控制不当作 0、参数越界拒绝、两份实例独立和快照准确恢复。修改 ROM 内容必须改变实际输出，旧源码不能伪装成新机器码。

边界：存储每个最多 256 项；FIFO 容量 1—256；键盘采用字节输入，显示器采用数值/ASCII 抽象。宽度、参数签名和行为固定，不支持上传脚本成为新行为模型。

实现与合同：[HARDWARE-V3.md](HARDWARE-V3.md)。

## 4. 自组装 Build8 处理器

**完成定义**：一个可以打开、修改、断线和封装的 13 元件处理器。实际 PC、ROM、IR、译码、ALU、RAM、寄存器和选择器参与运算，不委托隐藏 Core8 执行程序。

使用路径：「硬件与组装」选择自组装计算器、计数器、键盘回显或条件分支。观察 PC、IR、累加器、RAM 和输出；逐拍看取指与执行；编辑程序、编译并应用，或直接修改元件与接线。

参考计算器的可观察路径：1 μs 取到 LDI 7，2 μs 累加器为 7，4 μs 为 12，6 μs RAM[3]=12，8 μs 输出为 12，10 μs 停机。改运算或断开写回线必须改变这些结果。封装后导出、另一全新离线上下文导入，仍可运行并保留程序。

边界：8 位累加器、256 字 16 位 ROM、256 字节 RAM、16 条指令、每条两拍；与 Core8 指令不兼容。当前是并行字节 I/O，不附带 UART、PWM、SPI、I²C 和中断。那些能力继续使用 Core8/2 路线。

实现与合同：[HARDWARE-V3.md](HARDWARE-V3.md)、[builder-mcu.test.cjs](../tests/builder-mcu.test.cjs)。

## 5. 挑战与行为验证

**完成定义**：十个有真实故障的工程均可修复，通过条件检查行为而非指定图形；三级提示逐步解释原因。验证使用独立副本，原工程的时钟、RAM、事件队列及快照不改变。

使用路径：「挑战」选择题目，打开故障电路，查看目标和提示，修改后「验证当前设计」。原 10 个实验与新 10 个挑战单独计数，全部开放。

题目覆盖漏线、OR 报警、半加器输出互换、记忆使能、双实例、计数器清零、流水灯译码、程序等待、SPI 真正回读、I²C 真实地址。SPI 题要求成功事务和 RAM 结果，硬编码结果不能替代通信；温度题要求传感器输入变化后读数跟随。

边界：保持题目公开输入/输出合同，允许不同合法内部结构。通过记录保存挑战版本、工程 hash 与时间；修改后应重新验证。浏览器存储失败会提示仅本次有效，清除浏览器数据会丢失进度。

实现与合同：[DEBUG-AND-CHALLENGES-V3.md](DEBUG-AND-CHALLENGES-V3.md)、[challenges-v3.test.cjs](../tests/challenges-v3.test.cjs)。

## 6. 云端芯片库与多人房间

**完成定义**：线上使用 Sites 身份和真实 D1 数据库；发布独立修订、指定修订下载、授权、邀请和撤销均由服务端校验。多人共享服务器 Runtime 产生的权威快照；有序操作、幂等重试、控制租约与修订冲突不能只由前端模拟。

使用路径：

1. 在线游戏进入「在线实验室」，发布个人库中的芯片，填写描述、标签、许可和可见范围。
2. 在云库中检索可访问的作品，选择明确修订下载到本地库，再放置或打开内部。
3. 用当前设计创建房间，邀请查看者或编辑者。所有者须另外在网站分享设置添加受邀者；房间邀请码不改变网站权限。
4. 由一个控制者运行、暂停、单步；其他参与者观察共同状态。编辑者进入本地草稿，修改后提交；非冲突修改可合并，冲突会拒绝并提示同步。
5. 所有者可以撤销邀请，后续访问或写入必须失去授权。已下载的本地文件不被回收。

验收重点包括：纯数字与完整模块都能真实发布；不同修订内容不混淆；查看者不能写；撤销后再次请求被拒；同一操作重试不重复执行；断线重连后共同时间和 RAM 一致；并发修改不静默覆盖；服务重启后仍从数据库取得作品和房间。

当前采用 HTTP 有序操作与轮询，运行约 250 ms、暂停约 900 ms；没有 WebSocket、Durable Objects 或逐字协同文本。服务器执行每次仿真，控制者在线请求推进虚拟时间；所有页面关闭后不继续后台运算。房间复位为冷启动，设计提交也会冷启动。

预算包括 8 人、200 展开节点、800 连线、1 MiB 请求、512 KiB 初始工作台；快照及完整状态还有单独上限，见 [架构说明](ARCHITECTURE.md)。这是当前受控规模的多人实现，不宣称大规模公开平台。

实现：[server/cloud.mjs](../server/cloud.mjs)、[online-v3.js](../game/online-v3.js)。生产构建、实际本地 Worker/D1 和双浏览器操作均通过；生产发布与真实用户登录验证分别记录于验收表。

## 三种复用方式

| 方式 | 保存什么 | 恢复后的含义 |
|---|---|---|
| 工程/编辑工作台 | 设计、源码、视图、初值、锁 | 打开后从设计初态开始，可继续修改 |
| 结构芯片/完整模块/云端固定修订 | 内部设计与依赖，可放置为实例 | 重复放置保持状态独立，旧锁不会自动升级 |
| 运行快照 | 时间、寄存器、存储、队列、在途事件与连接版本 | 只在兼容工程上从同一执行状态继续 |

源码更改、候选设计、实际运行和历史通过记录不能混成一个状态。玩家可以随时从高级示例开始，也可以逐层打开它来学习；没有强制经济系统或等待时间阻碍实验。

## 离线交付设计

已按下述结构生成并解压验证 silicon-infinity-v0.3.0.zip。逐文件字节数与 SHA-256 在包内 release.json；压缩包整体摘要在 ZIP 同目录的 .zip.sha256 文件，避免校验清单自引用。

建议在源目录之外建立独立暂存目录：

```text
silicon-infinity-v0.3/
  开始游戏.html          指向 ./dist/index.html
  README.md
  dist/                  仅从 game 完整复制的静态离线游戏
    index.html
    *.js / *.css
    package.json
  game/                  同版本游戏源码，与上述 dist 同源
  docs/                  当前说明、验收和历史规格
  tests/                 核心、服务端和浏览器测试源码
  server/                在线服务源码，不是双击即运行的服务器
  app/ + 构建配置与脚本   在线部署和开发所需源文件
  package.json
  package-lock.json
```

发布时只复制实际存在且需要的目录；不要生成虚假的 examples 占位，也不要附带测试浏览器用户目录。配置文件需保留必要非秘密绑定名，排除凭据、身份头、数据库内容、私密环境文件、node_modules、构建缓存和开发进程数据。

在线构建目录也名为 dist，但内容是 dist/server 与 dist/client。**不能直接把在线 dist 当成离线游戏，也不能在源目录用离线复制覆盖在线构建。** 两类产物分别从同一已锁定源码产生，并分别验收。

离线游戏完整加载相对路径脚本、样式和数据，不依赖网络字体、CDN、账号或运行 API。在线按钮可说明需访问已部署网站，不应阻止本地实验。玩家只需保留完整文件夹；Node.js 22.13+、依赖安装、D1 和身份环境只属于服务端开发或完整测试。

### 打包后必须实际检查

- 从最终解压目录以 file:// 打开入口，在禁网或无服务器条件下完成逻辑实验、MCU 运行、Build8 编译和存档。
- 在全新浏览器上下文导入芯片包与快照，验证依赖、ROM 源码、嵌套路径和实例隔离。
- 检查所有脚本、样式和相对文档链接存在；捕获 console/pageerror 与资源失败。
- 对最终压缩包记录文件清单、字节数和 SHA-256；不能用源码测试结果替代最终包测试。
- 网站另做构建、D1 数据库、登录身份、指定修订、房间及权限检查；离线通过不证明线上通过。

最终完成状态统一记录于 [ACCEPTANCE-V0.3.md](ACCEPTANCE-V0.3.md)，不以本节设计代替执行证据。
