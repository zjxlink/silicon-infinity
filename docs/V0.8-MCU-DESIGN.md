# v0.8 · 设计自己的 MCU

本阶段把可编辑的芯片规则、外部设备和完整应用连在一起。所有工具仍直接开放；原有入门实验、记录器、挑战、测试时间线、作品里程碑与联机功能继续可用。

| 制作目标 | 入口与实际能力 |
|---|---|
| 自己定义 CPU | 「芯片设计器」编辑指令、操作码、格式、按顺序执行的微操作；新 CPU `/2` 有独立单层中断现场，IRQ 入口和 IRET 实际执行。旧 `/1` 保持原合同。 |
| 做自己的设备 | 编辑状态机、寄存器读写权限、位域、传感输入和协议存储容量；非法定义整份拒绝。 |
| 设计地址空间 | 编辑真实总线译码器；检查绝对窗口、重叠及握手连线。每个访问由实际译码和应答处理。 |
| 运行完整 MCU 应用 | 固定 CPU16 或自定义 CPU16 接同一外设。计时采样、I²C、SPI、RAM、DMA、GPIO 与双向串口协同工作。 |
| 看懂并修改 | 73 个注册模型、93 篇静态说明；修改后的 ISA/寄存器说明由当前定义生成，包含权限、复位、操作码和副作用。 |
| 公平比较方案 | 新型号具有明确游戏成本公式；旧里程碑可读取，旧报告标为过期；比较会重新执行同一目标。 |

## 完整终端怎么玩

1. 打开「完整 MCU 终端」，选择固定 CPU16。推进虚拟时间，等待程序初始化与定时器到期。
2. 更改传感器数值，观察后续记录。数值由 CPU 实际读取 I²C 设备，经 SPI 写入并回读确认，DMA 完成后才提交记录条数。
3. 发送串口 P 暂停采集、R 继续、C 清空逻辑记录计数。命令先传输到 UART，再进入中断队列，最后由主程序处理。暂停采集不冻结仿真时钟。
4. 按下、释放按钮观察 GPIO 中断。断开 SPI/I²C 后查看错误；恢复后等待下一次采样。
5. 切到电路与程序，修改设备寄存器或程序后明确应用。选择自定义核心，继续编辑指令本身。

当前参考有八条记录，满后停止采集；非易失存储中的旧字节继续保留。复位重启控制程序，不等于清空所有外部存储。程序、RAM 地址、错误、队列和复位的完整合同见 [TERMINAL-V8.md](TERMINAL-V8.md)。

## 深度与边界

新串行控制器通过 MMIO 接受命令，受理后释放 CPU 总线，传输在虚拟时间内异步完成。设备真的检查地址、权限、模式、忙状态、连接版本和复位代次。FIFO 溢出、未知输入、超时、断线和无效 IRET 都有明确结果；不会补造成功值。

这是数字功能级仿真。SPI/I²C 新模型描述寄存器事务，不模拟物理线上的全部边沿、电压和电气特性。自定义 CPU `/2` 明确为单层中断，不支持嵌套；HALT 不作为中断睡眠。游戏成本不是硅片面积、功耗或时序签核。范围与公式见 [COST-V8.md](COST-V8.md)。

后续 v0.9 的大型工程规模与性能、v1.0 的更成熟创作生态仍按路线推进，本版不把未实施阶段列为完成。第二个真实生产账号的跨账号验收仍按用户决定延后。
