# 自托管候选版验收记录

版本：`0.9.0-selfhost.1`；游戏引擎：`0.9.0`。记录日期：2026-10-11。

本版本的数字系统玩法已冻结，交付重点是独立部署、账号、持久化和维护能力。2026-10-11 已在真实 fnOS 设备的 Linux amd64 容器中完成构建与六组生命周期验收，并通过 42 项 Linux 自托管测试。版本仍为可部署候选版；这些结果不代表所有架构、公网环境或长期生产负载均已验证。

桌面程序验证环境为 Windows、Node.js 24.19.0、Chrome 154.0.8037.98。真实 fnOS 验证环境为 Debian 12、Linux amd64、Docker Engine 28.5.2、Docker Compose 2.40.3；容器实际运行官方 `node:24.21.0-bookworm-slim` 中的 Node.js 24.21.0。开发机 Docker Desktop Linux 引擎不可用的限制，已通过在目标 NAS 实际构建和运行容器补足。此处未记录未核实的 fnOS 产品版本号。

自托管测试创建两个真实本站账号，通过实际 HTTP、Worker 和 SQLite 验证私有芯片隔离、邀请与撤销、房间角色、SPI MCU 的执行结果、重试幂等性及重启后持久化。此前托管网站的生产第二账号验收仍属于另一部署，不能混为一谈。

运维测试包括在线备份、损坏备份拒绝、恢复前自动备份、版本迁移检查、两个进程争用数据库锁，以及强制终止持锁进程后的自动恢复。全程使用隔离临时数据，不读取实际玩家数据。

真实容器验收使用独立随机 Compose 项目和临时卷，验证非 root、只读根目录与权限收缩；完成管理员初始化、邀请注册、普通成员隔离和私有芯片校验。SPI MCU 经真实 HTTP 执行后 `RAM[0] = 90`；正常重启及 `SIGKILL` 后，账号、会话、芯片、房间快照与操作重试保持正确。在线 SQLite 备份后修改运行状态、停用成员，再停服恢复；旧运行快照及备份时的成员会话均恢复。

首次运行容器测试时，测试脚本误以为五秒控制权租期在重启和维护后仍有效。现已修正为显式等待租期失效并重新取得控制权，再执行后续操作，同时保留原操作的重试验证。这是验收脚本修正，未改变产品的控制权协议。修正后的六组容器检查全部通过。

浏览器验证包含首管表单、邀请注册、登录、修改密码、HttpOnly 会话、本站两账号芯片库、ALU 操作码说明、独立手册搜索和账号页面返回地址校验。默认 MCU 示例实际执行至 1048 µs 后暂停，界面显示 LED 点亮、串口收到 `B`。工作台载入 73 个模型和 93 篇手册说明；访问账号页面保留当前工程和运行现场。局域网兼容检查覆盖原生 `crypto.randomUUID` 不存在时的启动。

## 仍需执行

- **扩展设备与容量验证**：当前实测范围为上述一台 Linux amd64 fnOS 设备及隔离测试容器；ARM64、其他 fnOS 版本、长期高并发负载和磁盘故障演练仍需单独验证。
- **持续验证与镜像发布**：已创建公开源码仓库，最新自动检查结果以[本仓库 Actions](https://github.com/zjxlink/silicon-infinity/actions)为准。普通 CI 和版本发布前置检查均包含容器生命周期验证；版本镜像是否可用以对应发布工作流成功结果为准。
- **正式公网运行**：真实 HTTPS 反向代理、外网部署、容量规划和长期运维需在目标环境验收；本次不是独立安全审计。

## 复现

```sh
npm ci
npm test
npm run test:selfhost
npx playwright install chromium
npm run test:browser
npm run test:container
```

最后一条需要能运行 Linux 容器的 Docker Engine 和 Compose v2。浏览器报告和截图可通过 `QA_OUT` 指定保存目录。容器检查始终只清理自身生成的随机命名项目和临时卷，不操作既有部署。
