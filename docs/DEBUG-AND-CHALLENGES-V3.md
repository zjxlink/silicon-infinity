# 调试台与挑战工坊

版本：v0.3.0。实现位于 `game/`，可从游戏顶部的「调试台」和「挑战」进入。这里观察的是功能级数字仿真结果，不计算电压、电流或导线传播延迟。

## 两分钟开始调试

1. 打开「一块真正运行的控制板」，保持暂停，打开「调试台」。
2. 在探针列表选择 `$:led`，点击「添加探针」「开始采集」。端口使用实际完整路径，嵌套芯片也能选择。
3. MCU 选择 `mcu`，PC 地址填 `0x0000`，点击「添加断点」「继续运行」。虚拟时间停在 0 μs，第一条指令尚未执行。
4. 点击「执行一条指令」。断点只跳过当前这一次命中，循环再次到达同一条指令仍会停止。
5. 移除断点，继续运行。LED 波形显示来自当前端口的 0/1 变化。打开 SPI 示例并运行后，可以看到真实事务与 RAM 地址 `0x2000` 的 `5A`。

## 探针与波形

最多同时选择 16 个数字端口，支持 1—32 位。单个位直接显示 `0`、`1`、`X`（未知）、`Z`（未驱动）；完整已知总线显示十六进制，含未知或浮空位的总线逐位显示，以免掩盖部分未知。

采集开启时，在每个整数微秒完成全部同步更新和组合稳定之后记录端口。波形只保存实际变化及时间，不用动画推测输出，不呈现同一微秒内的组合求值过程。停止采集后保留最后一段；重新开始采集会开启新段，避免把未观察期间画成恒定信号。切换或重新应用工程会清空上一运行实例的记录。

每个探针最多保留 2048 次变化，事务最多保留 2048 条，界面显示最近 80 条事务。超出后移出旧记录并显示数量。波形中左、右时间刻度对应已采集区间，顶部另显示当前仿真时刻。

精细采集或断点启用后，一次运行调度最多推进 1000 μs，以免阻塞编辑器；工具栏显示实际推进的时间。较长等待需要继续运行或重复单步。没有采集和断点时使用原仿真器推进速度。这一预算不会跳过任何已经推进时间内的整数微秒。

## PC 断点、单步和 RAM

断点地址是 0—4092 范围内 4 的倍数，支持十进制或 `0x` 十六进制。它针对指定 MCU 的完整实例路径，检查其已取出的待执行指令，在提交寄存器、内存或外设副作用之前停止。多个 MCU 同时到达断点时，可依次继续各个命中，随后它们仍按共同虚拟时间执行。

`WAIT` 等待期间不会提前命中下一条指令；等待结束、下一条指令准备执行时才检查。指令单步会推进整个电路共同时间，直到选定 CPU 执行一条指令、命中其他断点、停机或达到 1000 μs 的响应预算。预算用尽而仍在等待时明确提示，可继续单步。

RAM 为只读窗口，显示所选 CPU 的真实 RAM。起始偏移允许 0—1023，每页最多显示 64 字节，对应地址从 `0x2000 + 偏移` 开始。查看 RAM、探针和历史不会改写程序或运行状态。

## 通信事务

UART 显示 MCU 实际发送、接收、溢出事件和终端实际收件；TX 与 RX 是不同观察点。SPI、I²C 显示仿真器完成事务后的结果，包括成功、错误及请求参数。断线、错地址或未送达必须显示实际失败，不用预设字幕代替通信。

采集工具打开前只能读取仿真器仍保留的历史，不能补出已经被运行时移出的旧事件。显示的虚拟时间来自事件本身。

## 十个挑战

挑战都提供合法但有功能故障的工程、明确目标和三级提示。全部开放，不要求先通过某题，也不购买解锁。

| 挑战 | 故障 | 通过条件 |
| --- | --- | --- |
| 找回第一根线 | 与门到 LED 缺线 | 四组输入完整满足 AND |
| 一扇门也要报警 | 报警器误用了与门 | 四组输入完整满足 OR |
| 和与进位接反了 | SUM/CARRY 输出互换 | 完整半加器真值表 |
| 让记忆听从使能 | EN 接到了 RESET | 写入、保持、复位及优先级 |
| 共享时钟，各自记忆 | B 误用 A 的使能 | 两份状态独立，公共清零正确 |
| 计数器回到起点 | RESET 悬空 | 循环计数、保持、清零 |
| 流水灯按顺序走 | 译码输入高低位交换 | 12 拍顺序、单灯、保持及清零 |
| 用程序改变节奏 | 等待时间仍为 60000 μs | 修改为 30000 μs 节奏且保留 B/P/R 功能 |
| 让 SPI 回读真正发生 | SPI 总线缺线 | 成功事务和 RAM 中回读的 90 |
| 找到温度传感器 | 使用错误地址 0x49 | 温度从 25 变 65 后，实际 I²C 读数跟随 |

从「挑战」打开故障电路后，随时回到这个入口查看目标、逐级提示和「验证当前设计」。修改电路或程序后应用，才能在工作台运行新版本；挑战验证可直接对候选设计运行独立副本，并报告无效工程和行为差异。

验证不移动当前 CPU、不改变运行时间、输入队列或快照。逻辑目标检查行为，允许用不同门或封装实现；需要保留题目公开的输入/输出接口。SPI 除检查 RAM，还要求发生真实成功事务，直接把 90 写入 RAM 无法通过。

通过记录包含挑战版本、工程哈希和时间，保存在当前浏览器的 `silicon-lab.challenges.v3`。原 10 个实验与挑战各自计数。历史通过记录不表示后来修改的工程仍然正确，需要再次验证。清除浏览器数据会清除进度；工程仍可导出文件保存。存储不可用时会明确提示仅本次有效，不假称保存成功。

## 扩展接口

`LabDebugger.Session(runtime, {limit?, budget?, onStop?})` 为无 DOM 核心：

- `addProbe(path, label?)` / `removeProbe(path)`；`setCapture(boolean)`。
- `addBreakpoint(cpuPath, pc)` / `removeBreakpoint(key)`。
- `advance(delta, options)` 返回实际 `advanced`、未推进的 `remaining`、`stopped`；时间均为十进制字符串。
- `stepTick()` / `stepInstruction(cpuPath)`；后者返回 `retired`、`pending`。
- `ram(cpuPath, offset?, length?)`、`snapshot()`、`clear()`、`bind(runtime)`。
- `LabDebugger.attach(LabAPI)` 自动安装统一 driver，所有运行与单步入口共用断点检查。

`LabChallenges.list` 为元数据；`build(id)` 返回可运行工作台，`build(id,{solution:true})` 供参考与测试生成修复版本；`verify(id,project)` 返回 `{ok, checks, projectHash?}`；`Progress(storage)` 可注入存储以测试持久化失败。页面入口为 `attach(LabAPI)`、`openPanel()`。

脚本顺序：核心、实验与库、编辑器桥之后加载 `debugger-v3.js` 和 `challenges-v3.js`，样式为 `debug-v3.css`。编辑器通过 `lab:ready`、`lab:workspace`、`lab:tick` 通知插件。挑战载入后发送 `lab:challenge`，包含 `id` 与 `goal`。

可运行：`node tests/debugger-v3.test.cjs`、`node tests/challenges-v3.test.cjs`、`node tests/browser/debugger-v3.cjs`。

测试覆盖四态和 bit31、真实输入波形、断点前副作用、WAIT、循环重复命中、多 CPU、嵌套路径、RAM、实际 UART/SPI/I²C 事件、十题故障与修复对照、验证隔离、进度保存和存储失败。浏览器验收使用独立临时浏览器环境，记录输出到 `qa/v0.3/browser/debugger-v3.json`。最终整体验收以本次发布的验收记录为准。
