# 教学 MCU 指令与外设行为规格

版本：0.1.0 · 日期：2026-10-10 · 状态：评审稿

本文件定义 Phase1 可实现合同；它是设计规格，不表示功能已交付。与《01 元件接口规格》共同使用；模拟信号、连接解析、整数时间和工程依赖格式遵循 01。Phase2 仅保留扩展位置，不得显示为可运行功能。

## 1 身份 状态与执行边界

**MCU-001** Core8 是自定义教学 8 位指令集，不兼容 ARM、RISC-V 或具体商品 MCU。包含 8 个 8 位通用寄存器 R0…R7、16 位字节地址 PC/SP、4 KiB ROM、1 KiB RAM 和下述外设。没有隐含标志寄存器；条件跳转直接检查指定寄存器是否为零。SP 在 Phase1 保留、复位为 0，不参与寻址。UI 必须标“教学 Core8 / 功能级”。

**MCU-002** 统一字节地址空间如下；所有 LD/ST 都是单字节。ROM 可读不可写，不允许自修改代码。RAM 起始地址不是 0。

| 地址（含端点） | 容量 / 用途 | Phase1 权限 |
|---|---|---|
| 0x0000–0x0FFF | 4096 字节程序 ROM | CPU 取指、LD 读；ST fault |
| 0x2000–0x23FF | 1024 字节 RAM | LD/ST |
| 0x4000–0x400F | GPIO 寄存器窗口 | 仅表中定义的地址可访问 |
| 0x4100–0x411F | UART 寄存器窗口 | 仅表中定义的地址可访问 |
| 0x4200–0x420F | Phase2 TIM | Phase1 访问 fault |
| 0x4300–0x430F | Phase2 PWM | Phase1 访问 fault |
| 0x4400–0x440F | Phase2 I²C | Phase1 访问 fault |
| 0x4500–0x450F | Phase2 SPI | Phase1 访问 fault |
| 0x4600–0x460F | Phase2 IRQ | Phase1 访问 fault |
| 其余地址 | 未映射 / 保留 | 访问 fault |

**MCU-003** 指令固定 4 字节，字节序为 `[opcode,a,b,c]`，下表opcode按十六进制书写。表中 `r/s` 是完整一字节寄存器编号，只有 0…7 合法；高 5 位必须为 0。`lo/hi` 表示 16 位数值的低/高字节；`0` 是必须为零的保留字节。未知 opcode、非法寄存器、非法保留位均产生 `F_ENCODING`，不得按 NOP 忽略。

## 2 完整 Phase1 指令表

| opcode | 汇编 | a,b,c | 成功退休后的状态 |
|---|---|---|---|
| 00 | NOP | 0,0,0 | 不改变数据状态 |
| 01 | LDI Rr,imm8 | r,imm8,0 | Rr←imm8 |
| 02 | MOV Rr,Rs | r,s,0 | Rr←Rs |
| 03 | ADD Rr,Rs | r,s,0 | Rr←(Rr+Rs) mod 256 |
| 04 | SUB Rr,Rs | r,s,0 | Rr←(Rr−Rs) mod 256 |
| 05 | AND Rr,Rs | r,s,0 | Rr←Rr AND Rs |
| 06 | OR Rr,Rs | r,s,0 | Rr←Rr OR Rs |
| 07 | XOR Rr,Rs | r,s,0 | Rr←Rr XOR Rs |
| 08 | NOT Rr | r,0,0 | Rr←Rr XOR 0xFF |
| 09 | SHL Rr,n | r,n,0 | n=0…7；左移，低位补0，只留8位 |
| 0A | SHR Rr,n | r,n,0 | n=0…7；逻辑右移，高位补0 |
| 0B | LD Rr,address | r,lo,hi | Rr←总线读取的一字节 |
| 0C | ST Rr,address | r,lo,hi | 总线写入Rr的一字节 |
| 0D | JMP target | 0,lo,hi | PC←target |
| 0E | JZ Rr,target | r,lo,hi | Rr=0时跳转，否则PC+4 |
| 0F | JNZ Rr,target | r,lo,hi | Rr≠0时跳转，否则PC+4 |
| 10 | WAIT n | 0,lo,hi | 等待n微秒；n=0…65535 |
| 11 | HALT | 0,0,0 | CPU停止继续取指 |

**MCU-004** 指令读取操作数旧值，然后统一写回；`ADD R0,R0` 正确加倍。算术不饱和、不抛溢出异常，减法下溢同样模 256。不存在立即数算术变体；先用 LDI 装入另一个寄存器。逻辑移位 n=0 保持原值，n≥8 非法编码。

**MCU-005** 非跳转成功指令 PC←PC+4，按16位保存。所有取指地址必须在 0x0000…0x0FFC 且四字节对齐；不满足产生 `F_FETCH`。所有跳转编码的目标必须符合相同范围与对齐，即便条件不成立也检查，非法目标产生 `F_TARGET`。顺序执行越过 ROM 的 fault 在下一次取指发生；最后一槽 HALT 可正常退休。入口地址固定0。

**MCU-006** 每条指令事务不可部分提交：先校验编码、地址、权限、读取值及副作用合法性，再同时提交寄存器、PC和总线效果。fault 时故障指令不退休，PC保持其地址、目标寄存器和被访问外设不变，CPU进入 FAULT 并记录 `{code,pc,address?,time}`。已经退休的指令不回滚；外设继续运行。只读地址写入、只写地址读取、未映射访问分别为 `F_ACCESS`；GPIO未知为 `F_UNKNOWN`；空RX读取为 `F_RX_EMPTY`。复位才清除fault。

sample读取RXFIFO只查看队首，不弹出；仅成功commit执行弹出。fault的“无副作用”只约束故障指令：同刻较早阶段已发生的UART完成、外部输入、网络解析及其诊断不回滚；GPIO网络解析也不因CPU读取失败而被撤销。

## 3 时间 暂停与电源

全局时间以整数微秒表示，保存为十进制字符串，不使用浮点时间累计，不依赖画面刷新率。普通指令在开始后1微秒退休，例如上电t=0，首指令在t=1退休。指令开始只锁定当前取指及预约退休事件，不在开始时读取寄存器、GPIO或总线操作数。所有寄存器与总线输入在退休时间戳的sample阶段采样，再在commit阶段原子提交。CPU每个实例同一时刻至多一条在途指令；同一时间戳所有CPU先从共同的稳定快照sample，之后才提交各自意图，不能让先提交实例的输出改变另一个实例本时刻已采样的输入。

**MCU-007** WAIT 也耗时1微秒并先退休。若它在t退休，后续指令在t+n开始、t+n+1退休。n=0与NOP的时间成本相同。等待期间CPU不执行其他指令，外设仍处理事件。剩余等待时间由绝对唤醒时间导出，不使用真实系统计时器；暂停不会消耗等待。Phase1没有中断唤醒。

**MCU-008** HALT退休时PC+4，CPU不再取指，外设定时任务和已排队UART传输继续。暂停/恢复不能解除HALT；暖复位或重新上电才能重启。FAULT同样只停止CPU，不隐式停外设。

**MCU-009** 冷启动：PC/SP/R0…R7=0、RAM全0、ROM保留，外设恢复下表明确的复位值（GPIO_PD=0xFF是显式例外），清空FIFO，撤销旧实例代次的所有运行事件。电源关断停止该实例执行与外设事件，输出变为未驱动状态；再上电从入口运行。ROM镜像不足4096字节时末尾补0，因00编码为NOP而得到确定结果。

**MCU-010** 暖复位：PC/SP/通用寄存器清0，RAM保留，ROM保留，外设恢复复位值，FIFO清空，等待取消，在途指令取消，UART尚未完成字节取消。旧事件通过实例代次令牌失效，不能在复位后回调写入。复位时刻按01外部事件阶段执行，新首指令在下一微秒退休。控制面命令的target默认为all，也可指定一个实例路径；只重置所选范围，其他实例保持状态。没有电气RESET引脚。

**MCU-011** 暂停冻结全局时间、指令退休和所有事件队列执行；恢复保持原时间与队列。暂停时编辑设计或固件应形成新的待运行版本，需要明确重启后生效，不在运行中改写已锁定ROM。

**MCU-012** 多枚MCU共享定义而不共享状态：寄存器、RAM、FIFO、GPIO、事件代次、等待和fault全部属于实例。一个实例复位不会影响另一个。完整运行快照另存，不与设计工程保存混淆。

同一时间戳，顺序固定为：断电/暖复位/现有连接的启用开关及输入事件（这一组按已记录事件序号排序）→到期UART完成事件→组合稳定→所有CPU/时序从共同稳定快照sample并生成意图→提交CPU寄存器及总线读写副作用→调度派生外设事件→组合稳定→观察。每个MCU只有一个CPU总线主设备，不提供DMA。断电、暖复位和断线必须先于同刻UART完成：先校验供电、实例事件代次及连接版本，再判断是否完成或交付；已经取消的事件不得从FIFO弹出任何字节，也不得创建观察消息。断线只导致交付丢弃，不取消仍供电UART本身的正常发送完成。

有效的到期TX先移出完成字节，再允许本时刻CPU写入，因此刚释放的FIFO空间可用。有效的到期RX先入队，再允许CPU读取；队列原本已满时，即使CPU同刻将读取，也先置溢出错误并丢弃到达字节。所有同时采样的CPU使用共同快照；不同实例的总线提交只能修改各自状态，连接影响留到提交后的组合稳定阶段体现。

## 4 GPIO

端口ID为GPIO0…GPIO7，均为digital inout；每位支持0/1/X/Z。GPIO与外部驱动解析遵循01。

| 地址 | 名称 | 权限 | 复位值 / 行为 |
|---|---|---|---|
| 4000 | GPIO_DIR | RW | 00；1=输出，0=输入 |
| 4001 | GPIO_OUT | RW | 00；输出锁存值 |
| 4002 | GPIO_IN | RO | 读取八个实际解析后的引脚 |
| 4003 | GPIO_PD | RW | FF；位1启用对应弱下拉，位0关闭 |
| 4004–400F | 保留 | 无 | 任何访问fault |

**PER-001** DIR=0时MCU对应位驱动Z；DIR=1时以推挽方式驱动OUT位。**PER-002** 写OUT总是更新锁存值，输入模式下不产生强驱动；后续改为输出立即使用锁存值。DIR/OUT/PD写入在该指令提交后生效，随后进行组合稳定。

**PER-003** IN读取实际解析值，不把OUT锁存器当输入结果。PD是明确的教学简化：无强驱动时启用的弱下拉使引脚为0；关闭PD且没有其他驱动时输入为X。任意一位为X或仍未解析为确定0/1，整次LD产生F_UNKNOWN，目标寄存器不变；软件AND掩码不能挽救此前的未知读取。

**PER-004** 一个网络同一位出现多个有效推挽驱动，即使数值相同也判X，并产生E_DRIVE_CONFLICT诊断；弱下拉不计入强驱动数量。驱动冲突首先是电路诊断，CPU在随后读到该未知位时fault。按钮接GPIO0，释放时Z、按下时1；默认PD提供0。GPIO1接LED输入，不接外部强驱动。演示不能将同一脚同时作为按钮输入和LED输出。

## 5 UART Phase1事务级串口

**PER-005** UART是固定9600、8数据位、无校验、1停止位的事务级模型。协议端口ID为UART_TX（out）和UART_RX（in），类型为`uart-txn/1`，分别连接终端RX和TX；不能直接连接普通数字引脚。它不生成9600波特的逐位电压波形。

| 地址 | 名称 | 权限 | 定义 |
|---|---|---|---|
| 4100 | UART_TXDATA | WO | 请求发送一个字节 |
| 4101 | UART_RXDATA | RO | 取出接收FIFO最早字节 |
| 4102 | UART_STATUS | RO | bit0 TX_FULL；bit1 TX_IDLE；bit2 RX_READY；bit3 ERR_ANY；高位0 |
| 4103 | UART_CTRL | RW | bit0 TX_EN；bit1 RX_EN；其余位必须0；复位00 |
| 4104 | UART_ERR | RW1C | bit0 TX_OVERFLOW；bit1 RX_OVERFLOW；写1清对应位；高位必须0 |
| 4105 | UART_TXCOUNT | RO | 0…16，含正在发送的字节 |
| 4106 | UART_RXCOUNT | RO | 0…16 |
| 4107–411F | 保留 | 无 | 任何访问fault |

FIFO为空且错误清零时STATUS=0x02；CTRL/ERR/FIFO复位均0。禁止CTRL/ERR的保留位写1，产生F_ACCESS。TX_EN=0时写TXDATA产生F_ACCESS；RX_EN=0时读RXDATA产生F_ACCESS。TX_EN由1变0取消在途TX并清空TXFIFO；RX_EN由1变0取消未完成RX并清空RXFIFO；不隐式清ERR。重新启用从空队列开始。

**PER-006** TXFIFO容量16，包含正在发送字节。TXDATA写入成功后入队；满时丢弃本次写入，置粘滞TX_OVERFLOW，指令仍正常退休，不fault、不覆盖旧字节。必须通过ERR显式清除。软件可以读取TX_FULL后决定重试；Phase1单主设备保证检查后的程序顺序确定。

**PER-007** RXFIFO容量16，满时丢弃新到字节并置RX_OVERFLOW。空队列读RXDATA产生F_RX_EMPTY且不改变状态；成功读取在提交阶段弹出恰好一个字节。读取STATUS不弹出数据。未启用RX时到达字节被忽略，不排队、不报溢出。

**PER-008** 每字节占用`ceil(10×1000000/9600)=1042`微秒。空TXFIFO在t收到写入，完成时刻为t+1042；连续排队的完成时刻间隔固定1042。完成前不得在终端显示发送内容。完成后将队首移除，并从该时刻开始下一字节。终端发送到MCU同样经过1042微秒后才入RXFIFO；终端多字节输入按字节串行排队，不能同刻瞬间全部注入。

事务载荷固定为`{byte:0..255}`，其余时刻和连接信息属于调度信封，不由用户载荷声明。每个UART_TX最多连接一个UART_RX，每个UART_RX最多接受一个UART_TX；终端使用同类TX/RX角色，不支持广播或多源合并。允许终端与MCU、不同MCU之间的连接，也允许同一MCU的TX连接自身RX作回环。一次完整发送只经历1042微秒：在发送完成阶段直接交付接收FIFO，接收端不能再次附加1042微秒。自回环也遵循此规则。

接收资格在该字节开始发送时记录：接收实例已供电、接收代次和连接版本均有效；MCU 另需 RX_EN=1，终端的接收使能遵守 01 的内建模型合同；完成时再次核对。接收器禁用、复位或断电使旧接收代次失效，即便在完成前重新启用也不能接收已经取消的在途字节。发送器可正常完成该字节而接收器丢弃。

同一时刻发生 UART 完成与禁用时，必须区分禁用来源：外部断电和暖复位在阶段一生效，优先取消旧交付；程序通过 ST 写 UART_CTRL 在阶段四提交，晚于阶段二的 UART 完成。后一情形中，先完成传输和交付，再清空相应 FIFO 并取消仍未完成的后续字节；不能把程序寄存器写伪装成阶段一事件。外部连接开关的同刻规则依 PER-009。

**PER-009** TX完成与终端接收是不同事件。断开终端不阻塞MCU发送，TX仍按时完成并从FIFO移除，但终端没有消息。每字节开始时记录连接端点和连接版本；结束时仍是同一有效连接才交付，传输中断线再接回也丢弃该字节。运行中的断线和接回使用现有导线的connection-enabled开关，每次有效切换递增连接版本，二者均进入快照。新增、删除或重接工程导线属于候选设计修改，须应用并冷启动，不能借拔线操作偷偷替换工程拓扑。UART内部观察器可以显示“已发送/未送达”，不得伪造终端接收。

**PER-010** UART观察历史不是FIFO：暖复位、冷启动、断电均保留当前会话的历史并追加带时间和实例ID的标记；FIFO清空、在途事件取消，不产生补发。历史采用有界缓冲并显示截断提示；工程保存不包含历史，运行快照可以包含。HALT后队列仍可发送，暂停时不能发送。

## 6 汇编与完整演示

**MCU-013** 汇编器大小写不敏感，寄存器仅R0…R7；数字只允许十进制或0x十六进制非负整数；超出字段范围直接拒绝，不截断。每行一个标签和/或一条指令，标签为`[A-Za-z_][A-Za-z0-9_]*`；`;`之后为注释。标签按不区分大小写解析，重复、未定义、指向程序末尾空位置均拒绝。Phase1不支持宏、字符串、表达式、立即数算术、伪指令或宿主语言执行。错误返回源行号与原因，失败不能覆盖旧的有效ROM。编译输出最多1024条指令，从地址0连续排列。

汇编成功输出一个01定义的固件record：`{id,targetModel:'core8/1',format:'hex',data,contentHash}`。`data`必须是无`0x`前缀的小写十六进制字符串，表示非空、长度为4字节倍数、范围4…4096字节的原始程序镜像，即字符串长度8…8192且可被8整除。`contentHash`为`sha256:`加原始镜像字节的SHA-256小写十六进制摘要；哈希在ROM末尾补零之前计算。不得哈希hex字符文本、源码或padding后的ROM。装入ROM时才补零至4096字节。空源码不能生成合法固件。

模型ID与固件`targetModel`统一为`core8/1`。Core8实例必须声明`bindings.firmware=<固件record的id>`；解析时查找唯一record并核对型号、长度、哈希与四字节镜像长度边界。原始镜像可以含只用于LD读取的数据，因此导入器不把每个四字节块都预判为有效指令；只有CPU实际取指时，才按MCU-003检查opcode、保留字段和操作数。汇编源码仍执行MCU-013的严格检查。其他模型不得声明这个绑定。汇编器另外输出独立的源码映射数组`[{address,line}]`，address为每条指令的字节地址，line从1计数；源码映射不影响镜像哈希。汇编、导入或依赖校验任何一项失败，均拒绝整个候选修改，不留下局部绑定或半份ROM。

暂停中导入或汇编的新固件仅进入已验证的候选工程；正在运行或暂停的旧runtime继续引用原来锁定的ROM及工程快照，界面标“已修改，待重新启动”。只有显式“应用并重新启动”才原子提交候选工程的全部定义、连线与固件绑定，并按冷启动规则建立新runtime；不能只替换固件而沿用旧PC、FIFO或RAM。用户选择放弃候选修改时恢复原工程视图，不改变旧runtime。工程导出使用明确选中的已应用版本；未应用候选须先应用或显式另存为新工程。

演示连线：GPIO0←Button（释放Z/按下1），GPIO1→LED，UART_TX→Terminal.RX、Terminal.TX→UART_RX；GPIO_PD保持FF，画面标明“内置弱下拉”。板级VCC/GND均为power输入端口，role分别为vcc/gnd，必须接入同一供电域对应角色的输出且该域已上电；MCU使用explicit供电，缺脚、跨域、角色错接均不能启动。Phase1复位使用全局暖复位操作，不额外暴露RESET引脚。此例先发B，然后不断闪灯；每轮采样按键，检测变化后按下发P、释放发R。它是轮询示例，没有去抖和中断承诺；短于采样间隔的按键可能漏读。

```asm
LDI R0, 2          ; 0000: GPIO1输出，其余输入
ST R0, 0x4000      ; 0004
LDI R0, 3          ; 0008: 开启UART TX/RX
ST R0, 0x4103      ; 000C
LDI R0, 0x42       ; 0010: ASCII B
ST R0, 0x4100      ; 0014
LDI R6, 1          ; 0018: 按键掩码
LDI R7, 2          ; 001C: LED位
LDI R4, 0          ; 0020: 上次按键状态
loop:
LD R1, 0x4002      ; 0024
AND R1, R6         ; 0028
MOV R2, R1         ; 002C
XOR R2, R4         ; 0030
JZ R2, unchanged   ; 0034
JZ R1, released    ; 0038
LDI R0, 0x50       ; 003C: ASCII P
JMP send           ; 0040
released:
LDI R0, 0x52       ; 0044: ASCII R
send:
ST R0, 0x4100      ; 0048
MOV R4, R1         ; 004C
unchanged:
XOR R3, R7         ; 0050: R3冷启动为0
ST R3, 0x4001      ; 0054
WAIT 60000         ; 0058
JMP loop           ; 005C
```

标签地址为loop=0x0024、released=0x0044、send=0x0048、unchanged=0x0050；最终代码96字节。编码例：`LDI R0,2`为`01 00 02 00`；`ST R0,0x4000`为`0C 00 00 40`；`JZ R2,unchanged`为`0E 02 50 00`；`WAIT 60000`为`10 00 60 EA`。程序在按钮始终释放且t=0上电时：B于t=6入TXFIFO、t=1048抵达持续连接终端；LED于t=16亮；WAIT于t=17退休；JMP于t=60018退休；第二次LED变化于t=60025，故稳定轮询路径闪烁半周期60009微秒。修改WAIT会改变此执行结果，不由预设动画决定。

## 7 可恢复状态 调试与错误展示

运行状态至少保存：实例标识及定义版本、执行模式（运行/等待/停机/故障/未供电）、八个寄存器、PC/SP、全部RAM、GPIO锁存值和方向及下拉配置、UART控制和错误位、两个FIFO及其顺序、正在发送的字节、该字节起止时刻、连接版本、等待截止时间、下一指令退休时刻、实例事件代次。ROM按不可变固件哈希引用。所有时间字段以整数字符串序列化；不得通过平台日期对象推导虚拟时间。计数器分别记录成功退休条数和仿真微秒，两者不能混称真实硬件周期。

快照恢复先校验芯片定义、固件、协议版本和资源上限，再恢复事件队列与运行状态；恢复过程本身不能多执行一条指令或补发串口字节。共享定义相同但实例标识不同的两颗芯片必须保持各自的队列归属。无法取得锁定依赖时拒绝恢复并显示缺失依赖，不自动换用新版本。只保存工程后重新打开属于冷启动，不承诺恢复此前寄存器内容。

调试器至少提供当前指令、寄存器、最后一次总线访问、执行模式和虚拟时间。暂停后单步指令：让目标CPU完成下一条指令的退休或出现fault，同时正常推进这段虚拟时间内的其他实例和外设；不能让目标CPU私自拥有第二套时间。目标正在WAIT时，单步可推进到下一条指令的退休，界面必须展示跨过的等待时间。目标已HALT或FAULT时，单步指令不可用；用户仍可选择推进全局虚拟时间观察串口排空。不同的“单步微秒”和“单步指令”操作须分开标记。

fault显示错误代码、实例、故障PC、源码行（有映射时）和访问地址，不只显示“运行失败”。GPIO未知错误应同时定位未知引脚及其连接网络；线路悬空与多个强驱动分别解释。UART队满属于已定义的可恢复粘滞错误，界面显示错误位，不能将它误标为CPU故障。暖复位标记必须保留，帮助用户分清旧日志和重新启动后的输出。

终端以实际收到的字节保存历史；可打印ASCII直接显示，其他字节用十六进制转义表示，避免控制字符执行终端指令。历史条目保留到达时间、来源实例和字节值；文本换行仅是显示规则，不影响协议数据。串口断线期间不存在接收条目，重新连接也不自动重放历史传输。观察历史截断不改变FIFO容量或程序行为。

实现前可用以下人工基准核对：先写入RAM再暖复位，内容应保留；冷启动则为零。CPU排队两个UART字节后HALT，在两个完成时刻仍依次收到它们；若在首字节完成前暖复位，则二者都不能出现。清除GPIO_PD的最低位、释放按钮且不接其他下拉后读取IN，应保持目标寄存器旧值并进入故障。两个MCU运行同一ROM，其中一枚改写RAM或复位，另一枚必须保持原状态。这些检验用于验证合同，不能由示例专属处理逻辑通过。

## 8 Phase2能力合同与验收入口

**MCU-014** Phase1任何Phase2寄存器访问、CALL/RET/EI/DI/IRET或未列出的opcode必须拒绝或fault，不得静默成功。下面仅表示升级边界：TIM独立虚拟时间计数和比较；PWM明确周期与占空比；I²C明确地址、ACK/NACK、事务及超时；SPI明确mode0…3、字宽与片选；IRQ明确使能、pending、优先级、嵌套和返回语义。每项启用前发布独立扩展规格及版本，按钮去抖由稳定时间规则或程序实现。ADC、电压电流和真实电气时序不在本合同。

**MCU-015** 长期可通过新的coreKind引入RV32I核心，并经总线适配器访问相同外设行为接口；不得把Core8字节码直接当RV32I执行，也不得宣称当前兼容。不同核心保留各自寄存器、地址宽度、异常和指令时间合同，外设复用依赖显式适配及版本锁定。

实现验收须覆盖MCU-001…015和PER-001…010：所有编码边界、溢出运算、原子fault、取指越界、WAIT0/最大等待、HALT后串口继续、冷暖复位差异、暂停无时间流逝、独立实例、GPIO未知与强驱动冲突、FIFO满/空、1042微秒延迟、断线丢弃、复位取消旧事件。完整场景及操作记录见03验收规格；此文档示例时序是其可核对基准。
