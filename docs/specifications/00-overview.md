# 硅纪元开发规格总览

版本 0.1.0　日期 2026年10月10日　状态 评审稿

本规格包定义一款面向零基础玩家的数字电路创造游戏。玩家可以连接基础元件、使用和修改预设芯片、封装自己的电路，并逐步搭建可编程 MCU 与应用设备。首个完整示例是能够上电运行的智能灯控制板。本文及三份配套规格是开发和验收输入，不表示相应功能已经实现或测试通过。

## 已确定的产品边界

游戏采用功能级数字仿真。逻辑、程序、连接关系和状态变化必须有明确语义；制程、晶体管物理、电源纹波、真实驱动电流不属于此版本。LED、电源、地、按键和复位均具有实际的模型作用，不作为不影响结果的装饰。

复杂芯片允许使用功能模型。编辑器须区分参数编辑与内部结构编辑：只有附带结构实现的芯片才能打开门级或模块级内部图。玩家可以复制结构模板、重新封装，并通过接口测试替换原模块。未验证的结构版本不能继续冒用原功能模型的运行结果。

自由创造模式开放已提供的元件和实例。引导实验逐步引入知识；关卡按可观察行为验收，允许多种正确实现。面积、能耗或制造成本等评分不进入当前发布闸门，未来加入时必须标为游戏化估算。

## 分期范围

| 阶段 | 必须覆盖 | 不属于本阶段的发布要求 |
| --- | --- | --- |
| Phase0 仿真基础 | 连线、位宽检查、四态信号合同、组合与同步逻辑、封装、实例隔离、版本锁定、导入导出 | CPU、完整协议控制器、在线服务 |
| Phase1 MCU 完整示例 | Core8 指令、ROM 与 RAM、GPIO、事务级 UART、供电与复位、程序编辑、智能灯示例、单步与观察 | 硬件中断、定时器、PWM、SPI、I²C、真实商用 MCU 兼容 |
| Phase2 外设深化 | 单独冻结定时器、中断、PWM、SPI、I²C 的详细扩展规格后实现 | 本包未指定的寄存器行为与协议特性 |
| Phase3 设计生态 | 共享芯片库、版本依赖、协作观察与运行，再扩展同时编辑 | 首版不引入账户、公开上传或网络同步要求 |

长期增加 RV32I 功能核心作为可替换处理器。Core8 是独立的教学架构，不是 RISC-V、ARM 或某款商用 MCU 的兼容实现。Phase2 和 Phase3 的能力合同用于预留扩展，不可在界面上显示为已可用功能。

## 规范性用语

“必须”与“不得”表示对应阶段的强制要求；“应”表示默认推荐，偏离时必须记录理由；“可以”表示可选。标为后续的要求不阻断 Phase1 发布。验收优先级 Blocker 表示必须通过才能发布；Major 表示重要体验或功能要求。优先级与 Phase 阶段是不同维度。

同一版本三份规格共同组成基线。通用信号、包格式与生命周期以元件规格为准；具体指令、地址和寄存器副作用以 MCU 规格为准；验收规格验证两者，不得自行增加相反语义。发现矛盾时必须修订规格，不能由实现者静默择一。

## 关键架构决策

| 编号 | 决策 | 对开发的约束 |
| --- | --- | --- |
| ADR01 | primitive、composite、behavioral 使用统一模块合同 | 外部行为可比较，内部实现方式不改变引脚含义 |
| ADR02 | 数字位宽支持 1 到 32 位，状态按位表达 | 不将数据结构写死为八位数字或一个空值 |
| ADR03 | 定义不可变，实例独立保存易失状态 | 两枚相同计数器或 MCU 不共享 RAM、FIFO、寄存器 |
| ADR04 | 使用整数微秒的虚拟时间 | 不用屏幕刷新率、系统时间或网络到达时间决定功能结果 |
| ADR05 | 区分冷启动、暖复位和暂停 | 程序保留、RAM 保留规则及待处理事件必须一致 |
| ADR06 | 芯片版本与依赖锁定 | 作者更新不自动改变已有工程，升级必须显式执行 |
| ADR07 | 模型级性能优化需保留语义 | 功能兼容和周期一致分开声明，修改结构后重新验证 |
| ADR08 | 事务接口和数字引脚接口使用不同类型 | UART 事务连线不得伪装为已验证的逐位电气波形 |
| ADR09 | 保存工程与保存运行快照分开 | 打开设计执行冷启动；恢复快照继续原运行位置 |

## 电源和时间的一致性

冷启动保留程序镜像与设计，清零 RAM，复位 CPU，并将外设置于各自规定的复位值。外设复位值不一定全零，例如教学 GPIO 的弱下拉默认开启。暖复位保持 RAM，但重置 CPU 和外设、清除其待完成操作。暂停保持所有当前运行状态，虚拟时间停止推进。

一条教学指令的执行步与真实 MCU 的硬件周期不是同一概念。界面分别提供指令单步、仿真时间推进和暂停。尚未退休或仍在传输的数据只能按对应合同在规定虚拟时刻生效。

## 示例中的功能链路

智能灯控制板必须经过“程序执行 → 外设寄存器 → GPIO 引脚或 UART 事务 → 实际连接 → LED 或终端”的链路产生效果。场景代码不得绕过 MCU 模型，直接根据预设时间表点亮 LED 或写入终端文本。

主示例使用 GPIO0 接收按键，GPIO1 驱动 LED；输入的稳定默认值来自明确的弱下拉配置。UART 的终端输出来自实际完成且连接成功的发送事件。改变程序、断开导线或修改方向寄存器，应产生规格中可观察的不同结果。

## 共享和联机的预留

工程应携带锁定的完整依赖关系，离线导出应能重现相同设计。未来共享条目包含接口、说明、测试、版本与依赖快照。只接受声明式电路、引擎允许的功能模型和受限教学程序，不允许共享包执行任意网页脚本。

联机采用一个权威仿真状态，统一排序输入事件。可先提供多人观察和轮流操作，再规划同时编辑及冲突合并。当前包格式只预留稳定标识、时间和事件顺序，不定义未验证的网络协议。

## 发布证据

测试报告必须记录规格版本、模型版本、程序镜像、设计包哈希、初始状态和输入事件。相同版本和相同输入必须得到相同的功能结果。速度与规模目标需在明确的测试设备上测量；本规格不声称已有性能基准或已通过游戏测试。

Phase1 发布前须满足所有适用的 Blocker 用例，并记录 Major 用例的结果和未通过项。Phase2 测试单列，不得通过将其标为已跳过来声称完成外设深化。影响接口或行为兼容性的功能变更须先更新规格、版本和验收用例，再进入实现。
