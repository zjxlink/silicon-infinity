# 芯片设计器

v0.8 的“芯片设计器”把已有的可编辑功能模型放到同一个界面：编排指令和微操作，填写数字状态机的状态与规则，配置协议设备的寄存器与位域，并检查当前层级的地址映射。所有结果仍由真实电路执行；编辑器不会直接修改寄存器、内存或仿真输出。

## 开始使用

在工作台点击“芯片设计器”，选择当前作品中的元件，或者选择一个完整可执行起点。也可以选中元件，在右侧点击“图形编辑 / 同源手册”。封装中的元件需要先进入内部，再打开编辑器。

编辑器提供四个视角：

- **图形编辑**：指令、微操作、状态、规则、寄存器与参数的表单。
- **地址映射**：当前层级各译码器的窗口、目标、累计地址范围与握手连线检查。
- **同源手册**：根据本次编辑副本生成的端口、指令、状态和寄存器信息。
- **高级 JSON**：完整参数的文本形式。点击“检查并载入表格”才替换图形编辑副本。

“检查”只验证副本。“保存候选”更新作品的候选设计，保留当前运行版本和现场。“应用设计”先执行同样的完整检查，再通过工作台应用流程启动新版本。关闭编辑器会放弃尚未保存的表单修改；已有作品中的源码草稿不会因为检查失败而被覆盖。

## 试做一条自己的指令

1. 打开“我的 MIX 指令”起点。选择 `MIX`，它先计算两个寄存器的乘积，再加 1。
2. 将第二个微操作的“操作数 B”从 1 改为 7，点击“检查”。检查同时汇编当前源码，不只检查表格外形。
3. 保存候选时，旧电路仍保留原状态。应用后推进电路，程序经真实外部总线把 42 写入 RAM，再读到 R3。
4. 可以尝试交换两个微操作。顺序会改变执行结果；不是装饰性的排序。

指令可添加、删除，助记符、操作码和操作数格式均可修改。若改了助记符，源码也要使用新名称。每条指令有 1—8 个微操作；跳转、返回与停止必须位于最后。寄存器与操作数引用、重复操作码、无效程序和资源上限都由对应核心验证器检查。

旧 `std.custom-cpu16/1` 继续使用原来的 ISA1 合同。新 `std.custom-cpu16/2` 使用 ISA2，提供中断允许、禁止与返回微操作。编辑器不会自动把旧 CPU 升级成新 CPU；两者有不同的端口合同。

## 状态与有序规则

`std.fsm16/1` 使用输入掩码、期望值和下一状态。`std.protocol-fsm16/1` 还支持上升沿、下降沿、计数和等待条件，以及移位、装载和计数动作。

每拍按界面从上到下判断规则，只执行第一条匹配规则。动作也按显示顺序执行。所有状态引用必须存在；删除或改名状态后，应修正初始状态及指向它的规则。引用未知输入会遵循核心的故障规则，不会在编辑器里被自动当作 0。

“按真实边沿接收 8 位数据”可以用来验证规则：把完成条件从计数 8 改成 4，输入同样的 0xA5 串行数据，只会接收前四位，得到 10。数字状态机是有限数字控制模型，不声称模拟物理 SPI/I²C 电气细节。

## 设备寄存器与存储参数

旧数字握手设备与新事务协议寄存器设备都能编辑地址、名称、访问权限和复位值：`rw` 为读写，`ro` 为只读，`w1c` 为写 1 清位，`rc` 为读后清零。外部来源寄存器必须满足模型规定的只读限制。

新 `std.protocol-registers/2` 还可以设置身份、I²C 地址、SPI 模式、写忙时间、真实 `sense` 输入来源，以及寄存器内的位域。位域描述不另行授予访问权限；它继承所在寄存器的权限，重叠或越界会被拒绝。改变寄存器权限会改变实际协议访问结果。

`std.protocol-memory/2` 可以修改容量、初始字节数组、只读与非易失设置等参数。数组仍使用明确的 JSON 字节值，超出 0—255 会整份拒绝。暖复位、冷复位和在途事务行为由该设备合同决定，详见芯片手册。

GPIO、定时器、DMA 配置接口的模型参数也可在此编辑。UART/SPI/I²C 控制器的固定寄存器布局由程序操作，不通过表格重定义；界面会说明这一边界，并提供同源合同查看入口。

## 集中检查 MMIO

地址映射视角沿实际连接的译码器树解析路径。下游收到的是减去窗口基址后的本地字地址；界面将各级基址累加，并用上游窗口裁剪可访问范围。例：上游从 0x100 开始，下游窗口从 0x20 开始，则对应上游地址为 0x120。

检查包含：

- 同一个译码器的窗口重叠和越界。
- `req/we/address/wdata` 与 `rdata/ready/error` 七条总线握手连线是否完整。
- 已知寄存器是否超出上游可访问窗口。

不同根译码器可能属于不同地址域，不能仅因地址相同就判冲突。分析限定在当前工作区层级；跨顶层边界或封装的路由会明确提示进入内部查看。此视角是静态连接检查，不能替代实际运行及失败测试。

## 保护已有作品

保存前，编辑器记录并比较整个候选设计、所选实例原参数和源码集合的哈希。其他编辑器修改候选、切换工作区，或者关闭本次编辑器后迟到的验证结果，都不能覆盖新现场。来源文件、未知字段、非法引用或错误程序不会被悄悄删减后接受。

协作房间内允许查看和纯检查，但不允许通过此入口载入本地示例或写入候选。需要修改本地设计时先离开共享房间。

## 自定义 CPU 的源码调试

选择自定义 CPU 后，右侧的“观察机器字与状态”同时支持旧 `std.custom-cpu16/1` 和新 `/2`。封装内的 CPU 可以用完整实例路径选择；每个实例显示自己的真实寄存器、外部总线等待、故障和源码行。源码来自已应用程序及其实际 ISA 的汇编映射，候选源码不会冒充正在运行的指令。

输入可执行源码行号并添加断点，继续运行会在该行第一个微操作之前暂停。“下一拍”推进一个真实时钟；“下一条指令”推进到一次指令退休、故障、停止或其他执行保护命中。它不跳过外部总线等待，也不会直接改写寄存器。若中断此时被接受，下一条退休的指令可能来自中断处理程序。未应用候选存在时必须先应用，协作房间内不能从此入口控制本地执行。

新 `/2` 还显示中断允许、已保存现场及返回 PC、中断进入次数。可以在处理程序设置断点，逐拍查看寄存器变化，再逐条执行到 `IRET`：恢复的是该实例实际保存的寄存器和调用栈，写入外部 RAM 的结果仍保留。持续高电平不会反复触发同一个请求；先把 IRQ 拉低使其重新武装，再拉高才能检查下一次进入。PC 和向量均为指令索引，不是字节地址。

“编辑指令集 / 协议 / 程序”会将 `/2` 导向芯片设计器，同一份 ISA 用于表格编辑、源码汇编、手册与调试；旧 `/1` 编辑方式保持兼容。

## 接口与验收

`StudioV8` 为无 DOM 的编辑辅助模块，提供 `supported`、`read/describe`、`validate`、`write`、`update`、`assemble`、`manual`、`inspectMMIO`。修改函数返回独立对象，不原地改输入；`validate` 返回 `{ok, parameters?, errors}`。`manual` 的内容由同一模型元数据和玩家参数产生，不维护另一份可漂移的指令表。

`StudioUIV8` 提供 `open(instanceId)`、`openStudio()`、`check()`、`save()`、`apply()` 和只读 `draft`。纯辅助、UI 和样式分别位于 `game/studio-v8.js`、`game/studio-ui-v8.js`、`game/studio-ui-v8.css`。

自动验收见 `tests/studio-v8.test.cjs` 与 `tests/browser/studio-v8.cjs`。浏览器记录写入 `qa/v0.8/studio/`，包括真实修改后的 CPU/总线/FSM/协议结果、拒绝负例、异步现场保护和窄屏截图。整体发布验收以当前版本验收记录为准。

源码调试验收见 `tests/browser/custom-debug-v8.cjs`，覆盖中断前断点、真实单步、返回、重入请求、自定义助记符、独立嵌套实例与窄屏。该轮新增 8 项、旧自定义架构 13 项均通过；记录分别为 `qa/v0.8/custom-debug/custom-debug-v8.json` 和 `qa/v0.8/browser-custom-architecture-legacy.log`。
