# 架构实验室：CPU16、状态机与自定义设备

版本：0.5.0。功能级数字模型。原有 Core8 与 Build8 的模型、程序和接口保持不变。

## 玩家可以做什么

从工作台「架构实验室」打开三个可运行作品，或在元件库单独放置四个新模型：

| 模型 | 可修改内容 | 真实可观察行为 |
|---|---|---|
| `std.cpu16/1` | 程序、总线超时、中断向量和优先级 | 8 个 16 位寄存器、PC、SP、调用栈、中断现场和总线请求 |
| `std.busram16/1` | 1—4096 词容量、初始内容、响应延迟 | 读写实际 RAM；按请求/响应握手完成 |
| `std.fsm16/1` | 状态、每个状态的输出、按输入选择的转移 | 当前状态编号与 16 位输出；每拍最多一次转移 |
| `std.register-device16/1` | 寄存器地址、权限、复位值、外部输入和输出寄存器 | 写入、写一清零、读清零、拒绝非法访问 |

「数组求和与子程序」通过间接寻址把 1—8 写入独立 RAM，使用 CALL、PUSH、POP、RET 求和，再把 36 写到 RAM[16]。CPU 没有内置数据 RAM，断开返回数据或完成信号会产生故障。「自定义寄存器设备」会实际写入 90、读入输入值，并演示 W1C 和读清副作用。「可编辑状态机」可修改成不同的有限控制序列。

选中元件可打开「编辑程序 / 控制表 / 参数」。CPU 源码草稿保存在作品的 `sources['architecture:'+实例ID]` 中，与已应用的 `parameters.source` 分离。检查不改变实际运行程序；应用才重新上电。状态表和设备说明必须先通过完整验证。封装包里的 CPU 程序在模块参数中，不依赖额外固件文件。

## CPU16 结构与指令

这是新的教学处理器行为模型；它没有调用 Core8 代执行，也不声称兼容真实商用 ISA。Build8 的可见门级/模块级结构仍独立存在。

- R0—R7：8 个 16 位无符号通用寄存器，复位为零。
- PC：程序指令索引，ROM 最多 1024 条指令。不是字节地址。
- 内部栈：64 个 16 位字，由 CALL/RET 和 PUSH/POP 共用；SP 是栈深度。
- 数据地址：16 位**字地址**；LOAD/STORE 全部经外部数字总线。没有隐式映射的内置 RAM 或外设。
- 程序：最长 60000 字符的严格汇编文本，被解析为受限指令记录。没有 `eval`、动态代码或上传插件执行。
- 运算溢出按 65536 回绕，没有隐含标志寄存器；条件分支直接检查指定寄存器。

| 指令 | 行为 |
|---|---|
| `NOP` | 不操作 |
| `LDI Rd,n` | 装入 0—65535 常数 |
| `MOV Rd,Rs` | 复制寄存器 |
| `ADD / SUB Rd,Rs` | 16 位加减 |
| `ADDI / SUBI Rd,n` | 加减立即数 |
| `AND / OR / XOR Rd,Rs` | 按位运算 |
| `NOT Rd` | 16 位取反 |
| `SHL / SHR Rd,n` | 逻辑移位，n=0—15 |
| `LOAD Rd,address` / `LOAD Rd,[Ra]` | 读取直接或寄存器指定的字地址 |
| `STORE Rs,address` / `STORE Rs,[Ra]` | 写入直接或寄存器指定的字地址 |
| `JMP target` | 跳转到标签或指令索引 |
| `JZ / JNZ Rn,target` | 检查寄存器是否为零 |
| `CALL target` / `RET` | 压入返回位置/检查返回位置后弹出并跳转 |
| `PUSH Rn` / `POP Rn` | 压入/弹出一个字 |
| `EI / DI / IRET` | 允许中断、禁止中断、恢复中断现场 |
| `HALT` | 停止 CPU，其他器件继续运行 |

共 26 个指令名称。寄存器和指令名称不区分大小写；标签区分大小写。数字可用十进制或 0x 十六进制，分号引入注释。静态目标始终验证，无效数字、无效寄存器、超长程序和尾部空标签不能成为跳转目标。

## 时序与总线合同

每拍为 1 虚拟微秒。普通指令用一拍取指、一拍执行。执行阶段仍可从源码行号定位具体操作。

| CPU 输出 | 从设备输出 |
|---|---|
| `req`：有效请求，等待期间保持高 | `ready`：事务完成 |
| `we`：1 写、0 读 | `error`：仅与 ready=1 同拍有效 |
| `address[16]`：字地址 | `rdata[16]`：读取成功时的数据 |
| `wdata[16]`：写数据 | |

CPU 在 LOAD/STORE 执行拍末锁定请求。后续拍只有看到真实 `ready=1` 才完成；未完成时 PC 和退休计数不推进。完成后取指阶段使 req 至少保持一整拍低。req 低时其余主端输出不表示有效事务。

RAM 和寄存器设备在采到 req 高时锁定请求，再等 `latency` 拍完成。响应保持到 req 低；持续高电平不会重复操作。事务完成前 req 低则取消。设备启动或复位后必须先看到 req=0 才重新武装，避免复位后重复执行旧请求。请求被接受后修改地址不会重定向在途操作。

`busTimeout` 默认 256，范围 1—65535，是 CPU 等待响应的最大采样次数。未知 ready、成功响应中的未知数据/错误位、设备 error 与超时均产生明确故障；失败读取不改变目的寄存器。设备已提交的事务不会因响应线后来断开而回滚。

冷启动清 CPU 状态、调用栈和中断帧。全局暖复位对 CPU 同样清零，但独立 RAM 保留内容；RAM 的同步 reset 引脚是冷复位。失电再上电重新装入初始内容。在途状态可保存为快照并确定性恢复。

## 中断

输入为 `irq` 和 `irq_id[2]`，输出为单拍 `irq_ack` 与 `irq_ack_id[2]`。中断在取指边界进入。外部控制器应收到确认后至少一拍撤回 irq，再提出新的请求。

四个 `vector0—3` 参数是程序指令索引；`priority0—3` 数字越小优先级越高，默认 0、1、2、3。同级和低优先级不能嵌套。进入中断后清 IE；处理程序显式 EI 后允许更高优先级进入。最多 4 层独立现场，每层保存 PC、所有通用寄存器、完整调用栈及 IE。IRET 全部恢复，因此持久结果需写外部 RAM 或设备。

调用栈溢出、空栈返回、无效返回地址、非法 IRET、未知中断输入均故障停止。HALT 不被中断唤醒。这些选择属于明确教学合同，不表示真实处理器的周期和上下文开销。

## 状态机与自定义设备

状态机 JSON 含 `initial`、`states`。每个状态有唯一 id、output 和有序 transitions；每条转移为 `{mask,value,next}`，按第一个符合 `(input & mask) === value` 的规则转移，不匹配则保持。最多 64 个状态、256 条转移；每拍一次；mask=0 为无条件转移。所有输出都是实际模型状态，不是演示动画。被检查的输入位为 X/Z 时故障停止，复位恢复。

寄存器 JSON 含 `registers` 数组，最多 64 项；每项含 address、name、access、reset，可选 `source:"input"`：

- `rw`：读当前值，写入替换。
- `ro`：只读；可通过 source 从实际 16 位 input 采样。
- `w1c`：读当前值，写入中的 1 清对应位。
- `rc`：读出旧值后清零；写入拒绝。

不存在的地址、写禁止寄存器返回 error，不改状态。outputAddress 必须指向一个存在的寄存器；out 可接显示器或其他数字逻辑。模型当前提供的是**数字寄存器请求/响应协议**；它没有额外宣称支持任意 UART/SPI/I²C 从设备。可与系统总线互连接入 CPU。

## 源码调试与工程边界

调试台支持按源码行断点、按地址设置读/写/任意观察点、逐拍、逐指令和继续。所有停止条件根据真实 CPU PC、执行阶段和寄存器计算。行断点与访存观察点均停在该指令产生请求或寄存器副作用之前。

停止条件通过工作台 `registerExecutionGuard` 接入普通运行和大步推进，没有覆盖已有仿真驱动。无停止点时不注册逐拍拦截。单步显式越过当前停止点；继续会在下一次满足条件时重新停止。进入协作房间后，架构 UI 拒绝本地编辑、替换示例和控制执行；不覆盖权威房间状态。

模型是有限资源的同步数字抽象，不模拟电压、电流、亚稳态或物理时序收敛。程序 ROM、栈、状态表、寄存器表和编译缓存全部有界；当前工程与房间的统一资源限制仍适用。

## API 与验证入口

`ArchitectureV5` 提供与 HardwareV3 一致的 provider 方法；额外导出 `assemble`、`build`、`SAMPLES`、`DebugSession` 和 `manuals={entries,portHints}`。assemble 的 sourceMap 是“PC 指令索引 → 原始源码行号”；labels 是大小写保留的普通对象。

运行 `node --test tests/architecture-v5.test.cjs` 验证 CPU、外设、快照、断线、中断与封装行为。浏览器脚本 `tests/browser/architecture-v5.cjs` 使用真实工作台入口，结果写入 `test-results/browser/architecture-v5-results.json`。本文件不把尚未执行的验收项目写成已通过；最终数量以实际报告为准。
