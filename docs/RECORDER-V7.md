# 本地数据记录器

版本 0.7.0。使用现有 CPU16、地址译码、输入寄存器与 RAM 模型组成作品，没有新增仿真模型。这个版本记录的是公开数字输入，通信接口仍留在后续版本；这里没有 UART、SPI、I²C 或物理传感器采样。

## 从哪里开始

从「数据记录器」选择一个起点，原工作现场可以返回：

| 起点 | 已提供 | 需要玩家完成 |
|---|---|---|
| 从接口开始 | 两个实际输入寄存器、64 词 RAM、sample/control/reset 接口 | 添加可执行程序的 CPU、译码器与真实总线接线 |
| 从骨架开始 | 完整接线与初始化后 HALT 的程序 | 读取样本、序号去重、追加、暂停、清空、容量处理 |
| 运行参考作品 | 完整作品与可编辑程序 | 观察数据路径，再修改程序、接线和实现方案 |

参考作品有两种可运行程序，满足同一个公开合同：

- **寄存器游标轮询**：计数、上一序号、清空编号保存在 CPU 寄存器中，使用间接寻址追加数据。
- **RAM 游标与子程序**：每轮从 RAM 读取游标，以 `CALL` / `RET` 分开追加和清空，使用真实调用栈保存现场。

两者不是提前生成记录的动画。删掉记录指令、改写数据指令、断开真实总线或者输入线，会改变结果或产生故障。面板只读已应用电路的实际 RAM，验证则运行候选工程的独立副本。

## 使用顺序与边界

1. 启动并推进 400 μs，让程序完成初始化。当前输入序号成为启动基准，不记录启动前已经存在的值。
2. 提交数值 0—255。默认序号递增，也可以指定 0—255 的序号。每次输入至少保持 400 μs，参考程序保证在这个时间内处理。
3. 同一序号的重复提交不追加记录；不同序号可以具有相同数值。序号 255 到 0 是有效变化。
4. 「暂停记录」由程序读取控制输入后生效。暂停期间 CPU 仍运行，输入可以改变；恢复时只记录最新序号，不补记每个中间变化。
5. 第 8 条提交后显示已满，后续样本不覆盖前 8 条。该版本是有限缓冲，不是循环缓冲。
6. 「清空记录」发送新的清空编号并关闭记录开关。程序清空逻辑计数、记住当前序号，再确认编号；恢复后要有新序号才追加。

全局仿真暂停与「暂停记录」不同：前者冻结虚拟时间及排队事件，后者需要推进电路，CPU 继续轮询控制寄存器。记录按钮并不直接修改 RAM。

提交过快可能只被读到最后一个值，因为公开接口是保持值的输入寄存器，不是队列。400 μs 是所附程序在本板连接和延迟参数下的处理约定；修改程序或增加延迟后，应重新验证。

## 实际电路与地址

参考板有 6 个独立元件。CPU 主总线连接 `memory_map`；其 RAM 窗口连接 `ram`，设备窗口连接 `device_map`，后者分别连接两个只读输入设备。

| 角色 / 模型 | 字地址 | 行为 |
|---|---|---|
| `cpu` / `std.cpu16/1` | 程序独立存于 `parameters.source` | 真实取指、执行、寄存器、栈、握手读写 |
| `memory_map` / `std.bus-decoder16/1` | RAM 0x0000—0x003F；设备 0x1000—0x1001 | 选择窗口并转换为下游相对字地址 |
| `device_map` / `std.bus-decoder16/1` | 下游相对地址 0 和 1 | 分别选择样本与控制设备 |
| `ram` / `std.bus-ram16/1` | 0x0000—0x003F | 64 个 16 位词，实际存储与握手响应 |
| `sample_device` / `std.register-device16/1` | 0x1000 | 事务完成时读取真实 `sample` 输入 |
| `control_device` / `std.register-device16/1` | 0x1001 | 事务完成时读取真实 `control` 输入 |

所有地址都是 **16 位字地址**。两组设备都是 `source:"input"` 的只读寄存器；不是读一个预设 JavaScript 数组。各总线包含 `req/we/address/wdata/rdata/ready/error`，请求等到真实应答后才完成。默认从设备延迟为 1 拍，CPU 等待超限为 256 拍。

公开输入：

| 名称 | 宽度 / 编码 | 初值 |
|---|---|---|
| `sample` | 高 8 位：序号；低 8 位：数值 | 0x0000 |
| `control` | 高 8 位：清空编号；bit0：1 记录 / 0 暂停；bit1—7 保留为 0 | 0x0001 |
| `reset` | 1 位同步高有效复位 | 0 |

序号和清空编号均按 8 位回绕，比较的是“是否不同”，不是大小或时间先后。参考程序忽略 `control` 的保留位；任务界面始终写 0。按键、传感器等后续来源必须通过实际电路转换为这个输入合同。

## 公开 RAM 记录格式

这项任务固定使用角色路径 **`ram`**，状态路径为 `hardware.memory`。封装内可用 `scope/ram` 只读观察。元件显示名称可以修改，角色 ID 不随意改名；缺少角色或公开输入会报告接口不兼容，不能当作普通功能未通过。需要换角色 ID 时，应同时另建相应测试合同。

| RAM 字索引 | 含义 | 有效值 |
|---|---|---|
| 0 | 完整会话标记 | 0x5243；初始化和清空重建期间为 0 |
| 1 | **已提交记录数** | 0—8，是追加记录的发布点 |
| 2 | 程序状态 | 1 记录中 / 2 暂停 / 3 已满 |
| 3 | 程序已经确认的清空编号 | 0—255 |
| 4 | 程序记住的上一序号 | 0—255 |
| 5 | 本任务容量 | 8 |
| 16—23 | 8 个记录槽 | 高 8 位序号，低 8 位数值 |
| 其他 | 当前合同未使用 | 玩家扩展时不要改变上述公开字段 |

追加顺序为：先写 `RAM[16+count]`，再更新上一序号，最后写新的 `RAM[1]`。面板只显示前 `count` 个完整记录槽，所以已经写入但尚未提交的下一个槽不会被展示。不同程序不必使用同样的寄存器或子程序组织，但必须保持公开结果及提交语义。

`inspect` 只有在 magic、capacity、count、状态、清空编号、上一序号和已提交 payload 都有效时才展示记录。未初始化或错误元数据不会被自动修正。CPU 刚复位而旧 RAM 标记尚未失效时，也不会显示旧记录为新会话；这个保护读取 CPU 的真实退休状态。

## 复位、故障与快照

冷启动及高有效 `reset` 会按原模型规则重置 CPU、设备与 RAM。全局暖复位会保留 RAM 物理内容，但是 CPU 程序重新执行：取消旧标记、清提交计数、以当前输入序号建立新会话。因而暖复位后旧槽可能仍有字值，逻辑记录为空，不会重新采集保持不变的旧样本。

清空同样只重建逻辑元数据，旧槽不需要逐个擦除。想观察原始 RAM 可以使用元件检查器；原始残留字不等于有效记录。

断开样本线会使输入读取未知，设备记录 `F_INPUT_UNKNOWN`，CPU 收到总线错误；断开应答线会产生总线故障。重新接线后须复位或重新应用程序恢复，不能靠面板按钮伪造成功。

快照保留实际 CPU、RAM、控制输入和在途请求，恢复后延续原会话。模块封装保留生效源码在 CPU 参数中；两个放置实例具有独立状态和输入映射。程序编辑器里的未应用源码草稿存于工作区 `sources['architecture:cpu']`，不是运行状态。

## 四阶段检查

| 阶段 ID | 实际检查 |
|---|---|
| `sample` | 初始化、容量、第一条真实 payload 和最后提交计数 |
| `sequence` | 重复序号、相同数值的新序号、顺序与序号回绕 |
| `control` | 暂停、期间变化、恢复最新值、清空确认与重新记录 |
| `capacity` | 前 8 条、拒绝第 9 条、所有旧记录保持及已满状态 |

`all` 是一个合法的现有测试台合同，共 52 个检查。阶段之间使用真实输入事件及暖复位建立独立会话。可以在时间线中复制、编辑合同做自己的实验；修改后的检查不自动代表完成原任务目标。

## 模块 API

浏览器全局 `RecorderV7`，CommonJS `require('./recorder-v7.js')`。提供纯元数据 `list/startModes`、`programs`、`stages`、`layout` 和常数 `CAPACITY=8`、`SETTLE_US=400`。

- `await build(mode='reference', {program:'polling'|'subroutine'})`：返回标准 `{project,view,sources,lesson}` 工作区；只使用标准 `view.positions`，不扩展工程 schema。
- `inspect(runtime, scope='')`：只读返回 `{available,compatible,initialized,capacity,count,status,statusName,clearToken,lastSequence,records,faults,time,reason}`。记录项为 `{index,sequence,value,raw}`；故障项为 `{path,code}`。
- `submit(runtime,value,{sequence?,scope?,inputMap?})`：只排一个真实输入事件，返回 `{sequence,value,raw,event}`。默认序号考虑已经排队的同输入事件，但不保证每个快速排队值都能被采到。
- `setRunning(runtime,boolean,{scope?,inputMap?})`：保留清空编号，只修改运行位并排队。
- `clear(runtime,{scope?,inputMap?})`：递增清空编号并关闭运行位，只排队；等待 `inspect().clearToken` 确认。
- `contract(stageId='all')` / `spec(...)`：返回 `chip-game.testbench/1` 合同，无自定义执行器。
- `await verify(workspace,{stageId='all',signal?,onProgress?})`：返回现有 `LabTestbench.run` 的结果字段加 `stageId`。取消信号传递给测试台；不推进传入工作区以外的现场。

模块放置后的输入 ID 是引擎生成的标识，不可自行拼接。调用控制 API 时传入 `inputMap: placed.boundaryMap`，并指定 `scope: '模块实例ID'`；观察使用 `inspect(runtime,'模块实例ID')`。未提供正确公开输入映射会明确拒绝。
