# 自定义指令集与数字协议

版本 0.6。入口为工作台“自定义架构”，详细参考也可在芯片用户手册中查询“自定义 ISA”与“可编辑数字协议控制器”。所有行为来自实际执行的机器字、微操作和接线。

## 可以做什么

- 定义助记符、8 位操作码、1—16 个通用寄存器，以及一条指令内 1—8 个微操作。取指后，每个微操作按拍执行，可以单独观察计算中间值。
- 将自己的 CPU 接到外部 RAM、地址译码器、仲裁器或寄存器设备；访存必须收到真实线路上的完成应答。
- 使用 CALL、RETURN 与公共数据栈，构造子程序、循环和间接访存。改变操作码会改变机器字，改变微操作会改变计算结果。
- 编写数字协议状态表，按电平、上升/下降沿、计数与等待时间转移，实际移入/移出数据。断线、未知输入、等待超时都是明确故障。
- 保存设计、封装模块、复制独立实例，或保存包含执行中间状态的快照。源码草稿与生效程序分开保存。

## 三个可玩示例

**我的 MIX 指令**：MIX R0,R1 的第一拍计算 TMP=R0×R1，第二拍计算 R0=TMP+1。给定 5 与 7，经外部 RAM 地址 16 写入、再读回，R3=36。在执行面板单步可看到 TMP=35。

**改助记符、操作码与微操作**：LIT 改成 CONST、操作码改成 0x61；MIX 改成 MAC7、操作码 0x77，第二步从加 1 改成加 7。同样真实访存读回 42。此 ISA 不再接受旧助记符 LIT。

**按真实边沿接收 8 位数据**：input bit0 启动，bit1 时钟，bit2 数据。面板“复位并发送 8 位”将所填字节按最高位优先变为真实输入事件；165 得到 165，60 得到 60。连续高电平只算一个上升沿。停止提供边沿会故障；把接收完成条件改成 4 位可收取高半字节。

## 创建与修改

1. 打开示例，选中 CPU/协议控制器，点击“编辑指令集 / 协议 / 程序”。
2. CPU 可用单条指令快捷编辑；完整 JSON 可添加、删除指令或改变操作数格式。改助记符后同时改源码。
3. “检查并汇编”验证候选设计，生成机器字及 PC 到源码行映射。它不会替换正在运行的电路。
4. “保存草稿”保存候选参数；“应用设计”验证整个工程并重新启动生效版本。CPU 源码输入过程也会存入作品草稿；未应用时执行的仍是旧程序。
5. 可修改机器字，然后“反汇编到源码”；应用之前同样不会改变执行。
6. 打开“观察机器字与状态”，选择实例，逐拍/逐指令运行或设置源码行断点。行断点停在取指完成、第一微操作之前。

协作房间内禁止此面板替换本地工程、修改参数或推进本地执行，以保留房间的权威状态。先返回本地工作现场再编辑。

## 自定义 CPU 合同

模型 ID 为 `std.custom-cpu16/1`。16 位数据、16 位外部字地址，程序最大 1024 条，每条 32 位。PC 是指令索引，不是字节地址。

参数为 `isa`、`source` 两段最多 60000 字符的文本，以及 `busTimeout`（1—65535，默认 256）。ISA JSON 的固定字段为 `schema:"silicon-lab.isa/1"`、`name`、`registerCount`、`instructions`。最多 64 条指令，总微操作最多 512。

每条指令是 `{mnemonic,opcode,form,steps}`；助记符唯一且匹配 `[A-Z][A-Z0-9_]{0,19}`，操作码唯一且为 0—255。编码固定为 `opcode[31:24] | rd[23:20] | rs[19:16] | imm[15:0]`。未用字段必须为零。

| form | 操作数 |
| --- | --- |
| none | 无 |
| r | Rn |
| rr | Rn,Rm |
| ri | Rn,16 位无符号立即数 |
| target | 标签或指令索引 |
| rt | Rn,标签或指令索引 |

源引用只允许常量、`tmp` 和格式中存在的 `rd/rs/imm`；目标只允许 `tmp` 或格式中存在的 `rd/rs`。微操作为 `nop/set/alu/read/write/push/pop/jump/call/ret/halt`；ALU 支持 `add/sub/mul/and/or/xor/shl/shr`。运算取低 16 位，移位量使用低 4 位。完整字段及默认 16 条指令见游戏内用户手册。

取指一拍，每个普通微操作一拍；访存可能等待多个拍。已执行的微操作会实际提交；同一指令后续故障不会回滚前面已完成的微操作或外部写入。故障给出 PC 与微操作索引。CALL 与 PUSH 共用 64 词栈，溢出、下溢和非法返回地址均故障。

输出 `req/we/address/wdata` 与输入 `rdata/ready/error` 遵循现有同步 1 μs 总线握手。请求锁定直到应答；完成后留至少一拍低请求，避免重复接收。未知 ready，或完成时未知 error/读数据，均故障；已知 ready=0 超时则报 F_BUS_TIMEOUT。

没有隐藏数据 RAM。此自定义 CPU 不含中断；固定 ISA 的 CPU16/1 仍提供原有中断能力。它与原有 Core8/Build8/CPU16 模型分别存在，不改变这些模型的指令与快照语义。

## 协议控制器合同

模型 ID 为 `std.protocol-fsm16/1`。唯一参数 `protocol` 是最多 60000 字符的 JSON。固定字段为 `schema:"silicon-lab.protocol/1"`、`initial`、`states`。1—64 个状态、总计最多 256 条规则，每条最多 4 个动作。

每个状态 `{id,output,timeout,rules}`；每条规则 `{when,next,actions}`。条件支持 `always/level/rising/falling/count/after`；动作支持 `clear/load/shift_in/shift_out/count_set/count_add`。完整字段见用户手册。未知字段、脚本和无效转移目标均拒绝。

每拍规则按顺序求值，第一条命中；一条规则的动作原子提交。动作失败不会部分改变移位数据或计数。转移包括自转移都清等待计数；未转移时递增，timeout 非零且到期故障。同拍命中规则优先于超时。初次采样建立历史，不凭空产生上升沿；快照保留边沿历史。

`out` 是状态输出，`data_out` 是移位寄存器，`serial` 是 bit15，`count/state/age/fault` 可接线观察。被实际条件/动作读取的未知位导致 F_INPUT_UNKNOWN；未读取的输入位不被静默转换成 0。输入高复位重新开始；未知复位立即屏蔽控制输出并产生故障。

## 保存、恢复与边界

模型参数携带 ISA/协议定义与生效源码，可随芯片模块携带；工作台 `sources["customarch:"+instanceId]` 保存顶层 CPU 源码草稿。快照另存寄存器、公共栈、微操作、在途访存、协议边沿历史。每个实例独立。

新增模块导出 `CustomArchitectureV6`，provider API 与现有行为模型一致；`assemble(isa,source)` 返回机器字、标签与源码行映射，`disassemble(isa,words)` 返回可再次汇编的源码。两个模型的完整手册通过 `manuals.entries/portHints` 导出。

数据格式严格且有界；只解释允许的操作，不执行任意 JavaScript。缓存最多 48 项。数字协议是按仿真拍采样的功能级模型，不声称是完整物理 SPI/I²C 或模拟电气。容量、指令格式和微操作集合有限；这使设计可保存、可验证、可复现。
