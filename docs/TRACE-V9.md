# 跨模块追踪与确定性回放 · v0.9

追踪面板用来回答：哪个模块发出了请求，什么时候收到了什么应答，处理器当时执行到哪里，以及断线、输入或复位前后发生了什么。所有记录来自当前电路的实际运行。点击工作台的 **追踪与回放** 开始。

## 玩家操作

1. 应用电路，打开追踪面板。选择要观察的实例。封装内的实例使用完整路径，例如 `left/cpu`。
2. 添加实际数字端口，例如 `cpu:req`、`dma:completed`。面板可列出当前电路的端口路径。
3. 选择触发条件：达到一个绝对仿真时刻、观察到总线应答/协议完成等事件、信号等于某值或出现 X/Z、状态字段达到某个值。
4. 设定触发前后各保留多少帧。点击 **开始捕获**，然后正常运行、单步或点击 **推进1000μs**。
5. 触发后的指定帧数完成时，整个工作台暂停。用帧游标查看各模块的 PC、寄存器、阶段、退休计数和探针值；按实例路径或请求 ID 筛选事件。
6. 点击 **独立回放并核对**。它从检查点建立另一个运行器，重放输入、断线、供电和复位，核对完整终态以及重新产生的观察记录。不会把结果覆盖到工作台。
7. 导出追踪包可保存本次检查点、工程、输入日志和观察记录；另一个离线浏览器可导入并核对。导入成功、校验和正确不等于已通过回放。

停止记录只结束捕获。触发完成、拍数预算耗尽和在提交阶段达到数据预算会暂停当前现场。回放可取消，关闭面板或切换工程也会取消旧回放；迟到的结果不会覆盖新的窗口状态。协作房间不能启动本地捕获；独立回放只读，不改变房间权威状态。

## 真实观察与解释边界

| 记录 | 含义 |
| --- | --- |
| `bus-request` | 在稳定输入采样阶段实际看到 `req=1`，记录地址、读写方向与数据。 |
| `bus-response` | 同一通道看到 `req=1 && ready=1`，记录真实 `error` 和 `rdata`。这表示该端口看到应答，不单独证明远端存储器已写入。 |
| `bus-withdraw` | 应答前请求变成低或未知；记录被撤去的实际信号。 |
| `retire` | 实际 CPU 退休计数增加。复位使计数归零不会被当成新指令。 |
| `irq-enter` / `irq-return` | 已观察中断帧深度增加/减少。减少可能是 IRET，也可能是复位；记录不据此编造原因。 |
| `route-created` | 运行器创建协议事务路由时发出的原生事件，包括真正的请求序号、来源、接收者资格及经过的导线版本。 |
| `protocol-complete` | 运行器实际完成事务后的结果，包括断线、接收者复位、器件错误导致的失败。 |
| `external` | 实际执行到的排队输入/断线/供电/复位/终端注入事件。这是事件被处理，不必然表示某个接收器接受了它。 |
| `issue` / `fault` | 运行器新诊断和所选处理器新故障。 |

数字总线 `bus:N` 是本次捕获中每个被观察通道的握手 ID。`cpu`、仲裁器和 RAM 各自的通道不会被自动归并为同一个事务。记录中的网络标识来自实际接线；共享网络证明连线关系，不能证明任意两个状态变化有因果关系。协议 ID 直接采用运行器 token 的序号。打开追踪前已经开始的握手标记 `originObserved:false`。

一帧是一轮实际提交，不保证正好一微秒。带同步硬件的电路通常逐微秒提交；Core8 等待、暂停或没有时钟活动时会跳过无事件区间。时间触发在首次观察到达到条件的提交时命中，不会插入隐藏时钟事件。状态和信号条件在提交后判断，和“执行前源码断点”不是同一功能。

帧只保存选中实例的小型状态和探针，不会每拍复制整块 RAM。完整 RAM、协议在途状态、队列、导线版本和依赖锁保存在起始、结束检查点中。Build8 的模块可追踪信号和握手；不会替它编造不存在的整颗 CPU 退休计数。

## 有界数据

默认最多选择 32 个实例、16 个数字探针；触发前后各最多 512 帧，合计最多 1025 帧。事件环最多 8192 条；新输入记录最多 4096 条；最多 200000 次实际提交；可回放时段最多 1000000 微秒。默认捕获设置更小：前后各 64 帧、2048 条事件、100000 次提交/微秒时段。

每个事件、帧和输入按自己的 UTF-8 序列化载荷计量。工程、起始检查点及预留结束检查点一并计入默认 24 MiB 总预算；可以用 API 设置更小预算。环形窗口移出记录会减去保留字节，同时增加移出计数。达到预算时停止，显示记录不完整，不能宣称完整回放；结束检查点本身放不下时不会保留它。预算是保留数据载荷上限，不是声称浏览器 JavaScript 堆恰好占用这些字节。

输入日志不会静默覆盖旧输入。输入预算耗尽后，仍可导出有限的观察资料，但包的 `replayable=false`。普通事件环和触发前窗口移出的旧记录会明确计数；只要输入日志和检查点完整，仍能重算全部过程并核对同一个保留窗口。

## 开发接口

`game/trace-v9.js` 导出 UMD `TraceV9` / CommonJS，无额外依赖：

```js
const capture = new TraceV9.Capture(runtime, {
  paths: ['cpu', 'dma', 'ram'],
  probes: ['cpu:req', 'dma:completed'],
  pre: 32, post: 16,
  trigger: { kind: 'state', target: 'dma', field: 'completed', op: 'gte', value: 4 }
}).arm();

runtime.setInput('dma_trigger', 1);
runtime.advance(1000n, { force: true });
capture.stop();                         // 已结束时无副作用
const bundle = await capture.export();
const result = await TraceV9.replay(bundle);
// result.ok 需要 matches.state 和 matches.trace 同时为 true。
```

接口包括 `listTargets(runtime)`、`validateConfig(config,runtime)`、`Capture.arm/stop/dispose/export`、只读 `Capture.progress`、`validateBundle(object|string)`、`replay(bundle,{signal,onProgress})`。UI 导出 `TraceUIV9.open/close/arm/stop/export/importData/replay/cancel`。

触发条件只允许数据结构，不接受表达式、JavaScript 或 `eval`：

- `time`：`{kind:'time',value:'200'}`。
- `event`：`{kind:'event',target:'protocol-complete'}`。
- `signal`：`{kind:'signal',target:'cpu:req',op:'rising'}`；目标必须先加入探针。
- `state`：`{kind:'state',target:'dma',field:'completed',op:'gte',value:4}`；只读取该实例的自有字段，最多四层，拒绝原型访问。

比较支持 `eq/ne/gte/rising/falling/unknown`。信号最多 32 位时以精确整数显示；更宽的已知数字用十六进制字符串，未知位保留 X/Z。状态计数如 `retired` 是十进制字符串，比较值也使用相同类型。

## 回放合同

追踪包 schema 为 `chip-game.trace/0.9.0`。工程和两个检查点沿用引擎原有校验；不会改变旧的工程、快照或芯片哈希。包的 SHA-256 校验和覆盖其余全部字段，检测意外损坏，不作为来源真实性签名。

每条输入日志保留 **排队时刻**、未来执行时刻和运行器原始序号。起始检查点已经包含的未来事件不重复排队。运行器创建协议 token 也使用同一个序号空间，因此回放在每次排队前核对序号，不能仅把按钮发生时刻复制一遍。

实际提交时刻另外记录，连续微秒压缩成范围；这样不同 `advance` 截止时刻不会改变等待期的观察历史。回放按这些边界推进，重建同样的有界观察器，并同时比较：

1. 完整终态快照，包括 RAM、CPU、协议在途状态、输入队列、导线版本、历史和诊断。
2. 保留的事件、帧、触发位置及丢弃计数。

暂停是无虚拟时间推进的控制状态；回放结束时恢复包内的暂停标志。回放每 128 次提交让出界面并检查取消信号，不替换既有调试器的 simulation driver。

只记录运行器公开排队输入接口产生的事件。直接改写 `runtime.states`、修改 JavaScript 对象、在观察器回调内部改变执行阶段等绕过正常输入接口的行为，不会被包装成可靠输入日志；终态或观察比对不一致时报告失败。回放不模拟模拟电压、电流，也不把事务协议解释为逐边沿电气波形。

## 验证证据

`tests/trace-v9.test.cjs` 覆盖真实 CPU/DMA 握手、复位与未来输入交错、嵌套实例、I²C 在途断线与重连、信号未知态、前后窗口、取消、恶意或损坏导入、日志/字节预算及 Core8/CPU16 单指令停止。大单条路由载荷预算测试明确是原生 observer 接口边界注入，不冒充一次实际路由完成。

`tests/browser/trace-v9.cjs` 覆盖玩家入口、100000 微秒响应式大批停止、自动运行停止、原调试台开启采集时停止、真实 DMA+复位独立回放、新浏览器导入、未提交文本、取消迟到结果、协作保护和手机布局。证据在 `../qa/v0.9/trace/`。
