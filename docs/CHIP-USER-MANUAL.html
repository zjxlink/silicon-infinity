入门

信号、输入、LED 与上电

先看懂数字、未知态、时钟和供电，再接线。

0 / 1 / X / Z 与数字位宽

0 和 1 是已知的数字逻辑值。X 是未知或冲突，Z 是当前没有驱动；Z 接入普通逻辑门时按未知处理，不会自动成为 0。

两个有效推挽输出接到同一位，即便都输出 1，也会形成驱动冲突并显示 X。需要输入的控制端应连接明确的 0 或 1。

写法含义
0x04十六进制 4，与十进制 4 相同
0b0100二进制 4；最右侧为 bit0
8 位可表示无符号 0—255；16 位为 0—65535
b0 / lob0 是最低位；lo 是 16 位数的低 8 位

输入开关与 LED / 输出

输入开关是工程的外部输入，LED / 输出是观察端，不是可编程芯片。点击输入或填写数字改变信号，LED 根据真实收到的值显示状态。

暂停时更改输入先排入事件队列；单步或运行后才生效。刚修改连线需要先“应用并重新启动”。LED 不模拟电流、压降或限流电阻。

组合逻辑与时序芯片

组合逻辑在输入传播稳定后直接得到输出。时序芯片在全局每 1 μs 的下一拍同时采样，再一起更新；一串寄存器不会在同一拍把新值直接传穿。

“暂停”冻结虚拟时间；“复位”是暖复位。暖复位可保留 RAM，而断电再上电会回到冷启动状态。各芯片的 reset 输入与顶部暖复位不一定相同，具体看该芯片手册。

接线规则

数字位宽必须相同；总线拆分/合并使用专门芯片。电源端口、数字端口和协议端口不是同一种线。UART、SPI、I²C 端口只接相同协议。

所有元件都受所属供电域控制；Core8 还需要同一供电域的 VCC/GND 实际接线。普通门和独立模块隐式供电。

8 位 ALU

4 位 OP 决定运算；所有数字按无符号处理。

OP 每个取值

这里 W=8，最大值为 255；OP 码与 Build8 的指令操作码不同。

OP（十进制 / 十六进制）运算OUTCARRY
0 / 0x0传递 BOUT=B0
1 / 0x1加法OUT=(A+B) 的低 W 位超过无符号最大值时为 1
2 / 0x2减法OUT=(A−B) 的低 W 位A≥B 时为 1（没有借位）；A<B 为 0
3 / 0x3按位与OUT=A AND B0
4 / 0x4按位或OUT=A OR B0
5 / 0x5按位异或OUT=A XOR B0
6 / 0x6按位取反OUT=NOT A，保留 W 位0
7 / 0x7逻辑左移OUT=A 左移 k 位的低 W 位移位前完整结果超过最大值时为 1
8 / 0x8逻辑右移OUT=A 右移 k 位，高位补 00（不记录被移出的位）
9 / 0x9传递 AOUT=A0

结果、ZERO 与 CARRY

OUT 截取低 8 位，溢出按模 256 回绕；没有有符号溢出标志。ZERO=1 表示截断后的 OUT 等于 0，否则为 0。

减法的 CARRY=1 表示没有借位，不能理解为“发生借位”。比较结果是整个总线上的数字 0 或 1，不是全部位都为 1。

左、右移的位数 k=B AND 7；仅使用 B 的低 3 位。因此 B=8 等价于移动 0 位。

未知输入与未定义操作

A、B、OP 任一包含 X/Z 时，OUT、ZERO、CARRY 全部为 X；即使该操作数学上不使用 B，也仍要求 B 已知。OP=14/15 未定义。

无状态、无复位、无参数。修改输入并推进事件后组合计算；失电输出 Z。

存储与时序 · std.ram8/1

256 × 8 RAM

256 个字；组合读、逐拍写，暖复位保留数据。

端口与操作

端口意义
ADDRESS8 位地址，0—255；不是字节偏移
DATA8 位写入数据
WRITE1在下一拍写入，0不写；持续为1会每拍写入
RESET1在下一拍恢复 contents 初值，优先于WRITE
OUT当前地址的存储值；读取无副作用
FAULT存在锁存故障时为1；需复位清除

参数和复位

contents 最多 256 个 0—255 的整数；未列的地址填0。顶部暖复位保留全部存储数据并清故障；冷启动/断电再上电/RESET引脚恢复 contents。

ADDRESS 不确定时 OUT=X。写入时 ADDRESS/DATA 含 X/Z，或控制信号不确定时置故障，不覆盖原存储。成功的后续写入不会自行清除已锁存 FAULT。

读写示例

ADDRESS=3、DATA=42、WRITE=1、RESET=0，逐拍写入后 OUT=42；将WRITE=0可反复读而不改数据。16位RAM同样只有256个地址，每个地址存一个16位字。

存储与时序 · std.fifo8/1

8 位 FIFO 队列

先进先出，所有 PUSH/POP 在下一拍处理。

端口和容量

capacity 参数范围1—256，默认16。初始队列为空；暖复位、冷启动、RESET=1均清空队列并清FAULT。

端口含义
DATA8 位待入队数据
PUSH1推入一个值；持续为1每拍推入
POP1弹出原队首；持续为1每拍弹出
RESET1下一拍清空，优先于PUSH/POP
OUT当前队首；空队列为X；读取不弹出
EMPTY / FULL空/满时分别为1
COUNT9位数量，0—capacity
FAULT锁存的满、空或未知控制/数据错误

同时推入和弹出

同一拍先 POP、再 PUSH。满队列同时POP/PUSH，可腾出一个位置再写入；空队列同时操作，会先因POP置空读故障，然后仍可成功PUSH。

满时单独PUSH拒绝新值并置FAULT；空时POP置FAULT。PUSH时DATA未知会拒绝新数据；RESET/PUSH/POP未知会置FAULT。后续成功操作不会自行清FAULT。

使用示例

依次让 DATA=65 和66，各PUSH一拍后关PUSH，OUT=65、COUNT=2。POP一拍后 OUT=66、COUNT=1。再POP后EMPTY=1、OUT=X。

先看懂寄存器表

所有 0x 开头的数都是十六进制；bit0 是最低位。RW 表示可读写，RO 只读，WO 只写，RW1C 表示读当前标志、写 1 清对应位、写 0 保持。示例中的分号后是注释。

Core8 的寄存器与存储

R0—R7 是八个可任意使用的 8 位寄存器，数值范围 0—255。加减与左移只保留低 8 位；没有隐藏的进位标志、比较标志或有符号运算。JZ/JNZ 直接检查指定寄存器。

PC 是 16 位字节地址，每条指令占 4 字节，正常执行后 PC 加 4。SP 是保留的 16 位观察字段，复位为 0；本指令集没有栈、CALL、RET 或访问 SP 的指令。

上电和冷启动：PC、SP、R0—R7、RAM、外设控制清零，GPIO 下拉 PD=0xFF；ROM 保留。暖复位也清寄存器与外设，但保留 RAM。复位会取消在途事务和 FIFO；观察历史保留复位标记。断电后输出不再驱动，再上电执行冷启动。

程序 ROM 共 4096 字节；固件至少一条、最多 1024 条指令，末尾补零，相当于 NOP。执行越出 0x0FFC 后无法取完整指令，会停止于 F_FETCH。

GPIO：方向、输出、输入、内部下拉

四个寄存器的 bit0—bit7 分别对应 GPIO0—GPIO7。DIR=0 时引脚不主动驱动，DIR=1 时驱动 OUT 对应位。PD 是明确的内部弱下拉，复位全开；外部有效信号优先于弱下拉。

IN 总是读取八个实际引脚，包括输出脚。任意一位为 X 或 Z 都使整次 LD 产生 F_UNKNOWN，目标寄存器保持原值，诊断指出未知引脚。多个有效推挽驱动即使写相同值也产生 X。接按键的引脚应保持输入。

UART：发送、接收、状态和错误

UART_TX 接终端 RX；终端 TX 接 UART_RX。它们是 uart-txn/1 事务端口，不能接普通数字线。固定 9600、8N1，每个字节耗时 1042 微秒；写 TX 不会立即在终端显示。

TX 与 RX 各容纳 16 字节，TX 长度包含正在发送的字节。满 TX 丢弃新字节并置 TX_OVERFLOW，程序继续；RX 满丢弃新输入并置 RX_OVERFLOW。读空 RX 是 F_RX_EMPTY，程序停止。

关闭 TX 清发送队列并取消在途字节；关闭 RX 清接收队列并使旧在途接收失效。重新开启不能找回取消的事务。关闭功能不会自动清 ERROR。断开终端时发送仍可完成，但没有接收消息；断线再接回也不能补交旧字节。

故障与执行顺序

F_ENCODING：操作码、寄存器编号或保留字节非法；F_TARGET：跳转目标非法；F_FETCH：PC 无法取完整指令；F_ACCESS：地址、权限或控制位非法；F_UNKNOWN：GPIO 输入未知；F_RX_EMPTY：读了空接收队列。发生故障的指令不会写寄存器、弹 RX、写总线或推进 PC。

FAULT 和 HALT 都停止 CPU，已经启动的 UART 和 Core8/2 外设仍继续；修正程序或接线后复位再开始。暖复位保留 RAM，重新编译并应用程序则从冷启动开始。

同一虚拟时刻先处理外部输入、断电和复位，再完成到期协议事务，再读取稳定的数字网络并执行指令。因此外部复位能取消同刻完成的字节；程序中同刻写“禁用”发生在完成之后，不能撤销已经交付的字节。

Core8 的寄存器与存储

R0—R7 是八个可任意使用的 8 位寄存器，数值范围 0—255。加减与左移只保留低 8 位；没有隐藏的进位标志、比较标志或有符号运算。JZ/JNZ 直接检查指定寄存器。

PC 是 16 位字节地址，每条指令占 4 字节，正常执行后 PC 加 4。SP 是保留的 16 位观察字段，复位为 0；本指令集没有栈、CALL、RET 或访问 SP 的指令。

上电和冷启动：PC、SP、R0—R7、RAM、外设控制清零，GPIO 下拉 PD=0xFF；ROM 保留。暖复位也清寄存器与外设，但保留 RAM。复位会取消在途事务和 FIFO；观察历史保留复位标记。断电后输出不再驱动，再上电执行冷启动。

程序 ROM 共 4096 字节；固件至少一条、最多 1024 条指令，末尾补零，相当于 NOP。执行越出 0x0FFC 后无法取完整指令，会停止于 F_FETCH。

UART：发送、接收、状态和错误

UART_TX 接终端 RX；终端 TX 接 UART_RX。它们是 uart-txn/1 事务端口，不能接普通数字线。固定 9600、8N1，每个字节耗时 1042 微秒；写 TX 不会立即在终端显示。

Core8/2 中断入口与返回

三个来源按低位优先：timer=1、SPI=2、I²C=4。没有 GPIO 或 UART 中断。外设自己的 IRQ_EN 允许时，事件先置 PENDING，不受全局 ENABLE/MASK 阻止；ENABLE=1、MASK 允许且不在 ISR 时，CPU 在指令边界进入同一个 VECTOR。入口自动清选中 PENDING 位，CAUSE 保留最后来源。

故障与执行顺序

F_ENCODING：操作码、寄存器编号或保留字节非法；F_TARGET：跳转目标非法；F_FETCH：PC 无法取完整指令；F_ACCESS：地址、权限或控制位非法；F_UNKNOWN：GPIO 输入未知；F_RX_EMPTY：读了空接收队列。发生故障的指令不会写寄存器、弹 RX、写总线或推进 PC。

FAULT 和 HALT 都停止 CPU，已经启动的 UART 和 Core8/2 外设仍继续；修正程序或接线后复位再开始。暖复位保留 RAM，重新编译并应用程序则从冷启动开始。

同一虚拟时刻先处理外部输入、断电和复位，再完成到期协议事务，再读取稳定的数字网络并执行指令。因此外部复位能取消同刻完成的字节；程序中同刻写“禁用”发生在完成之后，不能撤销已经交付的字节。

从 LED 和一个串口字符开始

空 RX 返回 X，置 ERROR bit1 并锁存 E_UART_EMPTY；RX 满丢新字节并置 bit1。TX 满丢新字节、置 bit0；TX 没启用时写入丢弃并置 bit2。错误不自动让取指控制器停机。

关闭 TX 清队列并取消在途；关闭 RX 清队列，旧在途接收不能混入重新开启后的 RX。CTRL 不清错误。清 ERROR 也不会清已锁存的 FAULT，FAULT 需复位。RX_IRQ_EN=1 且 RX 非空时 IRQ 保持高；读空队列前应先检查 STATUS bit0。

Build8/2 独立 SPI 主机

与 Core8/2 不同，写 DATA 只是准备数据，写 CMD=1 才开始事务。每字节 8 微秒，SPI_OUT 接 mode0 寄存器芯片 RX。首字节选择读/写 reg0—15，第二字节读或写数据，格式同本手册的 SPI 器件说明。

完成设 DONE=1，失败再设 ERROR=1；成功完成状态为 2、失败为 6，会替换忙期间的状态标记。IRQ_EN=1 且 DONE/ERROR 非零时请求保持高，写 STATUS 清标志。当前从设备仅支持 mode0；没有独立 CS 引脚或逐边沿时序。

外部总线与精确时序

一个普通指令用一拍取指、一拍执行，每拍为 1 虚拟微秒。LOAD/STORE 在执行拍末锁定地址、方向与写数据，并把 req 拉高；它们等待实际 ready=1 后才完成。等待中请求保持稳定。完成后进入下一条取指，因此至少有一整拍 req=0。

req=1 表示有效请求；we=1 写、we=0 读；address 为 16 位字地址；wdata/rdata 为 16 位数据。ready=1 时 error 才有效；error=1 表示设备拒绝。ready=0 时忽略 error/rdata。CPU 不凭等待时间伪造完成。

总线断线产生 X：未知 ready/error/读数据触发 F_BUS_UNKNOWN；拒绝触发 F_BUS_ERROR；等待超限触发 F_BUS_TIMEOUT。失败的 LOAD 不改目的寄存器、PC 或退休计数。外部设备已经完成的事务不会因为后来断线而自动撤销。

中断与嵌套

EI 后在取指边界检查 irq 和 irq_id。只有比当前中断更高的优先级才能嵌套；相同或较低优先级保持待处理。进入时保存 PC、全部寄存器、完整调用栈和 ie，清 ie，并输出一拍 irq_ack 与对应 irq_ack_id。

外部控制器必须在收到 ack 后至少一拍拉低 irq，之后才能提出新请求。CPU 对保持高电平的同一次请求只确认一次。处理程序需要显式 EI 才允许更高优先级嵌套。IRET 恢复完整现场；持久结果应写外部 RAM 或设备。

中断没有隐藏的定时器或 GPIO；需要真实连接外置中断控制器。未执行 EI 时可以不连接中断输入，EI 后输入悬空会 F_IRQ_UNKNOWN。HALT 不会被中断唤醒。

CPU16 · 外部握手 RAM

有容量、初始内容及响应延迟参数的独立 16 位数据 RAM。

参数与存储

depth=1—4096 词，默认 256；contents 是从地址 0 开始的 16 位初值，不足部分补零；latency=1—256，默认 1。数据地址是字索引，超出 depth 不回绕，而是返回 error=1。

全局暖复位保留 RAM 内容并取消在途事务；冷启动、失电再上电或 reset 引脚=1 重新装入 contents。快照保存完整存储、在途请求和响应。

握手与复位边界

启动或复位后先观察 req=0 一拍才接受请求。采到新 req=1 时锁定 we/address/wdata；再经过 latency 拍后完成读写并拉高 ready。完成前 req 变低会取消事务，没有存储副作用。

ready/error/rdata 保持到 req=0；持续 req 不会重复写入。未知请求字段产生拒绝与 F_REQUEST_UNKNOWN。写数据只在 we=1 时检查；读请求不要求 wdata 已连接。

可编辑状态机 · 状态与转移表

使用有限 JSON 控制表定义自己的控制功能。

状态表格式

table 包含 initial 和 states。每个状态包含唯一 id、16 位 output 和有序 transitions；每个转移包含 mask、value、next。每拍按顺序选择第一条满足 (input & mask) === value 的转移；都不满足则保持。输出是当前状态的 output。

最多 64 个状态、总计 256 条转移。value 不得在 mask 之外置位。mask=0 是无条件转移，可用于自动序列；next 必须存在。没有任意代码、动态对象路径或无限循环。

自定义架构 · std.custom-cpu16/1

自定义 ISA · 16 位 CPU

用受限微操作定义真正执行的助记符与操作码，连接外部 RAM 或总线设备。

开始创造自己的指令

从“自定义架构”打开“我的 MIX 指令”，选择 CPU 后点“编辑指令集 / 协议 / 程序”。MIX 先把 R0×R1 写入 TMP，下一拍把 TMP+1 写回 R0。外部 RAM 的 0x0010 地址以及读回的 R3 最终为 36。

可修改助记符、操作码、寄存器数量和微操作。“更新这条指令”只更新编辑框；“检查并汇编”只验证与显示机器码；“应用设计”才编译候选工程并重新开始运行。源码草稿与已应用程序分开保存。

“机器字与反汇编”支持将整数机器字还原成此 ISA 的源码。反汇编不保留标签和注释，但再次汇编得到相同机器字。

架构、时序与状态

16 位无符号数据，16 位外部字地址；程序是最多 1024 条、每条 32 位的独立只读镜像。PC 是指令索引，顺序执行 PC+1。这个 CPU 没有内置数据 RAM；所有 read/write 都经过可断开的实际总线。

可定义 1—16 个 R 寄存器，TMP 是每次取指清零的临时寄存器。PC、IR、微操作号、TMP、公共栈、寄存器和故障位置可在执行面板观察。输出 R0—R15 的端口数量固定，未启用的寄存器端口为 0。

每拍 1 μs：先取指一拍，再逐个执行微操作。普通微操作一拍；访存发出请求后等应答，完成后另留一拍 req=0 的间隔，再进入下一微操作。暂停冻结虚拟时间。

微操作逐拍提交：同一条指令前面的运算或已经完成的总线写入不会因后面的故障撤回。故障保留 PC / micro 精确定位并停止 CPU；外部设备按各自行为继续。

冷/暖复位均清 CPU 寄存器、栈、在途请求与故障，保留已应用 ISA 和程序。外部 RAM 的复位与保留规则由其自己的模型决定。此模型暂不提供中断；需要固定 ISA 的嵌套中断时可选 CPU16/1。

指令集 schema 与机器编码

指令集是 JSON 数据，不执行 JavaScript。根字段必须恰好为 schema、name、registerCount、instructions；schema 固定 silicon-lab.isa/1，名称 1—60 字符。最多 64 条指令，每条 1—8 个微操作，总数最多 512。ISA 文本和源码各最多 60000 字符。

每条指令字段必须恰好为 mnemonic、opcode、form、steps。助记符为 1—20 个大写字母/数字/下划线，首位为字母；助记符和 0—255 操作码分别唯一。机器字 bit31..24=opcode，23..20=rd，19..16=rs，15..0=imm。未使用字段必须全 0；超出寄存器数量、未知操作码和非法跳转目标均拒绝。

源码规则与微操作操作数

汇编助记符与 R 寄存器名不分大小写，标签区分大小写；分号开始行注释。数值允许十进制与 0x 十六进制，不接受负数。静态 target/rt 操作数必须指向镜像中的一条指令，尚未执行的条件分支也需满足此规则。

微操作源可为 0—65535 整数常量、tmp，以及本 form 中存在的 rd/rs/imm。rd 和 rs 表示该机器字选中的寄存器值；imm 表示立即数。目标只可为 tmp 或本 form 中存在的 rd/rs。没有表达式字符串、任意脚本或隐藏宿主访问。

移位量使用源 b 的低 4 位，即 0—15；所有算术结果取低 16 位。没有隐式进位/零标志，条件跳转直接检查指定源值。

外部总线连接和错误

req/we/address/wdata 接从设备的同名输入；从设备 rdata/ready/error 接 CPU 同名输入。与现有同步总线 RAM、仲裁器、地址译码器和寄存器设备兼容。双方 reset 必须有明确驱动。

req=1 时锁定请求直到看到 ready=1。仅 ready=1 时检查 error；读成功还需 rdata 所有位已知。应答后 req 至少低一拍。busTimeout 为 1—65535 拍，默认 256；等待达到该拍数且没有完成即报错，同拍成功应答优先。

从一个真实串行接收器开始

打开“自定义架构 → 按真实边沿接收 8 位数据”。input bit0=启动，bit1=采样时钟，bit2=串行数据。每次 bit1 从 0 到 1，控制器把当时 bit2 移入寄存器并计数。

“复位并发送 8 位”会给输入线排入复位、8 个真实时钟上升沿和逐位数据事件；输入 165 时 data_out=165、count=8、out=2。改变发送值会改变实际结果。停止时钟不会自动补齐数据，而会触发超时。

选择控制器，点“编辑指令集 / 协议 / 程序”修改 JSON 状态表。可把完成条件从 count≥8 改为 count≥4，发送 0xA5 后会只得到前 4 位的 10。

状态表 schema 与资源上限

根字段恰好为 schema、initial、states。schema=silicon-lab.protocol/1；initial 指向现有状态名。协议 JSON 最多 60000 字符、1—64 个状态、总计最多 256 条规则，每条最多 4 个动作。

每个状态字段恰好为 id、output、timeout、rules。id 是以字母/下划线开头的 1—32 个字母/数字/下划线且唯一；output 与 timeout 是 0—65535。output 是该状态稳定期间 out 端口的值；timeout=0 关闭该状态超时。

每条规则字段恰好为 when、next、actions；next 必须是现有状态名。条件与动作只允许下表字段，不支持任意表达式或脚本。

中断入口、屏蔽与单层返回

复位后ie=false。EI的微操作只设置使能；只有phase=fetch，也就是上一整条指令全部微操作完成之后，才会接受新的IRQ。bus等待、完成间隔、指令内部微操作均不会被打断。

有效入口同时要求：ie=true、没有irqFrame、请求已武装且irq=1、vector全部已知并指向程序中的指令。入口独占一拍，不退休普通指令；irq_ack拉高一拍，然后开始取处理程序指令。

入口保存下一PC、上次IR、TMP、所有通用寄存器、完整公共栈和旧IE。处理程序初始保留寄存器值，TMP/IR清0，公共栈从空开始；独立现场不占用64词调用栈容量。入口将IE清0。

本版不嵌套：处理程序内即使执行EI，也不会再保存第二份现场。IRET恢复全部保存内容并返回；需要留下的处理结果应写外部RAM或设备。处理程序自己的临时栈和寄存器修改随后被恢复值替代。

irq_ack之后必须看到irq=0至少一拍才重新武装；持续高电平不会重复进入。屏蔽或处理程序运行期间出现并保持的请求可在之后进入；短脉冲若没有外部控制器锁存则可能错过。

与外部中断控制器连接

std.irq4/1输出的是2位irq_id，本CPU输入vector是16位指令索引，两者不能直接连接。用真实多路选择器和向量常量完成译码；irq接irq，irq_ack回控制器ack，当前irq_id回ack_id。

req/we/address/wdata为主机输出，rdata/ready/error为从机输入。请求与字段锁定到真实应答，ready=0忽略error和rdata，ready=1检查error和有效读值。未知应答、设备拒绝、超时各自故障。

reset=1优先清CPU及中断现场并撤请求；未知reset立即屏蔽req与ack，下一拍故障。冷暖复位均清CPU现场，但外部RAM是否保留由RAM模型规定。暂停冻结全部拍数。

故障、快照与边界

故障不发中断确认，保持精确PC与微操作位置，取消未完成的CPU请求。不会承诺撤销外部设备已经提交的事务。

快照保留全部原CPU状态和单层现场。导入验证寄存器/栈预算、实际机器字、在途微操作、返回位置和确认阶段；拒绝非法现场，不修补成可运行状态。

IRQ在被屏蔽、处理程序中或尚未重新武装时不会采样vector；这些状态的未知vector不被虚构成0。只有可接受新中断的完整边界，未知IRQ才是故障。

可写存储与数据寿命

存储按字节寻址，深度1—4096；越界拒绝，readOnly=1拒绝写。写入在协议完成时原子提交，writeBusyUs表示提交之后的设备忙期。忙期不是第二次尚未提交的写操作。

暖复位保留已写memory；nonvolatile=1时冷复位和断电/上电也保留。nonvolatile=0在冷复位或电源转换恢复contents。复位总取消未完成事务和内部忙，绝不复活旧请求。

新工程实例从contents初始化。只保存设计不会包含当前已写字节；要保存运行数据请保存完整现场/快照。
