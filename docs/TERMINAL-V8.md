# 自制 MCU 数据记录终端 v0.8

这块板用真实可编辑程序串起定时器、按键、传感器、存储、DMA、显示和双向串口。它提供固定 CPU16 与可自定义指令集 CPU /2 两种核心；两者接同一类外部总线和外设，程序由同一份算法生成对应汇编。没有隐含 Core8 执行器，也没有脚本代写记录结果。

## 从信号到一条记录

1. 定时器到期，经 IRQ0 进入程序中断；处理程序清设备状态并设置 `due`。
2. 主程序启动 I²C 读取。地址 72（0x48）、寄存器 1 的值在实际事务完成当拍来自传感器 `sense` 引脚。
3. 主程序把该字节经 SPI 写到独立非易失存储器，再从同一地址读回并比较。写后忙会明确失败，程序会重试读取，最多 64 次。
4. 比较成功后，CPU 将数值写到外部 RAM 记录区，并设置 DMA 地址/长度、发出触发。DMA 作为仲裁器第二主端，逐字读取记录区、写入备份区。
5. DMA 成功后，程序更新 GPIO 输出、最新值和记录数。`RAM[1]` 是这条记录的提交点。
6. 程序发送原始采样字节到串口。该步骤有真实 1042 µs 延迟；串口断开时计错，但不会撤销已经提交的记录。

记录容量为 8，满后停止新采样，不覆盖旧条目。定时中断可以继续发生。过快的采样请求合并为一个待处理标志，不承诺逐个保留所有定时边沿；两种核心的指令耗时不同，也不承诺逐拍相同。它们遵守相同记录、控制与外设协议。

## 接线与地址空间

CPU 是仲裁器 m0，DMA 是 m1。多级地址译码器把下面窗口转换为各个从端的相对字地址。每条数字总线都包含 REQ、WE、ADDRESS16、WDATA16、RDATA16、READY、ERROR，完成后请求必须低至少一拍。

| CPU 字地址 | 模块 | 用途 |
| --- | --- | --- |
| 0x0000–0x00FF | RAM，256 个 16 位字 | 程序元数据、记录、备份、串口命令队列 |
| 0x0100–0x010F | GPIO | 输出显示、实际按键输入、变化中断 |
| 0x0110–0x011F | TIMER | 周期、控制、状态、IRQ 使能 |
| 0x0120–0x012F | DMA 配置端 | 源地址、目标地址、长度、触发、完成状态 |
| 0x0130–0x013F | UART 控制器 | 异步发送、接收 FIFO、IRQ |
| 0x0140–0x014F | SPI 控制器 | 独立存储器读写 |
| 0x0150–0x015F | I²C 控制器 | 传感器寄存器读取 |

其余地址没有映射。CPU 访问未映射地址或发生数字总线错误时会故障，不把未知数据当作 0。各窗口内部仍按照所属芯片的寄存器权限拒绝保留地址。

IRQ0/1/2/3 分别接定时器、GPIO、UART、DMA。CPU16 使用四个程序向量；自定义 CPU /2 用可见的四路 16 位选择器把 IRQ 编号转换为程序入口。CPU /2 只有一层中断现场，处理程序不嵌套；这份 CPU16 程序也不在中断内部启用嵌套。中断确认并不替代清外设状态。

参考程序的四个入口是 `timer_isr`、`gpio_isr`、`uart_isr`、`dma_isr`，地址单位为指令编号。生成参考板时会从实际汇编标签计算入口。如果编辑程序增加或删除了入口之前的指令，要同步更新 CPU16 的 vector0–3 参数，或自定义版的 vector0–3 边界常量；导线上的数值不会自行跟随文本标签移动。只修改立即数或操作码且不改变指令数量时，入口位置保持。

## 公开 RAM 布局

观察面板从实际 RAM 读取，不维护另一个成功计数器。固定角色实例路径为 `cpu`、`ram`；封装后可以加前缀，例如 `left/ram`。删除、更名或换成不匹配的存储容量，面板会报告不兼容。

| 字地址 | 意义 |
| --- | --- |
| 0 | 会话标记 0x544D；启动先失效，初始化完成后再写入 |
| 1 | 已提交记录数，0–8 |
| 2 | 最新已提交采样字节 |
| 3 | 主程序记录的采样/存储/DMA/发送失败次数，16 位回绕 |
| 4 | 待采样标志，0/1；多次定时请求可合并 |
| 5 | 容量常量 8 |
| 6/7/8/9 | TIMER/UART/DMA/GPIO 中断处理次数，16 位回绕 |
| 10 | 最近一次成功 SPI 读回值 |
| 11 | 至少一条提交已完成的标志；新采样开始或清空时为 0 |
| 12 | 记录运行状态，0 暂停、1 允许采样 |
| 13 | GPIO 处理程序最近读取的按键字 |
| 16–23 | 8 个记录字，只有 `[16,16+count)` 已提交 |
| 64–71 | DMA 实际写入的记录副本 |
| 96/97/98 | 串口命令队列 head / tail / dropped |
| 128–135 | 8 槽命令字节队列；保留一个空槽，有效容量 7 |

中断只更新队列 head，主程序只更新 tail，满时丢弃新命令并增加 dropped。中断保存/返回恢复程序现场；中断处理程序要保留的结果通过上述 RAM 地址写出。主程序在读取并清除 due 的短区间关中断，防止同拍读改写丢失新请求。

未初始化、暖复位后程序尚未使旧标记失效、容量/计数/记录值不合法时，观察面板不会把旧条目展示成新会话。正在提交的新条目只在 count 发布后显示；SPI 的在途值不会直接进入面板。

## 输入与控制

- `sense` 是 8 位数字输入，允许 0–255。它是功能抽象的传感数值，不是模拟电压或真实温度测量电路。
- `button` 是 16 位数字输入，界面只驱动 bit0。按下产生变化 IRQ 并切换记录状态；松开产生变化 IRQ，但不切换。按钮没有模拟机械抖动。
- `reset` 为整板复位。顶层工程也可使用工作台暖复位。
- 串口接收 ASCII `P` 暂停、`R` 继续、`C` 清逻辑记录数。命令先经真实 1042 µs 串口接收，再进入 ISR 队列，最后由主程序消费；当前采样可能完成后才执行命令。未知字符被消费并忽略。
- `C` 清计数、最新值、读回和 ready 标志；保留运行/暂停状态、累计错误/IRQ、物理存储内容以及 GPIO 最近输出。恢复采样时会从记录地址 0 重新写存储器。它不是擦除非易失器件命令。
- 全局暂停冻结仿真时间、CPU 和外设；不同于 `P`，后者仍允许运行中断和接收命令。

## 错误和恢复

I²C、SPI 或 UART 事务线中途断开会使那次帧失败；立即重连也不会复活旧帧。传感器未知输入也明确失败。采样/读回失败不发布新的记录，下一次定时机会由同一程序重试。SPI 写后忙属于可恢复状态：读回仅对 DEVICE_BUSY 重试，最多 64 次；其他错误立即结束本次采样。重试耗尽计错。串口发送失败发生在记录提交之后，记录保留。

断开数字总线、未知复位或违反总线握手可能使 CPU/DMA 故障，这类错误需要修复接线并复位。程序不承诺从 CPU 已故障状态自动恢复。错误计数描述已由主程序处理的失败；芯片自己的错误寄存器和故障字段仍可独立观察。

暖复位取消在途事务和中断现场，程序重新清理元数据/命令队列。外部 RAM 的物理旧内容由芯片规则保留，但 count 归零后不是新会话的有效记录。非易失存储器保留已提交字节；冷启动/断电同样遵守其 `nonvolatile` 参数。要保存当前存储数据和在途事务，必须保存运行快照，仅保存工程设计不会携带本次运行内容。

## 模块接口

`TerminalV8` 是浏览器全局，也是 CommonJS 模块。加载顺序在 CircuitLab、ArchitectureV5、CustomCpuV8 之后。

- `await build('fixed'|'custom', {period:5000,sense:25,writeBusyUs:100})` 返回标准 `{project,view,sources,source,lesson:null}`。period 支持 1000–65535 µs；writeBusyUs 支持 0–20000 µs。
- `source(core, options)` 返回实际可编译汇编。工作区源码键分别为 `architecture:cpu` 和 `customarch2:cpu`；实例参数中的 source 是实际执行版本。
- `inspect(runtime, scope='')` 只读返回兼容/初始化状态、记录、DMA 副本、IRQ 次数、各真实外设状态、CPU、终端历史和显示数值。
- `setSense(runtime,value,input='sense')`、`setButton(runtime,0|1,input='button')`、`sendCommand(runtime,'P'|'R'|'C',terminal='terminal')` 只排真实输入/串口事件，不推进时间或写 RAM。封装后可传 boundaryMap 对应输入和实例终端路径。
- `ADDRESS`、`META`、`IDs`、`PORTS`、`SAMPLES` 提供固定合同及两个示例入口。

这是有界、确定性的教学系统。I²C/SPI 使用实际连线上的事务级帧，计入协议延时、设备忙和失败，但不生成物理 SCL/SDA/SCK 边沿，也不模拟电压、电流或电磁行为。
