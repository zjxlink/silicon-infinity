# 新手路线与系统应用 v0.4

新手路线帮助你真正接线、读信号、改程序。系统应用提供五套能运行、能修改的电路。这里的灯、时钟、温度与串口输出都来自数字仿真和程序执行，没有用动画代替电路结果。

## 从第一根线开始

点击顶部“入门引导”，选择一个主题。每一步会在画布标出对应端口；依次点击起点和终点即可接线。“定位端口”会找到目标，“提示”解释接法和原理。

接好后点击“检查这一步”。检查会复制当前候选设计，改变测试输入并运行，确认实际信号或程序结果。没有通过时，“下一步”不可用；失败项可定位到相关端口。通过后又改了设计，需要重新检查。检查不会改变当前工作台的虚拟时间、RAM 或排队输入。

要在画布亲眼观察结果，可点击“应用并单步”，再改变开关并推进一次。暂停时开关先排入输入队列，下一微秒才会改变实际信号。

八个主题共十二步，全部开放，无需购买或解锁元件：

| 主题 | 操作 | 实际通过条件 |
| --- | --- | --- |
| 第一根线 | 将开关接到灯 | 输入 0、1、0，输出分别为 0、1、0 |
| 两个条件（3 步） | 接 A、接 B、接结果 | 前两步检查信号到达对应引脚，最后检查与门全部四种输入 |
| 电路记住一位（3 步） | 接 D、接 EN/RESET、接 Q | 写入、保持、清零和再次写入均正确 |
| 从一位到一个字节 | 连接 8 位数据总线 | 写入 165、保持、清零、写入 255 与 0 |
| 用程序点灯 | 编辑和编译 Core8 程序 | 程序实际驱动 GPIO1，并经接线到达 LED |
| 真正的外设读写 | 接 SPI 协议线 | 成功事务真实写入并回读 90 |
| 让环境进入程序 | 接 I²C 温度传感器 | 25 ℃ 与 65 ℃ 均通过实际事务被 MCU 读到 |
| 改造自己的计算机 | 将 ROM 中 `ADDI 1` 改为 `ADDI 5` | 键盘 7、250、255 分别得到 12、255、4，RAM 同步保存 |

“上一步重做”和“重做本步”会载入该步的初始状态，并保留前面应完成的连接。“跳过，继续沙盒”关闭引导，保留正在编辑的电路。想回到开始教程前的作品，点“返回原作品”：原设计草稿、源码和运行快照会恢复，当前暂停。

通过记录保存在当前浏览器，与原十个实验、挑战进度分别计算。页面刷新后仍可查看已完成步骤。教程前现场的快捷返回限当前页面会话；需要长期保留，请使用“我的作品”或导出现场。存储不可用时会明确提示，不会假称已保存。共享房间内不能启动教程或恢复本地现场，请先退出房间。

## 五个系统应用

点击顶部“应用”，选择系统实例。电路已接好，初始暂停。操作台能推进虚拟时间、设定环境、发送字符、查看当前结果和验证目标。“其他应用”返回目录；关闭面板可以直接操作画布上的输入、连线与元件，再从顶部返回操作台。

应用验证使用独立副本，当前运行场景保持不变。接线和固件修改仍遵循“候选设计 → 编译 / 校验 → 应用并重新启动”。推进、传感器操作和串口输入不能绕过未应用的草稿；共享房间内也不能通过应用入口改变本地运行状态。

### 电子钟

点击“仿真 +1 秒”两次，观察时钟数字和 GPIO 秒数位。初次上电要先执行初始化，所以精确的第一秒更新比虚拟时间 1,000,000 μs 晚几十微秒。输入 `hold=1` 暂停计时，`hold=0` 恢复；这是时钟程序的暂停输入，仿真本身仍在运行。

定时器每 10,000 μs 触发中断，程序累计 100 次得到一秒，按 60 秒、60 分、24 小时回绕。RAM[0]、RAM[1]、RAM[2] 分别保存秒、分、时，GPIO1—6 显示秒的二进制位。可打开程序修改计数阈值，做一只快钟。这里显示虚拟时间，不是电脑系统时间。

### 温控器

将环境设为 35 ℃，推进 20 ms，风扇输出变为 1；改为 30 ℃ 时保持开启；改为 26 ℃ 后关闭。开始时的 25 ℃ 对应关闭。这个保持区间称为滞回，用于减少阈值附近的反复开关。

输入 `enable=0` 强制关闭风扇。温度从 I²C 地址 0x48 读取，RAM[0] 保存最近读数，RAM[1] 保存风扇状态。断开 I²C 线会产生真实失败事务，程序关闭风扇，并把 RAM[3] 置为 1。模型只演示数字控制，不模拟热传导、电机或电压。

### 数据采集器

将温度依次改为 21、67、42 ℃，每次推进 20 ms。数据会经过 I²C 读取、SPI 环形缓存写入和回读，再从 UART 送到终端。输入 `enable=0` 停止新增样本。

RAM[0] 为温度，RAM[1] 为 SPI 回读值，RAM[2] 为八位样本数（超过 255 回到 0），RAM[3] 为错误标记。SPI 外设有 16 个寄存器，程序写满后回到开头。串口发送原始温度字节，不一定是可打印字符；例如 67 对应字符 C。可在调试台查看真实 I²C / SPI 事务。

### 串口控制台

先推进 20 ms 完成初始化，再发送 `1?0x`，然后再推进 20 ms。终端应收到 `110!`：`1` 开灯，`?` 查询当前状态，`0` 关灯，其他字符返回 `!`。

发送和回复均经过实际 UART 队列与连接，每个字节单向需要 1042 μs。RAM[0] 保存最近命令，RAM[1] 为灯状态，RAM[2] 为命令数。一次最多发送 16 个 ASCII 字符。只断开返回线时，MCU 仍可能执行开灯，但终端收不到回复。

### 小型计算机

这套电路由 26 个可见模块连接，没有隐藏的 Core8 实例。键盘 `key` 是 8 位输入；输入数值加一后送到 `value`，并保存在 RAM[3]。推进 100 μs，可观察 PC、指令、累加器和输出。

点击“修改程序”打开实际 ROM 源码，将 `ADDI 1` 改为 `ADDI 5`，编译并应用后，7 会得到 12。八位结果回绕，所以 255+1 为 0。总线、ROM、RAM、寄存器和外设均可在画布观察；想弄清执行过程可改为逐拍运行并使用调试探针。

## 检查与边界

实现检查见 `tests/learning-v4.test.cjs`、`tests/applications-v4.test.cjs` 和 `tests/browser/learning-v4.cjs`。覆盖未完成题目失败、正确方案通过、断线负例、程序改变真实结果、温控故障关闭、秒进位到分钟、进度保存和运行现场不被验证修改。实际执行结果统一见版本验收记录；本文不把未执行的长期压力目标当成已完成测试。

五个应用是数字教学模型，不能替代真实电路设计、模拟电路、电气安全或传感器校准。应用的验证接口是公开输入、输出和约定的 RAM 位置，允许在保留这些接口的前提下改写程序。探针采样或断点可能使“推进一段时间”提前停止，界面会显示实际推进量，数据始终对应真实运行时刻。
