# 首版玩法与引导设计

版本：0.1.0；日期：2026-10-10；状态：首版实施设计。本文以已交付的00—03规格为基线，不表示关卡、模板或仿真已经通过验收。

## 1 首版体验目标

玩家能把一个想法变成会工作的数字电路，解释它为什么工作，保存并改造自己的成果。游戏的主要回报是可观察的功能与可复用作品；首版不设置购买元件、制造资金、等待研究或消耗生命等限制。

默认打开完整的智能灯控制板，处于暂停状态，提示“点运行，让程序开始工作”。零基础玩家可以选择“从第一根线开始”，熟悉电路的玩家直接编辑示例或新建工程。十个引导实验均可直接进入，不因未完成前课隐藏已提供的元件。

首版完成定义：玩家可连接并验证逻辑电路、封装纯数字芯片、保存本地工程，运行及修改Core8智能灯程序，并在界面中定位错误。这里的“完成”不是实现SPI、PWM或现实芯片制造。

## 2 核心创造循环

1. **选一个功能。** 查看一句话目标及输入/输出示例，如“任一门打开时报警”。
2. **连接或修改。** 从空白、半成品或完整模板出发；元件说明先解释用途，再展示端口。
3. **运行并观察。** 输入、导线、输出和程序状态来自同一个仿真；选中一条线可以查看0、1、X或Z及其原因。
4. **验证目标。** 在独立仿真副本上执行公开输入向量，逐项展示期望与实际结果，不破坏当前运行位置。
5. **保存与再用。** 纯数字设计可封装为本地芯片；含MCU、固件、供电源和协议连接的应用板保存为完整工程，再复制改造。

界面必须始终区分“正在运行的版本”和“尚未应用的修改”。新连线、删除元件或修改固件形成候选；点击“应用并重新启动”才生效。运行中的断线开关仅改变既有导线enabled，不伪装成拓扑编辑。

## 3 首发内容目录

### 元件

| 分组 | 实际可用内容 | 面向玩家的说明 |
|---|---|---|
| 输入与观察 | 顶层digital输入、输出及按钮/LED视图 | 输入提供数值；LED只观察，不能自己决定亮灭 |
| 基础逻辑 | std.not/and/or/xor/nand/nor/xnor，均/1 | 不同规则的开关，每个引脚是一位 |
| 选择 | std.mux/1 | 由一个选择输入决定让哪路通过 |
| 记忆 | std.dff/1 | 在共同的下一时刻记下数据，可以暂停写入或清零 |
| 供电 | std.vcc/1、std.gnd/1与布尔供电域 | Core8两根供电线都须连接正确；不计算电压电流 |
| 可编程芯片 | core8/1 | 教学Core8 / 功能级：修改程序，查看寄存器、RAM和外设状态 |
| 通信观察 | io.terminal/1 | 查看实际收到的字节，并通过明确的发送队列输入字节 |

不得把旧试验中的ADD8、SRAM、GPU、ROM4、独立计数器等未注册模型加入首发列表。多位数据能力沿用1—32位接口合同；首版逻辑门仍是一位。多位逻辑可用多个一位端口组合，不能暗中加入未定义的总线拆分器。

### 模板

首发模板为初次接线、OR报警器、半加器、全加器、DFF记忆、两份独立记忆、半加器封装练习、智能灯、智能灯改速、UART自回环。逻辑模板都有真实结构，可复制修改；Core8只开放已定义的程序与可观察状态，不能假装拥有可打开的门级CPU图。

智能灯使用已交付的96字节参考固件和对应源码，GPIO0接按钮、GPIO1接LED、双向UART接终端。教学文本不得用另一个简化程序冒充同一参考镜像。

## 4 十个引导实验

所有关卡都有公开的端口接口；显示名称可修改，接口ID和位宽构成目标合同。验证检查接口行为，允许不同门组合、位置、内部实例名和等价结构。模板是起点而不是唯一解。

| 顺序 / ID | 玩家目标与操作 | 验证方式 | 初始模板 |
|---|---|---|---|
| 1 first-wire | 补上一根线，让两个开关共同点亮灯；运行后尝试四种输入 | A/B的00、01、10、11对应Y的0、0、0、1 | AND板，输出线缺失，供电已配置 |
| 2 or-alarm | 改成“任一门开就报警”，理解规则来自电路 | 四组输入对应0、1、1、1 | 完整OR结构，允许重搭 |
| 3 half-adder | 两个一位数相加，同时观察“和”和“进位” | 四组输入下sum=A异或B、carry=A与B | XOR与AND组成的半加器 |
| 4 full-adder | 让上一级进位也参与计算 | A/B/Cin八组输入全部验证；sum与carry重组后等于三输入之和 | 完整五门全加器 |
| 5 memory | 让输出记住上一个值，而不是一直跟随输入 | 写入1、禁止写入保持1、复位清零、再写入0；每一步共同推进1微秒 | DFF及data/en/reset三个明确输入 |
| 6 dual-memory | 两枚相同芯片各记各的 | 共同时钟，A允许写、B禁止写；交换使能后再次检查，禁止共享状态 | 两枚DFF，共享data但各自en |
| 7 chip-package | 将半加器保存为自己的芯片，再放入画布验证 | 与第3关相同四组行为；工程中实际使用一个composite实例 | 可直接封装的半加器；未封装时行为可通过但复用步骤未完成 |
| 8 smart-lamp | 上电运行程序，让板子发送B并自动闪灯 | 外部LED与实际终端接收验证参考行为；不从元件位置或名字判定 | 完整智能灯，默认暂停，源码可读 |
| 9 faster-lamp | 把WAIT 60000改为30000，比较修改前后 | 初始亮灯不变；第二次输出变化提前30000微秒；候选固件必须真正应用 | 同一参考板，保留原60000等待作为待修改起点 |
| 10 uart-loopback | 发送一个字节，再从自己接收回来的数据判断灯是否亮 | 发送0x42，经1042微秒实际回环后读取并点亮灯；断开现有回环线再测不得假成功 | Core8 TX接自身RX，检查接收结果的短程序；不违反TX单接收端规则 |

第8—10关默认使用微秒级可观察检查，不要求玩家知道所有汇编指令。指令逐行附简短释义，“跳到源码”只是定位，不能替代真实执行。第9关只改一个常量即可完成，不引入超过65535的WAIT值。第10关需要CPU按实际接收结果决定输出，不能发送后无条件点灯。

每关“验证”给出具体通过项数量，失败显示第一个反例并允许查看全部结果。已满足的模板可以直接验证成功，这意味着“此设计符合目标”，不把使用模板说成玩家独立发明。

## 5 首个30分钟

这是建议引导节奏，不是限时任务，也不要求30分钟完成十关。

| 时间 | 玩家应完成的动作 | 体验检查 |
|---|---|---|
| 0—2分钟 | 从第一根线或完整智能灯二选一；找到运行、暂停和输入 | 不读长教程也能看到一次真实输出变化 |
| 2—7分钟 | 补线并验证AND；对照OR看两种规则 | 能用一句话说清两者什么时候亮 |
| 7—13分钟 | 打开半加器，观察和/进位，试四组输入 | 不要求先掌握二进制大数运算 |
| 13—20分钟 | 将半加器封装、命名、放回画布；打开内部核对 | 得到第一件可再次使用的作品 |
| 20—25分钟 | 跳转完整智能灯，运行并看到B和LED；暂停看源码 | 明白程序→GPIO/UART→连接→输出的链路 |
| 25—30分钟 | 修改WAIT并应用；保存工程 | 看见自己的修改确实改变仿真结果，知道下次如何继续 |

记忆、全加器和回环关卡可以随后深入。首次进入DFF实验时默认暂停，明示“输入已排队，点推进1微秒后生效”；不得在暂停时偷偷改动运行状态来制造即时反馈。

## 6 自由模式与复用

自由模式有空白数字芯片、完整智能灯两个起点，也可载入自己的工程；不需要通关、货币或购买。推荐区只影响显示顺序，所有首发元件均可查找。资源上限沿用1000实例、4000线、128定义、16层等基线，不以“无限”暗示无限计算资源。

首版封装范围限定为纯数字端口、逻辑门与DFF组合。使用“保存为芯片”前显示输入/输出引脚与位宽，检查结构和已连接输入；保存不可变新版本。添加第二实例时只有定义共享，运行状态独立。打开内部结构是查看；点击“复制并修改”建立新版本候选，不改写预设或现有已锁实例。升级已放置实例需要显式操作并重新验证。

含MCU、固件或协议端口的板使用“保存工程”和“另存为实验”，首版不承诺将整块板变成任意工程里可直接插入的芯片。跨工程复用纯数字定义时必须携带全部锁定定义；供电域绑定冲突要明确解决，不能偷偷改变定义内容和哈希。这个交互边界由统一编辑器合同落实。

“保存设计”用于再次冷启动；“保存运行快照”用于保留当前时间、记忆与在途消息。两项必须有不同标签与解释，不用一个含糊的保存按钮混在一起。

## 7 错误与提示

错误提示由真正的诊断生成，先给可以采取的动作，再给规则与技术细节。红色只用于阻止应用或使结果无效的问题；X/Z使用文字与图标，不单靠颜色。

| 层级 | 默认显示 | 示例 |
|---|---|---|
| 观察提示 | 当前发生了什么 | “这根线没有人在驱动：Z。接收器因此不知道是0还是1。” |
| 第一级提示 | 高亮相关位置，不给完整解 | “检查指示灯的输入端有没有接到输出。” |
| 第二级提示 | 解释相关规则 | “两路同时驱动同一引脚会冲突，即使都输出1。” |
| 第三级提示 | 给出一个可操作例子 | “将GPIO0设为输入，让按钮负责驱动它；再重新运行。” |
| 查看一个解法 | 玩家主动打开模板副本 | 保留当前作品，不覆盖；说明只是可行解之一 |

结构错误不激活候选：位宽不匹配、输出冲突、缺失定义、组合循环、非法固件等保留旧运行态。运行错误显示实例和端口/指令：GPIO未知、串口空读、非法地址等不标成整个应用崩溃。CPU HALT/FAULT与全局暂停分开；CPU停止后，允许推进仿真观察已排队UART。

目标不满足不是报错。例如OR接成AND时，验证器显示“输入01，期望1，实际0”；不虚构电气故障。可跳过引导或查看解法，不扣分、不删除作品。

## 8 成就与验证证据

首版使用“已验证”与作品记录，不设置唯一电路答案或按耗时排名。可用里程碑为：第一根正确连线、第一份完整真值表、第一枚个人芯片、两份独立记忆、第一次程序改造、第一次真实回环。成就依据实际验证结果与必要的封装动作，不因点击按钮数量自动授予。

验证器对工程的独立副本运行：记录关卡版本、引擎版本、设计哈希、输入事件及检查结果。组合关卡穷举小输入空间；时序关卡使用公开事件脚本。观察输出与期望对比，不调用“正确答案”接口替玩家运行。内部布局、元件名及坐标不参与功能评分；封装关的composite要求属于明确的复用任务。

本地学习进度、提示使用与验证报告属于游戏内容侧数据，不添加到严格工程schema中。玩家修改已通过的作品后显示“上次通过的是旧版本”，而不是沿用新版本的通过标记。

## 9 需要统一落实的交互合同

以下都是实现依赖，不是已经增加到仿真白名单的新模型。

| 项目 | 首版处理建议 | 所需协调 |
|---|---|---|
| 模板/关卡包 | 独立manifest引用canonical工程、源码、视图位置及测试定义；不污染工程schema | LabLessons.build与verify统一API |
| 公开验证接口 | 每关声明固定顶层端口ID及位宽；允许修改显示名和所有内部结构 | 编辑器不得把改名误当更换端口ID |
| 验证沙箱 | 新建独立Runtime，执行已声明输入和推进，不改变玩家Runtime | 超时/资源错误显示未完成，不能当作通过 |
| 纯数字封装 | 边界由现有顶层端口生成，锁定依赖；状态按路径隔离 | 电源域绑定在跨工程导入时显式匹配；冲突拒绝，不自动重写 |
| 候选与运行态 | 修改区明确标“尚未应用”，统一应用并冷启动 | 固件sourceMap和实际镜像必须一致 |
| 控件语义 | 运行/暂停、推进1微秒、CPU指令单步分别显示；断线是enabled开关 | 不因渲染动画改变虚拟时间 |
| 本地内容库 | 保存结构定义、锁、说明及验证版本；新建/复制/升级可追溯 | V1不依赖账号或网络分享服务 |

这一版不需要新增SPI、I²C、PWM、定时器、计数器黑盒、随机制造结果或经营经济模型。后续若要加入宽位运算器、总线拆分器或可编辑CPU结构，必须另行定义模型和验收；不能把旧草稿中的同名功能当作已获批准。

## 10 非目标与发布检查

首版不承诺真实电气仿真、商业MCU兼容、RV32I运行、C编译器、硬件中断、联机共同编辑、在线商店、公开上传或无限算力。允许自由设计的含义是组合与程序空间开放，仍遵守明确的模型和资源限制。

可玩首版必须具备：上述模板可载入；首次缺线能修复；组合/时序验证能接受不同合法实现；个人芯片可再次实例化；智能灯从真实固件产生结果；程序修改可应用；回环通过实际连接完成；错误不损坏旧工程；本地导出可重开。Phase0/Phase1的完整发布证据仍以03的Blocker验收为准，本文件的十关不能替代全部引擎测试。
