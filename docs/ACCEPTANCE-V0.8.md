# v0.8 验收记录

> 历史版本记录：本文对应原游戏及原托管环境，不是本自托管候选版的 Docker、账号系统或 fnOS 验收。文中的旧 QA 路径、托管发布回执和访问范围仅适用于当时的版本；当前部署与维护请看 [运维说明](OPERATIONS.md)。

本版落实“设计自己的 MCU”阶段。注册模型由 64 增至 73，芯片手册由 84 增至 93 篇；新增图形 ISA/状态机/寄存器设计器、单层中断自定义 CPU、异步协议与系统外设、固定和自定义两种完整 MCU 终端，以及 `/2` 源码调试。

## 可重复的证据

- 完整核心测试：44 套通过，626 项 Node 测试加 129 项原有引擎检查，共 755 项；原始日志 `qa/v0.8/core-tests.log`。
- 芯片设计器：18 项浏览器场景；真实编辑指令与微操作后改变运行结果，非法定义不覆盖草稿和运行状态。
- 完整终端界面：12 项场景；两种核心、数据链、串口控制、GPIO 按钮、协议断线恢复、候选隔离和 390px 布局。
- 新核心调试：8 项；源码断点、逐拍/逐条、中断现场与返回、重复中断、模块内部路径。原有自定义架构另回归 13 项。
- 迟到恢复保护：3 项；旧异步操作不能覆盖新作品的运行现场、未应用设计和源码。
- 离线：从完整解压包以 `file://` 打开并禁用网络执行 16 项，包含两种完整 MCU 终端；零页面错误、零网络请求。最终证据 `qa/v0.8/offline-package/results.json`。
- 实际生产 Worker 构建与本地持久化 D1：14 个流程，269 次 API 请求、132 次完整快照一致比较、114 次重复操作验证。完整终端在固定与自定义核心上都得到 `[25,25,65]`，DMA 副本一致、CPU 无故障；见 `qa/v0.8/worker-d1.json`。
- 旧记录器 40 项（Chrome 主流程 22 项与三浏览器兼容 18 项）、时间线 12 项、里程碑 20 项和现场恢复 2 项继续回归。记录器汇总见 `qa/v0.8/regression/recorder-workflows.json`，其他逐项报告保存在该目录的相应子目录。首次计数差异及修复前的失败记录保留供追溯，最终通过状态以 `final-verification.json` 为准。

最终校验脚本 `scripts/release-check-v8.cjs` 要求上述结果全部通过，并逐文件核对游戏源码、生产构建和解压后的离线游戏内容一致；结果写入 `qa/v0.8/final-verification.json`。交付包还包括每个文件的大小、SHA-256 清单，并检查 ZIP CRC 与实际解压内容。

## 已修复的关键问题

总线应答当拍地址断开时，CPU 现在接收到错误而不是旧成功数据。设备在协议完成当拍复位或断线时，不提交过期事务。新的 CPU 源码键在服务器端绑定实际核心与层级路径，错误目标和恶意路径整份拒绝。异步载入、返回旧作品在提交前再次检查代次，保证用户的新选择优先。

旧库迁入期间的自动备份现在在提交前检查读保护与代次；相同内容的备份不会仅为更新当前作品标记而重写旧库。原里程碑 20 项、新增迁入竞态 4 项、旧作品界面 18 项及相关核心 39 项全部通过，退出迁入后自动备份继续工作。

## 验收边界

线上网站保持原有仅所有者访问范围。按用户决定，第二个真实生产账号的跨账号登录验收延后；本地隔离身份、权限拒绝和撤销测试不能替代它。

本版是数字功能级仿真。新 SPI/I²C 设备为有真实传输时长的寄存器事务模型，不模拟全部物理总线边沿、电压或器件制造；新自定义 CPU 是单层中断。完整终端为八条记录的可修改参考系统，满缓冲、设备忙、断线、复位、独立封装都按其公开合同处理。后续路线的规模、性能及生态阶段仍未声明完成。

发布成功后，交付包 `qa/v0.8/deployment.json` 提供精确源码提交、版本和部署结果。生产 URL 以该记录为准。
